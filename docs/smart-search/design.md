# Smart Search: Design

## Overview
Команда `/smart-search` реализует чтение‑поиск‑подтверждение с минимальным набором инструментов: glob → grep → read → ранжирование → форматированный вывод. Все операции — read‑only.
## Workflow
1. Normalize query:
   - Строка запроса `Q`.
   - Если `Q` относится к синонимам, расширить регулярное выражение: `(Q|unsubscribe|remove|cancel|optout|delete|detach)`.
2. Glob candidates:
   - Базовые маски: `**/*.py`, `**/*.md`, `**/Makefile`, `**/*.json`.
   - Исключения: `**/node_modules/**`, `**/.venv/**`, `**/__pycache__/**`, `practices/practice_03/lab/results/*.jsonl`.
3. Grep matches:
   - Применить regex по включённым файлам, собрать `{path, line, text}`.
4. Read context:
   - Для каждого совпадения прочитать 2–3 строки вокруг совпадения (слева/справа) — подтверждение и объяснение.
5. Rank results:
   - Приоритет форматов: `.py > .md > Makefile > .json`.
   - Стабильная сортировка: по формату, затем по пути и строке.
6. Limit:
   - Оставить топ‑10.
7. Format:
   - `file:line` + фрагмент (2–3 строки) + краткое объяснение.
8. Negative:
   - Если совпадений нет — «В предоставленных материалах нет ответа» + перечисление проверённых масок и исключений.

## Edge Cases
- Большие файлы: ограничиваем чтение контекста до нужных строк.
- Дубликаты совпадений: дедупликация по `path:line:text`.
- Бинарные файлы: не включаются масками.

## Implementation Notes
- Не использовать bash; только встроенные инструменты `glob`, `grep`, `read`.
- В случае ошибки чтения файла — пропустить и пометить в объяснении, не прерывая выполнение.
- Ответ должен оставаться кратким и подтверждённым.
