# Рефлексия по Практике 4

## Что помогло

**AGENTS.md.** Как только я прописал в нём маршрут чтения и границы, агент перестал 
лезть в лишние файлы. Он сразу читал нужное и ссылался на источники.

**Pre-commit hook.** Он реально работает — когда ruff нашёл 6 ошибок в check_pptx.py, 
коммит заблокировался. Я поправил, коммит прошёл. Без hook'а я бы это заметил позже.

**Subagent tester.** Он нашёл проблему, которую я сам не видел: check_pptx.py не вызывал 
MCP context7 в runtime. Я думал, что достаточно того, что MCP подключён, но tester 
показал разницу. После этого я сделал реальный вызов context7 через агента и закрыл замечание.

**MCP context7.** Помог найти документацию python-pptx по shape.text и проверить, что 
check_pptx.py использует API правильно.

## Что мешало

**Worktree.** Я не сразу понял, зачем нужен отдельный каталог ITMOv2-b. Пришлось 
разбираться, что .opencode/ не переносится автоматически — tester.md надо было копировать руками.

**Shadowing pptx.** Папка skills/pptx/ «затеняла» библиотеку python-pptx при импорте. 
Пришлось добавлять костыль с очисткой sys.path. Это было неочевидно.

**Ошибка gpt-5 через VseLLM.** Иногда запросы падали с "Request failed" без объяснений. 
Приходилось перезапускать.

## Где пришлось вмешаться

- Когда агент в first-shot вернул AS IS вместо TO BE в Практике 3 — пришлось явно указать 
  разницу.
- Когда pre-commit заблокировал коммит — сам разбирался с ошибками ruff.
- Когда tester нашёл проблему с MCP — сам решил, что делать: добавить runtime-вызов или 
  признать, что MCP использовался при разработке.
- Отклонил предложение агента использовать framework ради мелкой правки.

## Итог

Практика 4 дала понимание, как строить **среду для агента**, а не просто давать ему задачи. 
AGENTS.md, skill, MCP, hook — это не украшения, а реальные механизмы, которые влияют на 
качество работы агента. Больше всего помог pre-commit hook и subagent review — они ловят 
то, что сам пропускаешь.
