# Рефлексия ДЗ 5: Две команды — одна фича

## Сравнение фреймворков
- **Spec Kit (UI):** Отлично подходит для продуктовых требований (User Stories, Acceptance Criteria). Быстро генерирует спеку через `/speckit.specify`. Минус — сильно фокусируется на том, *что* видит пользователь, упуская технические детали.
- **Kiro (Logic):** Идеален для инженерных спек. EARS-нотация (WHEN... THE SYSTEM SHALL...) заставляет думать о граничных случаях (что если JSON битый?). Mermaid-диаграммы отлично визуализируют поток данных.

## Что согласовывали
- Kiro настаивал на строгом парсинге только `*.json` (игнорируя `.jsonl`). UI-спека об этом не думала. Договорились использовать `*.json`.
- Spec Kit хотел показывать путь к файлу, а Kiro — просто сохранять. Договорились, что Kiro возвращает путь, а UI его выводит.
- Конфликт: Kiro добавил строку со средними значениями в таблицу (FR-L13). UI об этом не просил, но мы решили оставить — это полезно для аналитики.

## Чему научился
- Разные инструменты заточены под разные аспекты: Spec Kit — под продукт, Kiro — под инженерию.
- Главное в ДЗ — не просто сгенерировать два документа, а найти между ними мосты (контракт).
