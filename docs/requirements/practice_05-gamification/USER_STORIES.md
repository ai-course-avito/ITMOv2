# User Stories

**Feature**: Игрификация задач: колесо фортуны и эмодзи
**Created**: 2026-10-27

## Story Format

As a [role], I want [capability] so that [benefit].

## Stories (prioritized)

### US1 - Разблокировка эмодзи через колесо (Priority: P1)

- **Story**: Как пользователь, я хочу крутить колесо фортуны и разблокировать эмодзи, чтобы использовать их для наглядной классификации моих задач.
- **Почему приоритет**: Это основной игровой цикл и ключ к появлению ценности от эмодзи.
- **Независимая проверка**: Пользователь с нулевым набором эмодзи может крутить колесо до 5 раз, получить хотя бы одно эмодзи и увидеть его в доступных для выбора при пометке задач.

**Acceptance scenarios**:

1. Given пользователь без эмодзи, when он крутит колесо и выпадает эмодзи, then эмодзи добавляется в его список доступных и становится видно при выборе меток.
2. Given пользователь уже имеет выпавшее ранее эмодзи, when это же эмодзи выпадает снова, then система сообщает о дублете и не увеличивает список (правило «игнор + сообщение»).

---

### US2 - Ежедневный лимит круток (Priority: P1)

- **Story**: Как пользователь, я хочу иметь ограничение на число круток в день, чтобы игровая механика оставалась контролируемой и стимулировала возвращение.
- **Почему приоритет**: Ограничение — часть запланированного опыта и экономии наград.
- **Независимая проверка**: После 5 круток в течение суток система блокирует кнопку «ИГРАТЬ» и показывает баннер о лимитах.

**Acceptance scenarios**:

1. Given у пользователя осталось 0 круток на сегодня, when он нажимает «ИГРАТЬ», then отображается полноэкранный баннер о необходимости продления лимитов (шутливый текст про b2c стартап), вращение не начинается.
2. Given наступила полночь по локальному времени пользователя, when пользователь возвращается, then лимит круток автоматически обновляется до 5.

---

### US3 - Использование эмодзи в задачах (Priority: P2)

- **Story**: Как пользователь, я хочу выбирать из доступных мне эмодзи при создании/редактировании задач и видеть их перед задачами, чтобы быстро ориентироваться в списке.
- **Почему приоритет**: Завершает ценность — визуальные метки в интерфейсе задач.
- **Независимая проверка**: После разблокировки эмодзи пользователь может назначить его задаче, и оно отображается перед названием задачи.

**Acceptance scenarios**:

1. Given задача без метки, when пользователь выбирает одно из доступных эмодзи, then эмодзи отображается перед задачей.
2. Given задача с эмодзи, when пользователь снимает метку, then у задачи не отображается эмодзи.
3. Given очень редкий приз «мульти-эмодзи» активирован для пользователя, when он назначает вторую/третью эмодзи на задачу, then задача отображает несколько эмодзи (до 3, при активном перке).
4. Given у пользователя нет доступных эмодзи, when он открывает выбор эмодзи при создании задачи, then кнопка добавления эмодзи отображается в неактивном состоянии, а список показывает недоступные эмодзи серым (если возможно) или скрывает их.
5. Given мульти-эмодзи не открыт, when пользователь пытается добавить ещё одну эмодзи к задаче, then кнопка «добавить ещё» отображается неактивной (с соответствующим названием/иконкой — уточнить на дизайне).

---

### US4 - Кнопка «ИГРАТЬ» в интерфейсе (Priority: P2)

- **Story**: Как пользователь, я хочу видеть яркую кнопку «ИГРАТЬ» в правом верхнем углу главного экрана, чтобы быстро начать вращение.
- **Почему приоритет**: Быстрый доступ, соответствующий тематике «казино».
- **Независимая проверка**: Кнопка присутствует, визуально выделена, доступна до исчерпания лимита.

**Acceptance scenarios**:

1. Given главный экран, when пользователь открывает приложение, then в правом верхнем углу видна заметная кнопка «ИГРАТЬ».
2. Given лимит исчерпан, when пользователь возвращается на главный экран, then кнопка «ИГРАТЬ» недоступна или ведет к баннеру о лимитах.

---

### US5 - Аккаунты и вход по имени (Priority: P2)

- **Story**: Как пользователь, я хочу входить по имени и иметь сохранение моих круток и набора эмодзи, чтобы продолжать прогресс между сессиями.
- **Почему приоритет**: Необходимая база для персонализации и хранения прогресса.
- **Независимая проверка**: Повторный вход по имени восстанавливает те же эмодзи и счетчик круток на текущие сутки.

**Acceptance scenarios**:

1. Given новый пользователь, when он вводит имя впервые, then создается профиль с лимитом 5 круток и пустым набором эмодзи.
2. Given существующий пользователь, when он входит по имени, then подтягиваются его эмодзи и текущий остаток круток на сегодня.

---

### US6 - Редкость ценных призов (Priority: P3)

- **Story**: Как владелец продукта, я хочу, чтобы редкие призы выпадали реже, но вращение выглядело честным и увлекательным, чтобы поддерживать интерес без ощущения манипуляции.
- **Почему приоритет**: Баланс удержания и восприятия fairness.
- **Независимая проверка**: На длительном периоде редкие призы статистически выпадают существенно реже, при этом пользователи не получают явных сигналов о «подкрутке».

**Acceptance scenarios**:

1. Given длинная серия круток, when анализировать результаты, then доля редких и очень редких призов существенно ниже доли обычных (целевые пороги 85/10/5).
2. Given интерфейс колеса, when пользователь крутит, then анимация и подбор сегментов не выдают явно предопределенный результат.

---

### US7 - Пулл «странных» призов на каждый раунд (Priority: P3)

- **Story**: Как пользователь, я хочу видеть на колесе набор неожиданных призов, который меняется от раунда к раунду, чтобы опыт оставался свежим и веселым.
- **Почему приоритет**: Поддержка новизны, юмора и лидерской задумки.
- **Независимая проверка**: Перед каждым запуском колеса формируется пулл призов из заранее заданного набора, часть из которых — эмодзи.

**Acceptance scenarios**:

1. Given новый запуск колеса, when оно отображается, then состав призов отличается от предыдущего раунда в статистически ожидаемой степени (не всегда, но периодически), при этом на колесе гарантированно ≥1 эмодзи.
2. Given призы включают эмодзи и «странные» бонусы, when пользователь видит колесо, then названия/иконки соответствуют задумке.
