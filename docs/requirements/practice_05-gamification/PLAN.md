# Implementation Plan

**Feature**: Игрификация задач: колесо фортуны и эмодзи
**Created**: 2026-10-28
**Inputs**: docs/requirements/practice_05-gamification/

## Summary

План реализует механику «колеса фортуны» для разблокировки ограниченного набора эмодзи, отображение эмодзи перед задачами и ежедневный лимит на крутки. Включены миграция пользовательских данных из JSON в централизованное хранилище, вход по уникальному имени, управление редкостью наград (85/10/5), а также UI-состояния для добавления эмодзи при создании/редактировании задач.

## Technical Context

- Project type: web
- Target platform: веб-интерфейс задач
- Constraints: ограничение 5 круток в сутки (сброс по полуночи локального времени: UTC + смещение); редкость призов незаметна для пользователя; отсутствие реальных финансовых операций
- Dependencies: существующий список задач и UI основного экрана; существующие данные пользователей в JSON (для миграции)

## Architecture Overview

- Пользовательский профиль: вход по уникальному имени, хранение лимита круток и набора эмодзи.
- Колесо фортуны: формирование пула призов на раунд (мин. 8 сегментов, гарантированно ≥1 эмодзи), анимация вращения, применение результата.
- Управление редкостью: целевые вероятности классов (обычные/редкие/очень редкие = 85/10/5) с нейтральной подачей в UI.
- Эмодзи-каталог: закрытый справочник с кодом и версией; отображение в UI; недоступные — серым (если возможно) или скрыты.
- Задачи и эмодзи: выбор/назначение эмодзи при создании/редактировании; «мульти-эмодзи» как очень редкий приз (до 3 эмодзи на задачу).
- Ежедневные лимиты: 5 круток/сутки, сброс по полуночи локального времени (UTC + смещение), баннер при исчерпании.
- Миграция: перенос из JSON в БД, политика «пропуск + отчёт» для проблемных записей, дубликаты имён отклоняются; вход по имени идемпотентен (создать-или-вернуть), ошибка invalid_name.

## Data Model (if applicable)

- Пользователь (User): имя (уникально), оставшиеся крутки на сегодня, отметка времени/правило последнего сброса (UTC+смещение), набор доступных эмодзи (ссылка на справочник), флаг перка «мульти-эмодзи».
- Эмодзи (EmojiCatalog): код, версия набора, метаданные отображения (иконка/название), класс редкости.
- Эмодзи пользователя (UserEmoji): связь пользователя с доступными эмодзи (код+версия).
- Задача (Task): поля задачи; связи с эмодзи задач (TaskEmoji) для 1..N в зависимости от перка.
- История спинов (SpinHistory) при необходимости аудита/аналитики (опционально).

## Contracts (if applicable)

- Нет внешних интеграций; внутренние события/действия фиксируются в приложении.

## Testing Strategy

- Contract tests: инварианты лимитов круток, редкости и состава пула; гарантия ≥1 эмодзи на колесе.
- Integration tests: поток «вход по имени → крутка → разблокировка эмодзи → назначение эмодзи задаче»; обработка дублей (игнор + сообщение); сброс лимита по полуночи (UTC+смещение).
- E2E tests: UX сценарии кнопки «ИГРАТЬ», баннер при 0 круток, добавление эмодзи при создании/редактировании задач; перк «мульти-эмодзи» (до 3 эмодзи на задачу).

## Risks and Mitigations

- Восприятие «подкрутки»: баланс вероятностей, нейтральные визуальные эффекты, UX-тесты.
- Дубли эмодзи: «игнор + сообщение», разнообразие пула.
- Миграция данных: бэкап, «пропуск + отчёт», проверка согласованности.
- Сброс лимитов: тесты на границы дат, явная политика UTC+смещение.
- Юридические риски: явные тексты об отсутствии реальных выигрышей.
