# Problem Statement

**Feature**: Игрификация задач: колесо фортуны и эмодзи
**Created**: 2026-10-27
**Owner**: Команда продукта

## Summary

В текущем опыте работы с задачами не хватает вовлеченности и наглядной классификации. Предлагается добавить элемент игры: пользователи смогут разблокировать ограниченный набор эмодзи через «колесо фортуны» и затем использовать эти эмодзи для пометки задач (эмодзи отображаются перед названием задачи). Ежедневный лимит на крутки создает дефицит и удерживает интерес. Также предполагается отказ от файлового хранения и перенос пользовательских данных в централизованное хранилище, а вход — по имени.

## Goals

- Визуальная классификация задач через разблокируемые эмодзи.
- Повышение вовлеченности и возвратов с помощью механики «колеса фортуны».
- Управляемая редкость «ценных» призов при сохранении ощущения честности и «живости» колеса.
- Прозрачное ограничение: до 5 круток в день с заметной обратной связью при исчерпании лимита.
- Единое централизованное хранение пользовательских данных вместо файлов.
- Интеграция выбора/добавления эмодзи непосредственно при создании/редактировании задач с понятными состояниями доступности.

## Non-Goals

- Внедрение реальных платежей и биллинга (баннер о переводе денег — шутливый/баннерный текст без платежной логики).
- Сложная регистрация/аутентификация (только вход по имени).
- Изменение базовой модели/логики задач, кроме добавления визуальных меток-эмодзи.
- Публичное раскрытие вероятностей выпадения призов.
- Отображение истории спинов/выпадений в пользовательском интерфейсе.

## Assumptions

- Вход осуществляется по имени; при первом входе данные пользователя создаются автоматически.
- Лимит круток — 5 в сутки на пользователя; сброс лимита — в полночь по локальному времени пользователя, определяемому как UTC + текущее смещение.
- «Ценные» призы (например, редкие эмодзи) должны выпадать реже «рядовых», при этом интерфейс не должен вызывать ощущение нечестности; используется 3 класса редкости (обычные, редкие, очень редкие).
- Данные пользователей и их разблокированные эмодзи хранятся в централизованной БД; файловое хранилище (JSON) не используется.
- В БД эмодзи не хранятся как Unicode-символы, а как код-идентификаторы с версией набора (код + версия) из закрытого каталога.
- Имена пользователей уникальны.
- Ограниченный набор эмодзи среднего размера (примерно 16–24 позиций).
- На каждом раунде колеса гарантированно присутствует как минимум одно эмодзи.
- «Странные» призы шутливого характера, без реального функционального эффекта.
