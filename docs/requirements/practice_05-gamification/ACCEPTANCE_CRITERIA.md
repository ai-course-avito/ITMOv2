# Acceptance Criteria

**Feature**: Игрификация задач: колесо фортуны и эмодзи
**Created**: 2026-10-27

## Functional Requirements

- FR-001: Пользователь может войти по имени; при первом входе создается профиль с лимитом 5 круток на текущие сутки и пустым списком доступных эмодзи.
- FR-002: На главном экране в правом верхнем углу отображается заметная кнопка «ИГРАТЬ», активная при наличии круток.
- FR-003: При нажатии «ИГРАТЬ» отображается колесо фортуны с пуллом призов, включающим часть эмодзи и «странные» бонусы (например, «скидка на задачи», «участие в розыгрыше»).
- FR-004: За одну сессию вращения пользователь получает один результат; результат добавляется в историю, а лимит круток уменьшается на 1.
- FR-005: Эмодзи становятся доступными к использованию только после их выпадения пользователю.
- FR-006: Пользователь может назначать доступные эмодзи задачам; эмодзи отображается перед задачей и может быть снято.
- FR-006a: При создании/редактировании задачи доступен элемент управления добавлением эмодзи; если у пользователя нет разблокированных эмодзи, элемент отображается в неактивном состоянии.
- FR-006b: В списке выбора эмодзи отображаются все эмодзи из набора; недоступные выделены серым (если визуально допустимо) или скрыты, в зависимости от выбранного дизайна.
- FR-007: При исчерпании 5 круток на день отображается полноэкранный баннер с сообщением о необходимости «перевода денег на b2c стартап» для продления лимитов; вращение недоступно.
- FR-008: В полночь по локальному времени пользователя лимит круток обновляется до 5.
- FR-009: «Ценные» призы выпадают существенно реже «рядовых», при этом интерфейс колеса не создает явного впечатления манипуляции.
- FR-010: Данные пользователей и их доступные эмодзи хранятся централизованно; отказ от хранения в JSON.
- FR-011: Эмодзи в базе хранятся как код-идентификаторы с версией набора (код + версия) из фиксированного справочника, с возможностью сопоставления с визуальными иконками.
- FR-012: На каждом раунде колеса гарантированно присутствует как минимум одно эмодзи в пулле призов.
- FR-013: Имена пользователей уникальны; при попытке использовать занятое имя требуется выбрать другое.
- FR-014: Очень редкий приз «мульти-эмодзи» позволяет назначать до 3 эмодзи на одну задачу; по умолчанию — одно эмодзи на задачу.
- FR-014a: При отсутствии активного перка «мульти-эмодзи» элемент «Добавить ещё эмодзи» отображается в неактивном состоянии, с подсказкой о способе разблокировки.
- FR-015: «Странные» призы носят шутливый характер и не оказывают функционального влияния на задачи или лимиты.
- FR-016: Текущие JSON-данные пользователей подлежат миграции в централизованное хранилище; результаты миграции проверяемы.

## Edge Cases

- Пользователь повторно получает уже доступное эмодзи: система обрабатывает дублет по правилу «игнор + сообщение» (без изменения набора).
- Пользователь меняет имя на совпадающее с уже существующим: изменение запрещено; пользователю предлагается выбрать другое имя.
- Пользователь теряет соединение во время вращения: результат должен быть определен однозначно и не допускать повторного бесплатного вращения.
- Пользователь исчерпал лимит и перезапустил приложение: баннер должен сохраняться до обновления лимита.
- Сброс лимита учитывает UTC и текущее смещение пользователя при определении полуночи.
- Пулл призов обязан включать ≥1 эмодзи: нарушение этой инварианты — ошибка конфигурации.
 - Если визуально нельзя показать недоступные эмодзи серым, они скрываются из списка; пользователь информируется о существовании дополнительных эмодзи через подсказку.

## Success Criteria (measurable)

- SC-001: ≥80% пользователей, попробовавших «ИГРАТЬ», совершают ≥1 крутку при первой сессии.
- SC-002: ≥60% пользователей возвращаются на следующий день для новых круток (при наличии данных).
- SC-003: ≥70% задач, созданных после запуска фичи, имеют хотя бы одну эмодзи-метку у пользователей, разблокировавших эмодзи.
 - SC-004: Средняя доля «редких» и «очень редких» призов среди всех выпадений ≤ 15% (целевые пороги 85/10/5), отличимо ниже «обычных».
- SC-005: Количество жалоб/обратной связи о «подкрутке» не превышает 10 на 1000 пользователей.
