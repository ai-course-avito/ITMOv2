# Backend Specification

Feature: Игрификация задач: колесо фортуны и эмодзи (Backend)
Created: 2026-10-28

## Scope

- Пользовательские профили: уникальные имена; создание при первом входе; хранение лимита круток; отметка перка «мульти-эмодзи»; список доступных эмодзи (код+версия).
 - Каталог эмодзи: закрытый справочник (код+версия, редкость, отображение). Требование: отображение хранится как Unicode-глиф (emoji), а не путь к статическому файлу. Это исключает зависимости от ассетов и 404.
- Колесо фортуны: формирование пула призов (мин. 8 сегментов, гарантированно ≥1 эмодзи), управление редкостью 85/10/5, генерация результата спина.
- Лимиты: 5 круток/день, сброс по полуночи локального времени (UTC + смещение), учёт и валидации попыток.
- Правила дублей: «игнор + сообщение» при выпадении уже открытого эмодзи.
- Перк «мульти-эмодзи»: очень редкий приз; разрешение до 3 эмодзи на задачу.
- Миграция данных: JSON → БД, политика «пропуск + отчёт», отклонение дубликатов имён.

## Contracts (Responsibilities)

- Вход/профиль: создать/вернуть профиль по имени; обеспечить уникальность имён.
- Колесо: выдать пул призов на раунд; принять запрос спина; вернуть результат; списать крутку.
- Лимиты: вычислить остаток круток, время до сброса (UTC + смещение), применить бан при 0 круток.
- Эмодзи и задачи: зафиксировать выдачу эмодзи пользователю; обработать запросы на назначение/снятие эмодзи у задач с учётом перка.
 - Каталог: предоставить UI список эмодзи (код+версия) с атрибутами редкости/отображения (glyph в icon_ref). UI может использовать glyph напрямую; ссылки на файлы не допускаются.
- Миграция: выполнить перенос, сформировать отчёт.

## Non-Goals (Backend)

- Управление анимацией колеса, визуальными эффектами, состояниями UI.
- История спинов в UI и её отображение пользователю.

## Acceptance Mapping (Backend)

- FR-001/013: Уникальный вход по имени; создание профиля при первом входе.
- FR-003/004/009/012: Пул призов, редкость 85/10/5, гарантированно ≥1 эмодзи, результат спина и учёт лимитов.
- FR-005/011: Доступность эмодзи только после выпадения; хранение код+версия.
- FR-007/008: Применение баннера (через статусы) при 0 круток; сброс лимитов по полуночи локального времени (UTC + смещение).
- FR-014: Перк «мульти-эмодзи» (до 3 эмодзи/задачу).
- FR-016: Миграция JSON → БД (пропуск + отчёт; отклонение дублей имён).
