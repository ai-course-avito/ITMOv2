# Рефлексия

## Что реально помогло
- Разделение ролей (контракт → skill → поручение) резко снизило разброс между сессиями: агент в фиче A и агент в фиче B читали одни и те же `AGENTS.md`/`docs/requirements.md`/`docs/design.md` и не изобретали архитектуру заново.
- Эталонный тест (`tests/test_example.py`) реально сработал как якорь стиля — агент в фиче A явно на него ссылался при TDD-цикле (red → green, зафиксировано в логах сессии).
- Worktree оказался удобным именно тем, чем и обещали: фича B писалась в чистом контексте, не зная деталей реализации A, и мерж прошёл fast-forward без конфликтов.

## Что мешало / не сработало сходу
- OpenCode-плагин-хук (`ctx.tool.hook("execute.after", ...)`) из методички **не завёлся**: установленный `opencode 2.0.15` + `@opencode-ai/plugin 1.18.25` (через pacman) не содержит домена `ctx.tool` вообще, а старый формат `Hooks`-объекта новый загрузчик молча игнорирует (без ошибки, но и без эффекта). Нашёл причину только по логам (`~/.local/share/opencode/log/opencode.log`) и официальному гайду миграции V1→V2 на GitHub курса. Решил не обновлять OpenCode поверх системного pacman-пакета (риск сломать окружение) и сделал автопроверку как git pre-commit hook — он реально блокирует коммит на красных тестах и пропускает на зелёных (проверено вживую, не на словах).
- Передача больших промптов агенту одной bash-командой с кучей вложенных кавычек один раз просто "зависла" — на деле сломался парсинг самого шелла, а не агент. Решилось переносом текста поручения в отдельный файл и подстановкой через `$(cat file)`.
- Установленный `mcp` SDK оказался версии 2.3.0 — заметно отличается от типичных туториалов (`FastMCP` переименован в `MCPServer`). Агент дважды подряд тратил весь отведённый тайм-аут на самостоятельную разведку API вместо написания кода. Помогло, когда я сам нашёл рабочий пример использования прямо внутри установленного пакета и передал агенту готовый шаблон вместо абстрактного задания.
- Один раз агент (GPT-5 через курсовой `vsellm`) **заявил, что у него нет доступа** к нашему же MCP-инструменту, хотя `graph-stats.graph_stats` реально был в списке его доступных tools. Помогла только явная проверка списка инструментов и повторный, более прямой вызов — после чего всё сработало корректно.

## Где пришлось вмешаться
- Все решения — выбор модели, замена хука на git-уровень, конкретный шаблон MCP-сервера — принимались не на основе слепого доверия отчётам рабочего агента: каждый раз результат перепроверялся независимо (grep по файлу, реальный запуск сервера, сырой JSON-лог вызова инструмента, живой тест pre-commit на специально сломанном тесте), а не просто принимался текстовый отчёт "готово".
- Решение не обновлять OpenCode, чтобы не рисковать системой — моё осознанное решение, а не то, что предложил агент.
- Распределение работы: весь код писал рабочий агент (`vsellm/openai/gpt-5`), я выступал в роли оркестратора/ревьюера — формулировал точные поручения, разведывал реальные API (где агент сам не справлялся или зацикливался), проверял результат независимо и решал, что делать дальше при расхождении с ожиданиями.
