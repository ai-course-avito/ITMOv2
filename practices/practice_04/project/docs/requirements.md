# Контракт: граф задач по тегам

## Стек
Бэкенд: FastAPI, in-memory хранилище (список в памяти процесса, без БД).
Фронт: чистый HTML/JS + d3-force (CDN, без сборки).

## Данные
Задача: {id: int, title: str, tags: list[str]}.
Ребро между двумя задачами - если есть хотя бы один общий тег.
Связный кластер - множество задач, транзитивно соединённых через общие теги.

## UI
- Меню добавления/удаления задачи.
- Канвас с графом: клик по узлу подсвечивает его связи.
- Панель настроек: 3 слайдера - сила отталкивания, длина связи, радиус коллизии (live-обновление симуляции).

## Фича A - входная валидация (POST /tasks, бэкенд, авторитетно)
- title: непустой (после strip), не длиннее 100 символов.
- tags: от 1 до 5 штук, каждый непустой, только буквы/цифры/дефис, не длиннее 20 символов.
- Невалидный вход -> HTTP 422, задача не создаётся.
- Валидный вход -> HTTP 201, задача создаётся и возвращается с присвоенным id.

## Фича B - отказ зависимости (фронт)
- Фронт загружает список задач с GET /tasks с таймаутом ~3 секунды.
- При таймауте/ошибке сети - UI не падает: показывает баннер "не удалось связаться с сервером, показан последний известный список" и продолжает показывать последние данные из localStorage.
- После восстановления связи баннер пропадает при следующей успешной загрузке.
