Правила хороших тестов для этого проекта (FastAPI, pytest):

1) Тестируй через публичный HTTP API (fastapi.testclient.TestClient), а не внутренние структуры.
2) Один сценарий на тест; придерживайся Arrange-Act-Assert.
3) Имя теста: test_<поведение> (не детали реализации).
4) Всегда проверяй response.status_code явно.
5) Явно проверяй тело ответа: важные поля и их значения/формат.
6) Не используй моки там, где можно вызвать реальный код через HTTP API.
7) Подготавливай состояние через API (например, POST /tasks) — не лезь во внутренние списки.
8) Тесты независимы: не полагайся на порядок выполнения и глобальное состояние.
9) Соблюдай контракт из docs/requirements.md (коды 201/422, схема задачи).
10) Минимизируй фикстуры; создавай клиент локально или через простую фикстуру без магии.
11) Используй понятные payload'ы; не перегружай тест лишними данными.
12) При ошибках проверяй как код, так и сообщение/структуру тела, если оно определено контрактом.
13) Избегай тестов на внутренние функции/классы — проверяй наблюдаемое поведение HTTP.
14) Держи тесты быстрыми; не вводи sleep и сетевые зависимости.
15) При добавлении эндпоинтов — сначала RED: новый тест должен падать по ожидаемой причине.
