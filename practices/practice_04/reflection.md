# Reflection. Практика 4

## Что сделано
- Собственный MCP-сервер `calculator-validator` на Node.js.
- Tool `validate_calculation_input` с Zod-схемой.
- Проверки: конечность чисел, деление на ноль.
- Тестовый клиент `test-client.js` — вызов tool в трёх режимах.

## Что работало
- Zod автоматически отклоняет неверные типы (`"abc"` вместо `10`).
- `Number.isFinite` ловит `NaN`, `Infinity`, `-Infinity` — то, что Zod пропускает.
- `isError: true` в ответе — корректная обработка ошибок без исключений.
- Stdio-транспорт: сервер и клиент запускаются одной командой, без сети.

## Что не работало / ограничения
- Zod не ловит `Infinity` как `number` — нужна ручная проверка.
- Деление на ноль — не ошибка схемы, нужна отдельная проверка.
- MCP-сервер сам по себе не подключён к реальному калькулятору — только валидирует вход. Это ограничение практики: задача — именно валидация, а не вычисления.

## Выводы
- MCP-tool удобен для вынесения проверок за пределы агента.
- Валидация делится на два уровня: структурная (Zod) + предметная (ручная логика).
- Ошибочные входы важнее корректных для тестирования: они показывают, что tool умеет отклонять невалидные данные.
- `isError: true` — правильный способ вернуть ошибку в MCP, не ломая протокол.
