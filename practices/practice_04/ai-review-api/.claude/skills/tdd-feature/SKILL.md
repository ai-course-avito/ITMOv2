# tdd-feature: фича через падающий тест

Процедура для этого проекта (FastAPI, pytest, LLM подменяется через `dependency_overrides`). Выполняй шаги по порядку и не перескакивай.

## Файлы skill (подгружай явно)

- `writing-good-tests.md` рядом с этим файлом: прочитай ПЕРЕД тем, как писать тест (что тестируем, имена, моки LLM, плохие тесты).
- `scripts/fail_first.sh` рядом с этим файлом: запускай на новом тесте на шаге 3. Он печатает `FAIL-FIRST OK` или `FAIL-FIRST BAD` с причиной.

## Процедура

1. **Контракт и пример.** Прочитай `docs/requirements.md` (раздел нужной фичи, точные коды и тела ответов) и `tests/test_example.py` (стиль: TestClient, fake LLM, `dependency_overrides`). Прочитай `docs/style-guide.md`. Не меняй контракт.
2. **Падающий тест.** Прочитай `writing-good-tests.md`. Напиши один тест на один сценарий из контракта в `tests/` (новый файл `tests/test_<фича>.py` или рядом с похожим). Имя теста описывает поведение.
3. **Fail-first.** ЗАПУСТИ тест, не пропускай шаг:
   `sh .claude/skills/tdd-feature/scripts/fail_first.sh tests/test_<фича>.py::test_<имя>`
   - `FAIL-FIRST OK`: проверь, что причина "нет нужного поведения" (например 200 вместо 422). Иди дальше.
   - `FAIL-FIRST BAD`: чини тест, а не код. Тест прошел сразу, ошибка импорта, опечатка, сломанная фикстура: значит тест не доказывает ничего. Повторяй шаг 3, пока не будет OK по правильной причине.
4. **Минимальная реализация.** Правь `app/`, ровно столько, сколько нужно для зеленого теста. Зависимости только через `Depends`, ошибки в формате из style guide. Никакого "заодно".
5. **Полная проверка.** `sh scripts/check.sh`. Последняя строка должна быть `CHECK PASS`. При `CHECK FAIL` читай хвост pytest, чини и повторяй. Не меняй `scripts/check.sh`.
6. **Diff.** `git diff` и убедись, что изменились только нужные файлы (тест + код фичи), нет отладочных принтов, временных файлов, лишних комментариев.

Если сценариев несколько, повторяй шаги 2-5 по одному сценарию (красный, зеленый, следующий).

## Итог

Коротко сообщи: какие тесты добавлены, вывод fail-first (OK и причина), финальная строка `CHECK PASS`, список измененных файлов.
