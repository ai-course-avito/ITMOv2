# SPEC — subtracker

## 1. Продукт

**Проблема.** Люди забывают, за что платят (стриминг, облака, VPN, приложения): списания приходят неожиданно, общая сумма в месяц и в год неизвестна.

**Ценность.** Один экран показывает расход за месяц и за год и заранее предупреждает о списаниях.

**Аудитория.** Физлица с 5–20 подписками. Разработка — соло, ролей и командных тарифов нет.

## 2. Тарифы

| | Free | Pro |
|---|---|---|
| Количество подписок | без лимита | без лимита |
| Список подписок, расход за месяц/год | да | да |
| Реклама | да (показывает фронт) | нет |
| Перетаскивание (ручной порядок подписок) | нет | да |
| Интеграция с календарём (дата списания) | нет | да |
| Прогноз расходов | нет | да |
| Оценка необходимости подписки (рейтинг) | нет | да |
| Подсказки по экономии / оптимизации расходов | нет | да |

Статус реализации: **ни одна Pro-фича пока не реализована.** Реализован только признак `plan` (`free` по умолчанию) и его выдача через `GET /api/auth/me`. Реклама — задача фронта: бэкенд лишь сообщает план. Оплата (Stripe) не делается; тариф переключается вручную в БД. Лимита подписок на Free нет.

## 3. Модель данных

- **User**: `id`, `email` (уникален, хранится в нижнем регистре), `hashed_password` (argon2), `default_currency` (3 буквы; одна валюта на пользователя), `plan` (`free` | `pro`, по умолчанию `free`).
- **Subscription**: `id`, `owner_id` → User, `name` (1–255), `amount` (`Decimal`, > 0, 2 знака, до 99 999 999.99), `billing_cycle` (`monthly` | `yearly` | `weekly` | `custom_days`), `custom_interval_days` (обязателен и > 0 только для `custom_days`, иначе запрещён), `is_active`, `start_date`, `next_billing_date`, `note` (до 500, необязательно).
- Правила на `amount`, `billing_cycle` и `custom_interval_days` дублируются CHECK-ограничениями в БД. Категорий нет.

Следующие этапы добавят поля для Pro-фич (порядок, оценка необходимости).

## 4. API

Все эндпоинты, кроме `/health` и `/api/auth/*`, требуют `Authorization: Bearer <access_token>`.

**Реализовано**
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`, `GET /api/auth/me`
- `GET /health`
- `GET /api/stats/summary` — расход за месяц/год по активным подпискам текущего пользователя.
- `POST /api/subscriptions` (201), `GET /api/subscriptions` (`is_active`, `limit` 1–500 по умолчанию 100, `offset`), `GET /api/subscriptions/{id}`, `PATCH /api/subscriptions/{id}`, `DELETE /api/subscriptions/{id}` (204).
- `GET /api/subscriptions/upcoming?days=N` — ближайшие списания.

Чужая подписка неотличима от несуществующей: 404 на чтение, изменение и удаление. Поля `id` и `owner_id` в запросе игнорируются. Невалидные данные — 422. Лимита подписок на Free нет.

Пример создания:
```json
POST /api/subscriptions
{"name": "Netflix", "amount": "15.49", "billing_cycle": "monthly", "start_date": "2026-01-05"}
```
Ответ содержит `amount` строкой с двумя знаками (`"15.49"`) и `next_billing_date`. Если дата не передана, она считается как ближайшая дата списания не раньше сегодняшнего дня от `start_date` по циклу.

**PATCH** — частичное обновление: итоговая подписка проверяется целиком. Если меняются `billing_cycle`, `custom_interval_days` или `start_date` и `next_billing_date` не передан, дата пересчитывается; при переходе с `custom_days` на другой цикл интервал сбрасывается сам.

**Ближайшие списания (напоминания).** `days` от 1 до 365, по умолчанию 7. Возвращаются свои активные подписки, у которых дата списания попадает в промежуток от сегодня до сегодня + `days` включительно. Элемент: `id`, `name`, `amount`, `billing_cycle`, `charge_date`, `days_until`; сортировка по `charge_date`, затем по `name`. Если сохранённая `next_billing_date` уже в прошлом, `charge_date` считается от неё вперёд по циклу (месяц и год — с обрезкой до последнего дня месяца без накопления сдвига: 31 января -> 28 февраля -> 31 марта; 29 февраля + год -> 28 февраля). Запрос ничего не записывает в БД. «Сегодня» — дата по UTC, поэтому у пользователей в других часовых поясах возможен сдвиг на день около полуночи UTC. Напоминаний по email нет: это список для экрана.

**Планируется:** Pro-эндпоинты (прогноз, рейтинг, подсказки).

## 5. Дорожная карта (этапы, один этап = один change и коммит)

1. `backend-foundation` — миграции, auth, `plan`, запуск без Docker, seed, `/health`, CORS. Готово.
2. `subscriptions-crud` — CRUD подписок, изоляция пользователей, `next_billing_date`, ближайшие списания (напоминания считаются по запросу, планировщик не нужен).
3. Фронтенд: дизайн (тёмная тема), вход, список, дашборд.
4. Pro-фичи: прогноз, календарь, рейтинг необходимости, подсказки, drag-and-drop.
5. Оплата (Stripe) и реклама.

## 6. Известные ограничения (TODO)

- Refresh-токены не хранятся и не отзываются (stateless JWT) — для продакшена нужен список/ротация.
- Напоминаний по email/push нет: ближайшие списания считаются при запросе. Когда понадобятся уведомления вне приложения, потребуется планировщик (очередь задач или cron + таблица статусов); APScheduler внутри процесса не годится для продакшена (теряется при перезапуске, не масштабируется на несколько инстансов). В `AGENTS.md` он пока значится в стеке — устарело.
- «Сегодня» для напоминаний — UTC, персональных часовых поясов нет.
- Docker/compose пока нет (в `AGENTS.md` они указаны как планируемые); запуск локальный (см. раздел 7).

## 7. Локальный запуск

Нужны: Python-окружение через `uv`, запущенный PostgreSQL и база из `DATABASE_URL`.

```bash
cd backend
uv sync
cp .env.example .env          # один раз; задайте SECRET_KEY (обязателен)
./scripts/dev.sh --seed       # проверка БД -> миграции -> демо-данные -> uvicorn на :8000
```

- Swagger: http://localhost:8000/docs, проверка живости: http://localhost:8000/health
- Демо-пользователь после `--seed`: `demo@example.com` / `demo-password` (план `free`, 5 подписок). Повторный запуск не создаёт дубликатов.
- Без демо-данных: `./scripts/dev.sh`.
- Перевести пользователя на Pro вручную: `UPDATE users SET plan = 'pro' WHERE email = '...';`
- Тесты: `uv run pytest`. Тест миграций на реальном Postgres включается переменной `TEST_POSTGRES_URL` (укажите одноразовую БД, он делает `downgrade base`).
- Линт и формат: `uv run ruff check .`, `uv run ruff format .`
