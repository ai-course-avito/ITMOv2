# Design

## Context

Бэкенд готов и не меняется; CORS разрешает `http://localhost:5173` и заголовки `Authorization`, `Content-Type`. Деньги приходят строками (`"15.49"`), даты — `YYYY-MM-DD`. Макеты — файлы `.dc.html` в `design/project/`: из них берутся цвета, размеры, тексты и состав экранов, но не код. Мотивация — в `proposal.md`, требования — в `specs/`.

## Goals / Non-Goals

**Goals:**
- Точное повторение макетов на 1280 px и на 390 px, обе темы, оба языка.
- Минимум зависимостей: проект учебный, фронтенд должен читаться целиком.
- Расчёты денег только на бэкенде.

**Non-Goals:**
- Серверный рендеринг, PWA, офлайн-режим.
- Тесты в браузере (Playwright): проверка экранов вручную и тестами компонентов.
- Хранение темы и языка на сервере.

## Decisions

1. **Vite + React 19 + TypeScript (strict) + Tailwind CSS v4** через `@tailwindcss/vite`. Цвета макетов вынесены в CSS-переменные (`--bg`, `--surface`, `--line`, `--accent` и т. д.) и подключены как токены Tailwind; тема переключается атрибутом `data-theme` на `<html>`. Альтернатива — два набора классов `dark:`: отвергнута, переменные из макетов уже так устроены.
2. **Маршрутизация — `react-router-dom`**: `/login`, `/` (Обзор), `/subscriptions`. Обёртка `RequireAuth` для защищённых маршрутов.
3. **Свой тонкий API-клиент на `fetch`** (`src/api/client.ts`), без axios и без TanStack Query. Он подставляет Bearer, при 401 один раз обновляет токен и повторяет запрос; одновременные 401 делят один refresh-запрос. Ответы разбираются в типы; в camelCase поля переводятся только в клиенте (решение из `SPEC.md`). Альтернатива — TanStack Query: удобнее, но для трёх экранов лишняя зависимость; данные грузятся простым хуком `useAsync` с повтором.
4. **Хранение сессии — `localStorage`** (access и refresh). Компромисс: токены доступны скриптам страницы при XSS. Принято для MVP, записано в `SPEC.md` как ограничение; `httpOnly`-cookie потребует изменения бэкенда.
5. **Деньги — строки.** Форматируются функцией `formatMoney(value: string, currency)` через `Intl.NumberFormat` с передачей строки, без `parseFloat` и без сложения в браузере. Доли и проценты приходят с бэкенда; ширина столбцов топ-5 считается как отношение двух строк, переведённых в числа только для CSS-процентов (это не деньги, а геометрия).
6. **Диаграмма — свой SVG** (`stroke-dasharray`, как в макете), без библиотеки графиков. Цвета сегментов — фиксированная палитра из макета, по кругу при более чем шести подписках; последний сегмент «Остальное» для хвоста длиннее шести.
7. **i18n — свой словарь** `src/i18n/ru.ts` и `en.ts` с общим типом ключей (TypeScript не даёт забыть ключ) и контекст `useT()`. Даты и числа — `Intl` с локалью `ru-RU` или `en-US`. Тексты ошибок бэкенда сопоставляются с ключами по статусу и полю; сырой `detail` не показывается.
8. **Тема и язык — контексты** с чтением из `localStorage` в блоке `try/catch` и значением по умолчанию `dark` и `ru`. Начальная тема выставляется скриптом до отрисовки, чтобы не было вспышки светлой темы.
9. **Группировка списка** по `days_until` на клиенте: 0 — «Сегодня», 1–7 — «На этой неделе», 8–30 — «В этом месяце», больше — «Позже», `null` — «Приостановлены». Поиск, фильтры и сортировка отправляются на бэкенд (дебаунс поиска 300 мс). Сортировка по умолчанию — `charge_date`.
10. **Панель добавления и правки — один компонент** `SubscriptionPanel`: боковая панель от 768 px, нижняя шторка уже. Форма проверяет поля так же, как бэкенд (сумма > 0, два знака, интервал 1–3650 только для `custom_days`); следующая дата списания не отправляется, её считает бэкенд.
11. **Пауза** — `PATCH {is_active: false}`; **удаление** — диалог подтверждения (`<dialog>`), затем `DELETE`.
12. **Баннер рекламы** — компонент по `plan` из `GET /api/auth/me`, который грузится один раз после входа.
13. **Тесты — Vitest + Testing Library + jsdom**, запросы подменяются `fetch`-заглушкой. Проверяются: клиент (refresh при 401), форматирование денег, группировка, словари (одинаковые ключи), защита маршрутов, форма подписки.
14. **Структура:** `src/api`, `src/i18n`, `src/theme`, `src/auth`, `src/components`, `src/pages` (`Login`, `Overview`, `Subscriptions`), `src/lib` (деньги, даты, группы).

## Risks / Trade-offs

- [Токены в `localStorage` уязвимы при XSS] → React экранирует вывод, внешних скриптов нет; в `SPEC.md` записано как ограничение.
- [Макеты статичные: состояния загрузки, ошибки и пустого списка в них нет] → делаются в той же стилистике и описаны в спеках.
- [«Сегодня» на бэкенде считается по UTC, у клиента другой часовой пояс] → фронтенд использует `days_until` и `charge_date` из ответа, а не собственную дату.
- [Без библиотеки данных возможны лишние запросы] → после изменения подписки перезагружаются только открытые экраны.
- [Свой SVG-график хуже в доступности, чем готовая библиотека] → `role="img"` с текстовым описанием и легенда с теми же числами.
- [Свёрстанное по макету может разойтись с ними] → сверка в браузере на 1280 и 390 px обеих тем перед закрытием change.
