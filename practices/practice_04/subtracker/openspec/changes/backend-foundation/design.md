# Design

## Context

Backend is FastAPI + async SQLAlchemy (asyncpg) with `User`/`Subscription` models, a `get_current_user` JWT dependency, and one stats router. Tests use SQLite in-memory (`aiosqlite`) with auth overridden via `dependency_overrides`. Local Postgres 17 runs via brew; Docker is not installed. AGENTS.md forbids hand-edited schema, floats for money, business logic in routes. See proposal.md for motivation.

## Goals / Non-Goals

**Goals:**
- Reproducible schema via Alembic, working against local Postgres.
- Real auth flow, testable end to end (including real token verification, not only overrides).
- Run-and-evaluate locally with one command and demo data.

**Non-Goals:**
- Refresh-token revocation/rotation storage, email verification, password reset.
- Implementing Pro features, ad serving, payments, any subscription-count limit.
- Subscription CRUD and schema additions such as `next_billing_date` (next change; will come with its own migration).
- Docker/compose files.

## Decisions

1. **Async Alembic env** (`alembic init -t async`), URL taken from `settings.database_url`, `target_metadata = Base.metadata`. Alternative: sync driver just for migrations - rejected to avoid a second driver (psycopg) and URL duplication.
2. **argon2 via `argon2-cffi` `PasswordHasher`** in `app/security.py`, with `verify` catching `VerifyMismatchError`. Alternative: passlib - unmaintained, rejected. Hashing is CPU-bound; call via `asyncio.to_thread` to avoid blocking the loop.
3. **Stateless JWT with a `type` claim** (`access`/`refresh`) plus `exp`, `iat`, `sub`. Decode with `options={"require": ["exp", "sub"]}` and reject wrong type. Alternative: refresh tokens stored in DB for revocation - deferred (MVP; noted as TODO in SPEC.md, consistent with AGENTS.md's honesty about MVP limits).
4. **Email normalization**: lowercase on write and lookup; unique constraint on the stored value. Catch `IntegrityError` for the race and map to 409 rather than only pre-checking.
5. **Layering**: `routers/auth.py` (HTTP) -> `services/auth.py` (register/authenticate/token issuing) -> `security.py` (hash, jwt encode/decode). `get_current_user` moves its decoding to `security.py`.
6. **`HTTPBearer(auto_error=False)`** and raise 401 ourselves so missing credentials are 401 regardless of FastAPI version.
7. **Config**: `secret_key` has no default (pydantic raises on startup); add `access_token_ttl_minutes` (15), `refresh_token_ttl_days` (7), `cors_origins` (list, default `["http://localhost:5173"]`). Tests set `SECRET_KEY` in `conftest.py` before importing the app.
8. **Initial migration is autogenerated then reviewed**; verified by upgrade/downgrade and a drift check (`alembic check`) against local Postgres in a scratch database.
9. **Dev script `backend/scripts/dev.sh`**: loads `.env`, probes the DB with `scripts/check_db.py` (opens a connection using `DATABASE_URL`, exits non-zero with a message naming host and port), runs `alembic upgrade head`, optional `--seed`, then `uvicorn --reload`. Seed is `backend/scripts/seed.py` using the service layer, idempotent by demo email. Alternative: Makefile - rejected for portability of the explanation; a shell script is easy to read.
10. **Runtime dependencies**: `uvicorn[standard]` (it was missing, so `uvicorn app.main:app` could not start) and `email-validator` (required by Pydantic `EmailStr`) are added alongside `alembic` and `argon2-cffi`.
11. **`/health`** executes `SELECT 1`; 503 on failure.
12. **Tests**: auth tests use a real token path (no override) on SQLite; migration tests run only when a Postgres URL is provided via env (skipped otherwise), so `uv run pytest` still works anywhere.

13. **Plan as a string column with a CHECK (`free`/`pro`), server default `free`**, added to `User` now so the initial migration already contains it. Alternative: a separate `plans` table or boolean `is_pro` - rejected as heavier than needed for two tiers. No entitlement logic is built here; features check `user.plan` in later changes. Plan is changed manually (SQL or a small script) until payments exist.
14. **Business model lives in SPEC.md**: Free = unlimited subscriptions + ads; Pro = no ads + drag-and-drop ordering, calendar integration, spending forecast, subscription necessity rating, savings/optimization suggestions. Ads are a frontend concern; the backend only reports `plan`.

## Risks / Trade-offs

- [Stateless refresh tokens cannot be revoked] -> Documented TODO in SPEC.md; short access TTL limits exposure.
- [SQLite tests differ from Postgres] -> Migration tests against Postgres when available; money columns already `Numeric`.
- [Making `SECRET_KEY` required breaks existing local setups] -> `.env.example` updated; `.env` already exists locally with a value to verify during apply.
- [Argon2 slows tests] -> Accepted: default parameters cost tens of milliseconds per hash and the full suite still runs in about a second.
- [Existing `models.py` lacks constraints (email case, billing_cycle enum)] -> Only what the migration needs now; enum/check constraints arrive with CRUD change to avoid a second migration churn here.
