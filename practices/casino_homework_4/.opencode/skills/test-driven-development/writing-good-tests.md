# Правила хороших тестов для LuckySpin

## Основные принципы
- Тест проверяет ценность для пользователя, а не внутреннюю реализацию.
- Один сценарий — один ожидаемый результат (Arrange-Act-Assert).
- Тесты быстрые, детерминированные, независимые.

## Практики
- RNG и время контролируем: инъекция зависимостей или мок часов/рандома.
- Логику выигрыша и баланс выносим в чистые функции и тестируем без UI.
- UI-тесты покрывают взаимодействия: клик по игре, ввод ставки, спин, получение результата.
- Не используем any в тестах TypeScript, описываем типы ожидаемых значений.
- Именование: describe — фича, it — конкретное поведение.

## Примеры сценариев LuckySpin
- Спин: при достаточном балансе и ставке списываем ставку, запускаем RNG, возвращаем результат, баланс обновляется.
- Бонус: если сегодня бонус ещё не получен, колесо фортуны выдаёт монеты; повторный запрос в тот же день — отказ.
- Баланс: баланс сохраняется в localStorage и восстанавливается при перезагрузке.

## Антипаттерны
- Тесты, зависящие от реального времени/рандома.
- Огромные снапшоты без смысла.
- Тесты, дублирующие реализацию построчно.
- Общие состояния между тестами.

## Короткие правила
- «Тест читает как спецификация».
- «Один источник случайности под контролем».
- «Падай по причине: сообщение ошибки должно помогать».
