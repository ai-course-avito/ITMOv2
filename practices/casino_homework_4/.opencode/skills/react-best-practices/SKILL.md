# React Best Practices (LuckySpin)

## Когда применять
- Любая разработка UI в LuckySpin: лобби автоматов, окно спина, колесо бонуса.
- Рефакторинг компонентов и хуков.

## Как устроено
- Функциональные компоненты и хуки. Без классовых компонентов.
- TypeScript без any; точные проп-тайпы, возвращаемые типы для хуков.
- Состояние через Zustand для глобального баланса/истории; локальное состояние — useState/useReducer.
- Мемоизация по необходимости: useMemo/useCallback только при горячих путях или дорогих вычислениях, с измеримым эффектом.
- Побочные эффекты в useEffect/useEffectEvent; избегаем гонок, чистим таймеры.
- Стабильные ключи списков, предсказуемый рендер.

## Шаги
1. Определить данные и источник правды: глобальное (Zustand) vs локальное.
2. Описать пропсы и стейт типами. Не использовать any; предпочитать конкретные union/enum.
3. Реализовать компонент как чистую функцию UI → JSX; вынести бизнес-логику в хуки/утилиты.
4. Добавить эффекты только для синхронизации с внешним миром (localStorage, таймеры).
5. Оптимизировать рендер только после профилирования; добавить мемоизацию точечно.
6. Написать тесты UI через @testing-library/react на пользовательские сценарии.

## Запрещено
- any, unknown без причины; implicit any в конфиге.
- Бессмысленная мемоизация «на всякий случай».
- Сайд-эффекты в рендере; чтение/запись localStorage напрямую из JSX.
- Классовые компоненты и mixins.
- Нестабильные ключи списков (index как key, если возможны изменения порядка).
