# Feature Specification: Экспорт событий в JSON

**Feature Branch**: `002-events-export-api`

**Created**: 2026-10-29

**Status**: Draft

**Input**: User description: "Экспорт событий в JSON: пользователь с ролью ADMIN скачивает все события карты как JSON-файл"

## User Scenarios & Testing

### User Story 1 - Администратор скачивает полный экспорт (Priority: P1)

Администратор получает один JSON-файл со всеми событиями карты и данными планеты, на которой произошло каждое событие.

**Why this priority**: Полный экспорт является основной ценностью функции и нужен для резервного копирования и анализа данных.

**Independent Test**: При наличии нескольких событий администратор вызывает endpoint и проверяет, что файл содержит каждое событие ровно один раз и пригоден для повторного чтения как JSON.

**Acceptance Scenarios**:

1. **Given** действующая сессия пользователя с ролью ADMIN и 3 события в хранилище, **When** пользователь отправляет `GET /events/export`, **Then** сервер возвращает статус 200, JSON-файл с 3 записями и заголовки скачивания.
2. **Given** событие связано с планетой, **When** выполняется экспорт, **Then** поле `place` содержит данные планеты, а не только её идентификатор.
3. **Given** события имеют массивы `shots`, **When** выполняется экспорт, **Then** каждый массив сохраняется в исходном порядке, а отсутствие снимков представлено пустым массивом.

### User Story 2 - Неавторизованный запрос отклоняется (Priority: P1)

Только пользователь с ролью ADMIN может получить выгрузку.

**Why this priority**: Экспорт содержит содержимое событий и ссылки на изображения и не должен быть публичным.

**Independent Test**: Отправить запрос без cookie, с истёкшей сессией и с ролью USER и убедиться в отказе без тела файла.

**Acceptance Scenarios**:

1. **Given** запрос без сессии, **When** вызывается endpoint, **Then** возвращается 401.
2. **Given** действующая сессия с ролью USER, **When** вызывается endpoint, **Then** возвращается 403.
3. **Given** действующая сессия с ролью ADMIN, **When** вызывается endpoint, **Then** возвращается 200.

### User Story 3 - Пустая карта экспортируется корректно (Priority: P2)

Администратор может скачать экспорт, когда событий нет.

**Why this priority**: Пустой результат является валидным состоянием и не должен превращаться в ошибку.

**Independent Test**: Очистить события, вызвать endpoint и проверить валидный JSON с пустым списком.

**Acceptance Scenarios**:

1. **Given** в хранилище нет событий, **When** ADMIN вызывает endpoint, **Then** возвращается 200 и файл с `events: []`.

### Edge Cases

- Если событие ссылается на отсутствующую планету, экспорт завершается ошибкой 500 и не выдаёт частичный файл; причина записывается на сервере.
- Если количество событий превышает 10 000 или итоговый JSON превышает 50 MiB, сервер возвращает 413 и не начинает скачивание.
- Если хранилище временно недоступно, сервер возвращает 503.
- Повторяющиеся или лишние поля из базы не попадают в экспорт.
- Поля `description`, `link` и `ingamePosition`, отсутствующие в записи, сериализуются как `null`; `shots` всегда является массивом.

## Requirements

### Functional Requirements

- **FR-001**: Система MUST предоставить endpoint `GET /events/export`, возвращающий JSON-файл с медиатипом `application/json; charset=utf-8`, заголовком `Content-Disposition: attachment; filename="events-YYYYMMDD.json"` (дата UTC) и статусом 200 при успешном экспорте.
- **FR-002**: Система MUST включать корневой объект формата `{"exportedAt":"<ISO-8601 UTC>","events":[...]}`; каждая запись события MUST содержать `id`, `name`, `description`, `link`, `shots`, `place`, `createdAt`, `updatedAt`. Поле `place` MUST быть объектом с `id`, `name`, `size`, `top`, `left`, `ingamePosition`, `pic`, `description`.
- **FR-003**: Система MUST выбирать все события без фильтрации и сортировать их по `createdAt` по возрастанию, а при совпадении даты по `id` лексикографически. Порядок элементов `shots` MUST сохраняться.
- **FR-004**: Система MUST разрешать экспорт только ADMIN. Для этого endpoint MUST выполнять проверку сессии и роли явно, поскольку текущий глобальный `AdminGuard` пропускает методы GET, HEAD и OPTIONS без проверки cookie; отсутствие сессии даёт 401, неверная роль даёт 403.
- **FR-005**: Система MUST отклонять экспорт при превышении лимита 10 000 событий или 50 MiB сериализованных данных статусом 413, а ошибки чтения данных возвращать статусом 503. Тело ошибки MUST быть JSON-объектом `{"statusCode":<code>,"message":"<описание>"}` без частичного экспорта.
- **FR-006**: Система MUST формировать UTF-8 JSON без BOM, с единственным корневым объектом, пригодным для разбора стандартным JSON-парсером.

### Ожидания от клиента

Клиент должен отправлять запрос с cookie сессии и credentials, проверять статус до обработки тела и сохранять ответ как файл с именем из `Content-Disposition`. Для 401 клиент предлагает повторную аутентификацию, для 403 показывает отсутствие прав, для 413 сообщает о превышении лимита, для 503 предлагает повторить позже. Клиент не должен пытаться интерпретировать ответ с ошибкой как JSON-экспорт.

### Key Entities

- **Событие**: карта события с идентификатором, названием, описанием, ссылкой, снимками, связанной планетой и временными метками.
- **Планета**: разрешённое место события с координатами, размером, изображением и описанием.
- **Экспорт**: снимок набора событий с временем формирования и фиксированным порядком записей.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 100% запросов ADMIN к набору до 10 000 событий возвращают один валидный JSON-файл без пропущенных или повторных событий.
- **SC-002**: 100% запросов без сессии и с ролью USER завершаются статусами 401 и 403 соответственно и не содержат данных событий.
- **SC-003**: Для набора до 1 000 событий файл становится доступен клиенту не позднее 5 секунд после запроса при штатной работе хранилища.
- **SC-004**: В 100% успешных экспортов одинаковый набор данных даёт одинаковый порядок событий и снимков.

## Assumptions

- Сессия определяется существующим endpoint проверки сессии; роль имеет точное значение `ADMIN`.
- Дата в имени файла и `exportedAt` используют UTC.
- Лимиты 10 000 событий и 50 MiB применяются к одной операции и являются границей версии v1.
- Экспорт не изменяет события, планеты или файлы снимков.
- Версия API использует существующий префикс приложения, если он настроен; относительный путь остаётся `/events/export`.
