# Spec Delta

## Purpose

Общий каталог товаров, из которого клиенты выбирают позиции для заказа и из которого склады берут номенклатуру для остатков.

## ADDED Requirements

### Requirement: Создание товара
Система SHALL создавать товар с обязательными `sku` (1-64 символа) и `name` (1-200 символов) и необязательным `description` (до 1000 символов). `sku` SHALL быть уникален без учёта регистра и обрезаться по краям от пробелов.

#### Scenario: Успешное создание
- **WHEN** клиент отправляет `POST /api/products` с `sku` "MILK-1L" и `name` "Молоко 1 л"
- **THEN** ответ 201 содержит созданный товар с числовым `id`

#### Scenario: Дубликат SKU
- **WHEN** товар с `sku` "MILK-1L" уже есть и создаётся товар с `sku` "milk-1l"
- **THEN** ответ 409 с `code` равным `product_sku_duplicate`

### Requirement: Чтение каталога
Система SHALL отдавать список всех товаров (`GET /api/products`) и один товар по `id`. Каталог общий для всех складов и клиентов.

#### Scenario: Список товаров
- **WHEN** в каталоге два товара и клиент вызывает `GET /api/products`
- **THEN** ответ 200 содержит оба товара

### Requirement: Изменение товара
Система SHALL позволять изменить `sku`, `name` и `description` товара по правилам создания. Смена `sku` на занятый другим товаром SHALL завершаться отказом.

#### Scenario: Смена SKU на занятый
- **WHEN** товар A меняет `sku` на `sku` товара B
- **THEN** ответ 409 с `code` равным `product_sku_duplicate`, у товара A прежний `sku`

### Requirement: Удаление товара
Система SHALL удалять товар, только если ни на одном складе нет его положительного остатка. Нулевые строки остатков SHALL удаляться вместе с товаром. История заказов SHALL сохраняться.

#### Scenario: Товар с остатком
- **WHEN** на складе лежит 5 единиц товара и клиент удаляет товар
- **THEN** ответ 409 с `code` равным `product_has_stock`, товар остаётся

#### Scenario: Товар без остатков
- **WHEN** остатков товара нет и клиент удаляет товар
- **THEN** ответ 204, повторный `GET` возвращает 404
