# Design

## Context

Бэкенд из change `argon-logistics-core` готов (79 тестов), но не архивирован. У него нет позиций объектов и «движущегося времени»: отгрузка и доставка вызываются вручную. Фронт нужен красивый (Material Design 3), интерактивный, и всё должно подниматься через Compose. См. `proposal.md` и `specs/`.

## Goals / Non-Goals

**Goals:**
- Один экран-«рабочий стол»: карта в центре, слева «Строения»/свойства, справа заказы, планшет поверх карты.
- Грузовики едут по реальным данным API и корректно показываются после перезагрузки.
- Минимум зависимостей, воспроизводимая сборка без CDN.

**Non-Goals:**
- Реальные карты и геокоординаты, WebSocket/SSE, мобильная вёрстка редактора, браузерные e2e-тесты.

## Decisions

### Стек фронта
Next.js 16 (App Router) + React + TypeScript 5.9, данные через SWR (опрос), без UI-библиотек: Material Design 3 собран вручную из токенов (CSS custom properties: цвета baseline-схемы light/dark, типографика, формы, elevation, state layers, emphasized easing). Иконки: Material Symbols (variable font из npm), шрифт Roboto из npm.
Альтернативы: `@material/web` (поддерживается в режиме обслуживания, веб-компоненты плохо дружат с SSR и React) и MUI (визуально это Material 2/3-ish, но кастомный MD3 для карты всё равно пришлось бы рисовать). Ручные токены дают точный MD3 и ноль лишних зависимостей.

### Прокси API
Route Handler `src/app/api/[...path]/route.ts` пересылает запрос на `API_URL` (читается в рантайме, не при сборке), пропуская метод, тело и заголовки `content-type` и `x-user-id`. Альтернатива: `rewrites()` в `next.config`: адрес запекается при сборке. В Compose `API_URL=http://api:8080`, локально `http://localhost:5281`.

### Карта
Один `<svg>`: слой фона (сетка), слой связей, слой узлов, слой грузовиков, всё внутри `<g transform>` с панорамой/зумом. Перетаскивание объектов и протягивание связи на pointer events, drag-and-drop из палитры на HTML5 DnD (координаты экрана переводятся в мировые обратной матрицей). Позиция сохраняется `PUT .../position` только по окончании перетаскивания, во время него состояние локальное, чтобы не дёргать API.
Две связи между одной парой рисуются дугами с противоположным смещением, подпись времени ставится на дугу.

### Время и грузовики
Сервер отдаёт `serverTime` и `speedFactor`; фронт хранит смещение часов `serverTime - Date.now()`. Положение грузовика это чистая функция `truckPosition(legs, minutesElapsed)`, где `minutesElapsed = (serverNow - dispatchedAt) * speedFactor`. Скорость по участку пропорциональна `minutes` (участок 30 мин занимает вдвое больше времени, чем 15). Анимация на `requestAnimationFrame`, поэтому плавная между опросами, а после перезагрузки грузовик встаёт сразу в верное место. Чистая математика вынесена в `lib/geometry.ts` и покрыта unit-тестами (vitest).

### Симуляция на бэкенде
`SimulationService : BackgroundService` с тиком `TickMilliseconds`. На каждом тике в новом scope: отправки `Planned` с `order.CreatedAt + DispatchDelay <= now` отгружаются, отправки `Dispatched` с `(now - dispatchedAt) * SpeedFactor >= totalMinutes` доставляются, через существующие `OrderService.DispatchAsync/DeliverAsync` (те же замок и инварианты). Сравнение времён делается в памяти (SQLite не умеет сортировать/сравнивать `DateTimeOffset` надёжно). Ошибки конфликта (ручная операция опередила) логируются и игнорируются. Выдачу клиенту симуляция не делает: это действие человека.
Альтернатива: двигать заказы с фронта. Отвергнута: логистика остановилась бы при закрытой вкладке.

### Позиции и снимок сети
`MapX`/`MapY` (double) в сущностях Warehouse и PickupPoint, отдельные `PUT .../position`. `GET /api/network` собирает склады (с суммами остатков), ПВЗ, пути и привязки за один запрос, чтобы опрос карты был дешёвым. Схема меняется без миграций (`EnsureCreated`): старую базу нужно удалить (описано в README).

### Планшет и клиент
Гость создаётся автоматически (`POST /api/users` с `guest-<random>@argon.local`), id хранится в `localStorage`; при 401 создаётся новый. Корзина тоже в `localStorage`. Предпросмотр через `POST /api/plans` с дебаунсом, маршруты подсвечиваются на карте через общий контекст «preview».

### Compose
`api` (образ из `mcr.microsoft.com/dotnet/aspnet`, healthcheck на `GET /api/simulation` через `curl`/`wget` в образе), `web` (Next.js `output: "standalone"`, `depends_on: api: condition: service_healthy`), volume `argon-data` под SQLite. Симуляция включена переменными окружения `Simulation__*`.

## Risks / Trade-offs

- [Опрос вместо push: статус может запаздывать до 2 с] → Приемлемо; грузовики плавны за счёт локальной интерполяции.
- [Часы клиента и сервера расходятся] → Используется смещение по `serverTime`; ошибка порядка сетевой задержки.
- [Старая БД без новых колонок падает при старте] → README и шаг в tasks; в Compose volume новый.
- [Один процесс API, симуляция в нём же] → Достаточно для демо; при нескольких инстансах симуляцию нужно выносить (Non-Goal старого change).
- [Ручной MD3 может разойтись с эталоном в мелочах] → Токены и размеры берутся из спецификации MD3 (цвета baseline, радиусы, высоты компонентов 40/56 px).
