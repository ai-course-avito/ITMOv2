# Spec Delta

## Purpose

Визуальный редактор сети на карте: из панели «Строения» на карту перетаскиваются склады и ПВЗ, объекты двигаются, а связи между ними создаются мышью и получают время в пути.

## ADDED Requirements

### Requirement: Панель «Строения»
Интерфейс SHALL содержать панель «Строения» с двумя типами объектов: «Склад» и «ПВЗ». Перетаскивание типа на карту SHALL создавать объект через API в точке сброса с именем по умолчанию, выбирать его и показывать его свойства. Объекты SHALL оставаться на карте после перезагрузки страницы.

#### Scenario: Склад перетащили на карту
- **WHEN** пользователь перетаскивает «Склад» из панели в точку карты
- **THEN** создаётся склад с позицией этой точки, он появляется на карте и выбран

#### Scenario: Перезагрузка
- **WHEN** страница перезагружается
- **THEN** все объекты стоят на тех же местах

### Requirement: Перемещение объектов
Пользователь SHALL перемещать объекты перетаскиванием по карте. Новая позиция SHALL сохраняться через API по окончании перетаскивания. Карта SHALL поддерживать сдвиг фона и масштаб колесом мыши.

#### Scenario: Объект передвинули
- **WHEN** пользователь перетащил склад в другую точку и отпустил кнопку
- **THEN** позиция склада сохранена и после перезагрузки остаётся там же

### Requirement: Свойства и удаление объекта
Выбранный объект SHALL показываться в панели свойств с редактированием названия и адреса (для ПВЗ ещё признака активности) и кнопкой удаления. Отказ API (например, склад с остатками) SHALL показываться понятным сообщением, объект при этом остаётся на карте.

#### Scenario: Удаление склада с товаром
- **WHEN** пользователь удаляет склад, на котором есть остатки
- **THEN** показывается сообщение об отказе, склад остаётся

#### Scenario: Переименование
- **WHEN** пользователь меняет название склада и сохраняет
- **THEN** подпись на карте обновляется

### Requirement: Создание связи
Пользователь SHALL создавать связь, протянув линию от объекта-источника к объекту-цели. Допустимы связи «склад → склад» (путь) и «склад → ПВЗ» (привязка); при протягивании от ПВЗ к складу направление SHALL быть развёрнуто. После отпускания SHALL открываться диалог времени в пути (минуты, 1-10080); для пары «склад → склад» диалог SHALL предлагать опцию «в обе стороны».

#### Scenario: Путь между складами
- **WHEN** пользователь протягивает связь от склада A к складу B и вводит 60 минут
- **THEN** создаётся путь A → B со временем 60, на карте появляется стрелка с подписью «60 мин»

#### Scenario: Привязка ПВЗ
- **WHEN** пользователь протягивает связь от ПВЗ к складу
- **THEN** создаётся привязка склад → ПВЗ, а не обратная

#### Scenario: Недопустимая пара
- **WHEN** пользователь протягивает связь от ПВЗ к другому ПВЗ
- **THEN** связь не создаётся и показывается сообщение

#### Scenario: В обе стороны
- **WHEN** в диалоге включена опция «в обе стороны» для пары складов
- **THEN** создаются два пути с одним временем

### Requirement: Изменение и удаление связи
Клик по связи SHALL выбирать её и показывать панель с полем времени и кнопкой удаления. Изменённое время SHALL сохраняться через API, а подпись на карте обновляться. Если между объектами есть связи в обе стороны, они SHALL отображаться как две различимые стрелки.

#### Scenario: Изменение времени
- **WHEN** пользователь выбирает связь, вводит 90 и сохраняет
- **THEN** подпись становится «90 мин»

#### Scenario: Удаление связи
- **WHEN** пользователь удаляет связь
- **THEN** стрелка исчезает с карты
