# Data Model: HTTP API ревью диффа

Форматы стыка заданы контрактом
[specs/contract/review-api.md](../contract/review-api.md); здесь — как
команда логики их обрабатывает.

## Запрос ревью

| Поле | Тип | Правило |
|---|---|---|
| `diff` | строка | обязательно; иначе `invalid_request` (400) |
| прочие поля | любые | игнорируются |

Проверки до `review_diff`, по порядку:

1. Метод и путь: `POST /api/review`, иначе 405 / 404.
2. `Content-Length`: есть и целое ≥ 0, иначе `invalid_request`;
   > 1048576 → `request_too_large` (413), тело не читается.
3. Тело — JSON-объект (`dict`), иначе `invalid_request`.
4. `diff` есть и это `str`, иначе `invalid_request`.

Содержимое `diff` (пустота, размер в байтах) проверяет только
`review_diff` — второго правила размера нет (контракт п.7).

## Ответ ревью

Словарь `review_diff` без изменений (контракт п.3):

| `status` | HTTP | Поля |
|---|---|---|
| `ok` | 200 | `review`, `stats` |
| `rejected` | 400 | `code`, `message` |
| `error` | 502 | `code`, `message`, `stats` |

## Ошибка запроса (HTTP-слой)

`{"status": "request_error", "code": <код>, "message": <для разработчика>}`

| `code` | HTTP |
|---|---|
| `invalid_request` | 400 |
| `request_too_large` | 413 |
| `method_not_allowed` | 405 |
| `not_found` | 404 |

## Конфигурация запуска

| Параметр | Источник | По умолчанию |
|---|---|---|
| адрес | константа | `127.0.0.1` |
| порт | `REVIEW_PORT` | `8055` |
| клиент модели | флаг `--fake-model` | `OllamaClient()` |
| каталог статики | константа модуля | `<проект>/web` |

## Состояния

Сервер не хранит состояния между запросами; переходов состояний нет.
