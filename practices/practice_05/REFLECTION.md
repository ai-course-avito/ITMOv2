# Рефлексия ДЗ 5

## Зафиксированные решения

- Пользователь выбрал AI-помощника ревью PR и разрешил двум независимым агентам
  подготовить спецификации UI и логики.
- Перед кодом обсуждались непустой список проверок, обязательная привязка риска
  к строке diff, единый формат ошибок и различие ожидания модели/UI.
- После рекомендации использовать формулировку «Возможные риски» пользователь
  ответил «Тогда одобряю». Согласованные версии сохранены до реализации.
- Истинность вывода модели оставлена на проверку человека: совпадение цитаты
  подтверждает только присутствие строки в diff.

## Личная оценка студентки

При согласовании мне помог общий контракт: он позволил понять, какие данные
передаёт логика и что должен показывать интерфейс. Таблица расхождений упростила
принятие решений, потому что в ней были видны позиции обеих команд и предложенный
вариант согласования.

Самым важным для меня стало требование сопровождать каждый риск цитатой из diff
и номером строки. Это позволяет проверить, к какому изменению относится замечание,
и самостоятельно оценить его обоснованность.

Главный вывод — спецификация полезна тогда, когда по ней можно проверить
конкретное поведение приложения. Требования к результату и обработке ошибок
должны быть достаточно определёнными, чтобы их можно было проверить тестами.

В дальнейшем я хотела бы подключить настоящую модель и оценить полезность её
замечаний на разных PR. Также было бы удобно загружать diff из файла или получать
его по ссылке на PR, чтобы не копировать изменения вручную.
