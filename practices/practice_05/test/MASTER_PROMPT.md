# Мастер-промт: бэкенд кофейни (OpenSpec practice)

## Роль и жёсткое ограничение
Ты — AI-агент, работающий по методологии Spec-Driven Development (SDD) с использованием OpenSpec и OpenCode. Твоя задача — реализовать бэкенд кофейни в папке `practices/practice_05/test/`. Все файлы, команды и изменения должны находиться строго внутри `practices/practice_05/test/`. Не читай и не изменяй файлы за пределами этой папки. Если для выполнения задачи объективно требуется внешний файл, сначала запроси разрешение.

## Обязательный процесс OpenSpec
1. В папке `practices/practice_05/test/` выполни `openspec init` и выбери OpenCode в качестве инструмента (если инициализация уже выполнена — пропусти шаг).
2. Для каждой фичи создавай отдельный change в `.openspec/changes/<feature-name>/`:
   - крупная/сложная фича → `/opsx-new <feature-name>` (последовательное создание proposal, design, specs, tasks);
   - мелкая/очевидная → `/opsx-ff <feature-name>` (все артефакты за один проход).
3. В документации каждого change обязательно отражай три аспекта:
   - Почему (Why) — проблема/возможность, бизнес-ценность;
   - Как (How) — техническое решение, архитектура, эндпоинты, модели данных;
   - Что следует (What follows) — последствия, зависимости, риски, следующие шаги.
4. После реализации и проверки фичи — архивируй change: `/opsx-archive <feature-name>`.

## Функциональные требования (основные фичи)
- Управление меню кофе: добавление новых видов кофе (название, состав, цена в вымышленной валюте, размеры).
- Новости: быстрая загрузка и отдача новостей (JSON-файл или in-memory кэш; без внешних сервисов, чтобы работало локально).
- Оплата: приём оплаты в вымышленной валюте (назови её, например, `CoffeeCoin`); эндпоинт создания заказа и «оплаты».
- Скидки: генерация выгодных скидок (счастливые часы, скидка на основе истории заказов или случайная скидка дня).
- Время работы: эндпоинт, возвращающий статус магазина (открыт/закрыт) на основе текущего времени и расписания.
- Состав и стоимость: эндпоинты для получения деталей кофе (состав, цена, калории и т.п.).

## Дополнительные фичи (минимум 2 на твой выбор)
Предложи и реализуй не менее двух фич, которые дополняют продукт. Примеры: программа лояльности (баллы за заказы), система отзывов, рекомендации на основе истории, уведомления о готовности заказа, «карта постоянного клиента». Для каждой — полный цикл OpenSpec и документация по схеме «Почему / Как / Что следует».

## Контекст продукта
Создай в корне `practices/practice_05/test/` файл `PRODUCT_CONTEXT.md`, который содержит:
- видение продукта и целевую аудиторию;
- глоссарий (вымышленная валюта, роли, термины);
- архитектуру высокого уровня (стек, компоненты);
- список всех фич (реализованных и запланированных) со ссылками на соответствующие change-артефакты;
- правила и соглашения проекта.

Обновляй `PRODUCT_CONTEXT.md` после каждой значимой итерации.

## Технические требования
- Стек: Python + FastAPI (если не указано иное — обоснуй выбор в документации). Альтернатива: Node.js + Express.
- Хранение данных: in-memory (словари/списки) или SQLite — без внешней БД. Обоснуй выбор.
- Все эндпоинты — RESTful, с автоматической документацией OpenAPI/Swagger (FastAPI даёт её из коробки).
- Код чистый, с комментариями там, где это необходимо.
- Базовые тесты (pytest) для ключевых эндпоинтов.

## Формат документации
- Все файлы документации — Markdown.
- В `.openspec/` используй стандартную структуру OpenSpec.
- В артефактах change-а (`proposal.md`, `design.md`, `specs.md`, `tasks.md`) следуй шаблонам OpenSpec, но добавляй разделы «Почему / Как / Что следует» (или Why / How / What follows), если шаблон их не включает.
- `PRODUCT_CONTEXT.md` — единая точка входа для понимания продукта.

## Порядок работы
1. Инициализируй OpenSpec (если ещё не инициализирован).
2. Создай `PRODUCT_CONTEXT.md` с начальным видением.
3. Для каждой основной фичи (6 штук) и дополнительных (2+) выполни полный цикл OpenSpec.
4. После завершения всех фич — финальная проверка, обновление `PRODUCT_CONTEXT.md`.

## Важно
- Не выходи за пределы `practices/practice_05/test/`.
- Если какая-то команда OpenSpec недоступна, создай файлы в `.openspec/changes/<feature-name>/` вручную по шаблону OpenSpec.
- Стремись к тому, чтобы проект можно было запустить и протестировать локально. Для создания PRODUCT_CONTEXT руководствуйся парадигмой DDD.
