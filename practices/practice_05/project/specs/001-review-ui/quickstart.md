# Quickstart validation — UI

Ниже сохранён порядок проверки; фактический результат выполнения добавлен в конце. Потребуются Python-окружение backend, поддерживаемый браузер и Playwright-окружение координатора. Файлы static/index.html, static/app.js, static/styles.css должны быть реализованы, FastAPI должен отдавать их с тем же origin, что POST /api/reviews.

## Запуск

1. Из корня project выполнить `make run`: режим по умолчанию demo; UI отдельной установки и сборки не требует. Эквивалентная команда: `REVIEW_MODE=demo ../../../.venv/bin/python -m uvicorn app.api:app --host 127.0.0.1 --port 8000 --no-access-log`.
2. Открыть http://127.0.0.1:8000/ и убедиться, что GET /static/app.js и /static/styles.css успешны.
3. Вставить содержимое ../inputs/TRAINING_PR.diff в «Diff одного PR» и нажать «Проверить diff».
4. Проверить loading с заблокированными контролами, затем «ДЕМО», «Краткое описание», «Возможные риски» и «Что проверить». У каждого риска есть путь, сторона/номер строки, буквальная цитата и описание; проверки не исполняются.

После реализации `make test` запускает unittest логики/API; `make e2e` запускает `python -m unittest tests.test_e2e -v` из проектного Python-окружения, самостоятельно поднимает временный сервер и закрывает его. `make check` выполняет обе группы. Файл tests/test_e2e.py принадлежит координатору; UI не создаёт второй набор e2e. Эти команды — запланированный интерфейс интеграции, не утверждение уже выполненного запуска.

## Сценарии приёмки

- US1: успешный учебный diff, 0 и 3 риска; demo маркирован. При mode live показан реальный анализ; это не повод утверждать реальный вызов без доступного провайдера.
- US1/US2: управляемые ответы с пустым checks, 4 рисками, пустым/лишним полем риска, недопустимым mode, неверным line или превышенной длиной отклоняются целиком.
- US2: пустой ввод и 20001 code points отклоняются без запроса; 20000 проходят клиентскую границу. Проверить emoji, поскольку UTF-16 length отличается; переданный diff совпадает с textarea.value.
- US2: controlled MODEL_TIMEOUT/MODEL_UNAVAILABLE и отсутствие ответа дают error, сохранённый ввод и ручной повтор. При 15 секундах UI завершает loading; задержанный ответ первой попытки не заменяет исход второй.
- US3: клавиатурный обход, Enter/Space на кнопках, видимый фокус, объявление статуса; очистка возвращает фокус полю. При успехе/ошибке фокус не прыгает сам.
- US3: изменение текста скрывает прежний результат; очистка удаляет и ввод, и ошибки; загрузка не допускает изменения/очистки.
- Общие: literal HTML в тексте не выполняется; 360/1280 CSS px и 200% читаемы; нет истории, URL с diff, localStorage или журналов содержимого.

При автоматизации использовать роли и имена из [contracts/ui-interface.md](contracts/ui-interface.md); лимиты и модели описаны в [data-model.md](data-model.md). Проверка реального screen reader выполняется вручную и не подменяется DOM-assertion.

- Ширина 360 CSS px и reflow 640 CSS px (эквивалент ширины 1280 при 200%) проверены без горизонтальной прокрутки. Это проверка reflow, а не реальное переключение browser zoom на 200%.
