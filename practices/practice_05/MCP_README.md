# MCP: сравнение сохранённых цен

В practice_05 перенесён сервер `flight-history` из практики 4. Tool `compare_prices` читает SQLite в режиме `mode=ro` и использует общий с веб-приложением расчёт из `backend/app/price_math.py`. Запросов к Ignav он не выполняет.

## Запуск

Сначала установите зависимости по [инструкции проекта](PROJECT_README.md). Запускайте OpenCode из `practices/practice_05`: `opencode.json` подключает сервер через `sh ./scripts/start_mcp.sh`. После изменения конфигурации перезапустите клиент. В Codex эта конфигурация OpenCode автоматически MCP не подключает.

По умолчанию сервер читает `backend/price_history.sqlite3` этой копии проекта. Серверная переменная `FLIGHT_HISTORY_DB` позволяет выбрать отдельную базу. Tool не принимает произвольные пути от агента. Для реальных данных сначала выполните поиск в приложении.

## Аргументы и результат

- `current_search_id`: положительный ID текущего поиска; по умолчанию берётся последняя запись.
- `previous_search_id`: положительный ID предыдущего поиска; по умолчанию берётся ближайшая более ранняя запись с ценой и теми же параметрами.

Ответ содержит маршрут, даты, ID и время записей, цены, валюту, разницу и процент. Отрицательная разница означает снижение. При прежней цене 0 процент равен `null`.

Первый поиск возвращает `no_previous_price`. Пустая текущая цена, несовместимые параметры, разные валюты, обратный порядок записей и неизвестные ID дают MCP-ошибку. Отрицательные ID отклоняются входной схемой.

## Офлайн-демо

Из `practices/practice_05/backend`:

```sh
.venv/bin/python -m app.mcp_demo --report ../verification/mcp-calls.json
```

Демо создаёт временную SQLite с синтетическими данными, запускает сервер и делает настоящие MCP-вызовы через SDK. Оно проверяет успешный сценарий и ошибочные входы, а также неизменность базы. Рабочая история не затрагивается. Демо входит в backend-тесты.

Отчёт создаётся при запуске. Сохранённые подтверждения практики 4 остаются в её каталоге и не являются результатами проверки этой копии.
