# events Specification

## Purpose
Управление событиями карты: изменение их данных и привязки к планете без потери связанных изображений.

## Requirements

### Requirement: Edit event metadata
Система SHALL позволять менять `name`, `description` и `link` существующего события через `PUT /events/:id` в JSON-теле. Поля, которых нет в запросе, MUST сохраняться.

#### Scenario: Частичное изменение
- **WHEN** клиент отправляет `PUT /events/:id` только с `name`
- **THEN** ответ 200 с новым `name` и прежними `description`, `link`, `place`
- **AND** `GET /events/:id` возвращает те же данные

#### Scenario: Невалидное значение поля
- **WHEN** клиент отправляет пустой или `null` `name`, `null` или не ObjectId в `place`
- **THEN** ответ 400, событие не меняется

### Requirement: Move event between planets
После успешного изменения `place` событие MUST числиться только в `events` своей текущей планеты.

#### Scenario: Перенос на другую планету
- **WHEN** клиент отправляет `PUT /events/:id` с `place` другой существующей планеты
- **THEN** событие убирается из `events` всех остальных планет и добавляется в `events` новой
- **AND** проверка целостности не находит висячих ссылок

### Requirement: Keep event images
Система SHALL NOT менять `shots` события при редактировании, в том числе если `shots` прислан в теле запроса.

#### Scenario: Снимки сохраняются
- **WHEN** редактируется событие с загруженными снимками
- **THEN** его `shots` не меняются, файлы остаются в хранилище

### Requirement: Unknown references
Система SHALL отвечать 404, если редактируемое событие или целевая планета не существуют.

#### Scenario: Неизвестное событие
- **WHEN** клиент отправляет `PUT /events/:id` для отсутствующего события
- **THEN** ответ 404

#### Scenario: Неизвестная планета
- **WHEN** клиент передаёт `place` отсутствующей планеты
- **THEN** ответ 404, событие остаётся на прежней планете
