# Spec Delta

## Purpose

Ревью диффа локальной моделью: валидация входа, делегирование текста ревью
модели, классификация ошибок зависимости и подсчёт базовой статистики
диффа (число файлов, добавленных и удалённых строк).

## ADDED Requirements

### Requirement: Успешное ревью диффа
Когда дифф проходит валидацию входа и клиент модели успешно возвращает
текст, система SHALL вернуть `{"status": "ok", "review": "<текст>"}`.

#### Scenario: Модель возвращает текст ревью
- **WHEN** дифф непустой, не превышает `MAX_DIFF_BYTES`, и `client.complete`
  возвращает текст без исключения
- **THEN** `review_diff` возвращает `{"status": "ok", "review": "<текст из
  client.complete>"}`

### Requirement: Отказ валидации входа без вызова модели
Пустой или состоящий только из пробелов дифф, а также дифф длиннее
`MAX_DIFF_BYTES` байт SHALL быть отклонён до вызова клиента модели.

#### Scenario: Пустой или пробельный дифф
- **WHEN** `diff` пуст или состоит только из пробельных символов
- **THEN** `review_diff` возвращает `{"status": "rejected", "code":
  "empty_diff", "message": "<...>"}`, не вызывая `client.complete`

#### Scenario: Дифф превышает лимит байт
- **WHEN** `len(diff.encode("utf-8")) > MAX_DIFF_BYTES`
- **THEN** `review_diff` возвращает `{"status": "rejected", "code":
  "diff_too_large", "message": "<...>"}`, не вызывая `client.complete`

### Requirement: Ошибка зависимости модели
Если валидный дифф передан клиенту модели, но клиент не вернул ответ
(истекло ожидание, соединение не установлено, модель ответила HTTP-ошибкой
или ответ не содержит ожидаемых полей), система SHALL вернуть
`{"status": "error", "code": "<model_*>", "message": "<...>"}` без
проброса исключения наружу.

#### Scenario: Ожидание ответа модели истекло
- **WHEN** `client.complete` не отвечает дольше `REVIEW_TIMEOUT_SECONDS`
- **THEN** `review_diff` возвращает `{"status": "error", "code":
  "model_timeout", "message": "<...>"}`

#### Scenario: Соединение с моделью не установлено
- **WHEN** `client.complete` не может установить соединение с моделью
- **THEN** `review_diff` возвращает `{"status": "error", "code":
  "model_unavailable", "message": "<...>"}`

#### Scenario: Модель ответила HTTP-ошибкой
- **WHEN** `client.complete` выбрасывает исключение, соответствующее
  HTTP-ошибке ответа модели
- **THEN** `review_diff` возвращает `{"status": "error", "code":
  "model_http_error", "message": "<...>"}`

#### Scenario: Ответ модели не содержит ожидаемых полей
- **WHEN** `client.complete` возвращает или выбрасывает исключение,
  указывающее на отсутствие ожидаемых полей в ответе модели
- **THEN** `review_diff` возвращает `{"status": "error", "code":
  "model_bad_response", "message": "<...>"}`

### Requirement: Правило подсчёта статистики
Подсчёт `stats` SHALL следовать правилу: строка `--- X`, непосредственно
после которой идёт строка `+++ Y`, образует заголовок файла и учитывается
только в `files`. Любая другая строка, начинающаяся с `+`, SHALL
увеличивать `added`. Любая другая строка, начинающаяся с `-`, SHALL
увеличивать `removed`.

#### Scenario: Пара "--- X"/"+++ Y" — заголовок файла
- **WHEN** дифф содержит строку `--- a/x.py`, сразу за которой следует
  строка `+++ b/x.py`
- **THEN** эта пара увеличивает `files` на 1 и не учитывается в
  `added`/`removed`

#### Scenario: "--- X" без следующей "+++ Y" — удалённая строка
- **WHEN** дифф содержит строку `--- x`, представляющую удалённую исходную
  строку `-- x`, после которой следующая строка не начинается с `+++ `
- **THEN** эта строка учитывается в `removed`, а `files` не увеличивается

#### Scenario: Одиночная "+++ Y" без предшествующей "--- X" — добавленная строка
- **WHEN** дифф содержит строку `+++ y`, не следующую непосредственно за
  строкой `--- X`
- **THEN** эта строка учитывается в `added`, а `files` не увеличивается

### Requirement: Статистика диффа в успешном ответе
Когда `review_diff` возвращает `{"status": "ok", ...}`, ответ SHALL
дополнительно содержать поле `"stats": {"files": N, "added": N, "removed":
N}` — результат детерминированного подсчёта по тексту диффа (см. "Правило
подсчёта статистики"), без участия модели.

#### Scenario: Дифф с заголовками файлов
- **WHEN** дифф содержит строку `--- a/x.py`, сразу за которой следует
  строка `+++ b/x.py`, и далее строки `+print(1)` и `-print(2)`
- **THEN** `stats` равен `{"files": 1, "added": 1, "removed": 1}`

#### Scenario: Дифф без распознаваемых конструкций
- **WHEN** дифф не содержит ни одной пары `--- X`/`+++ Y`, ни строк,
  начинающихся с `+` или `-`
- **THEN** `stats` равен `{"files": 0, "added": 0, "removed": 0}`, без
  кода ошибки

### Requirement: Статистика диффа в ответе об ошибке зависимости
Когда `review_diff` возвращает `{"status": "error", "code": "<model_*>",
...}` (дифф уже прошёл валидацию входа), ответ SHALL дополнительно
содержать поле `"stats"`, посчитанное по правилу из "Правило подсчёта
статистики".

#### Scenario: Модель не ответила, но дифф валиден
- **WHEN** `diff` проходит валидацию входа, но `client.complete`
  выбрасывает исключение, классифицируемое как ошибка зависимости
  (`model_timeout`, `model_unavailable`, `model_http_error` или
  `model_bad_response`)
- **THEN** ответ содержит `"status": "error"`, соответствующий `code` и
  поле `"stats"`, посчитанное по тексту переданного диффа

### Requirement: Отказ валидации входа не содержит статистики
Ответы со `"status": "rejected"` (коды `empty_diff`, `diff_too_large`)
SHALL оставаться без изменений: поле `"stats"` в них не добавляется.

#### Scenario: Пустой дифф отклонён без поля stats
- **WHEN** `diff` пуст или состоит только из пробелов
- **THEN** ответ не содержит ключ `"stats"`

#### Scenario: Превышение лимита байт отклонено без поля stats
- **WHEN** `len(diff.encode("utf-8")) > MAX_DIFF_BYTES`
- **THEN** ответ не содержит ключ `"stats"`
