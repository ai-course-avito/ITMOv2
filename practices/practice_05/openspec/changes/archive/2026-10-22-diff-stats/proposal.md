# Proposal

## Why

Ответ `review_diff` сейчас содержит только текст ревью от модели. Вызывающей
стороне не видно объём изменений (сколько файлов, сколько строк добавлено и
удалено) без собственного парсинга диффа. Эти числа легко и надёжно считаются
в коде, без обращения к модели, и дают ценный сигнал наравне с текстовым
ревью.

## What Changes

- В `app/review.py` добавляется детерминированный (без модели) подсчёт
  статистики диффа: число файлов, добавленных строк, удалённых строк.
- Поле `"stats": {"files": N, "added": N, "removed": N}` добавляется в ответ
  `review_diff` при `status == "ok"` и при `status == "error"`
  (`model_timeout`, `model_unavailable`, `model_http_error`,
  `model_bad_response`) — в этих случаях дифф уже прошёл валидацию фичи A и
  ограничен `MAX_DIFF_BYTES`, поэтому подсчёт дёшев и осмыслен.
- Поле **не** добавляется при `status == "rejected"` (`empty_diff`,
  `diff_too_large`): контракт отказов фичи A не меняется.
- Правило распознавания заголовка файла: строка `--- X`, за которой **сразу**
  следует строка `+++ Y`, — заголовок файла (увеличивает `files`, не
  учитывается в `added`/`removed`). В диффе строка `--- x`, представляющая
  удалённую исходную строку `-- x`, после которой следующая строка не
  начинается с `+++ `, — это удалённая строка контента и учитывается в
  `removed`.
- Строки, начинающиеся с `+`, учитываются в `added`, **кроме** строки
  `+++ Y`, стоящей непосредственно после распознанного заголовка `--- X`;
  одиночная `+++ y` без предшествующей `--- X` — это добавленная строка и
  учитывается в `added`. Строки, начинающиеся с `-`, учитываются в
  `removed`, кроме строки `--- X`, образующей пару с последующей `+++ Y`.
- Диффы без распознаваемых конструкций дают `{"files": 0, "added": 0,
  "removed": 0}`, без новой ошибки.
- `docs/requirements.md` обновляется: добавляется описание поля `stats` для
  успешного ответа и для ответов фичи B.

## Capabilities

### New Capabilities
- `review-diff`: ревью диффа локальной моделью, включая успешный путь,
  отказы валидации входа, ошибки зависимости и (этим изменением) подсчёт
  статистики диффа.

### Modified Capabilities
(нет — `review-diff` фиксируется впервые этим изменением как новая
capability, описывающая всё поведение `review_diff`, включая уже
реализованные фичи A и B.)

## Impact

- Код: `app/review.py` — новая приватная функция подсчёта статистики и её
  подключение к веткам `ok`/`error`.
- Тесты: `tests/test_review.py` — новые тесты через публичный `review_diff`
  (без обращения к внутренней функции подсчёта), по стилю
  `docs/style-guide.md`.
- Документация контракта: `docs/requirements.md` — описание нового поля
  `stats`. Правка этого файла в рамках данного change разрешена
  пользователем отдельным поручением (это не нарушает общий запрет на
  изменение контракта без отдельного поручения из `AGENTS.md`).
- Не затрагивается: `app/subscribe.py`, `app/ollama_client.py`, коды и
  тексты ответов `rejected`, `scripts/check.sh`, `practices/practice_03/`.
- Вне scope (явно не покрывается): статистика по бинарным файлам
  (`Binary files ... differ`) и по rename-диффам без изменения содержимого
  — такие файлы не увеличивают `files` и их строки не считаются в
  `added`/`removed`.
