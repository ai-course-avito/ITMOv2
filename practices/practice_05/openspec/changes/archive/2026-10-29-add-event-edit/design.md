# Design

## Context

Связь событие-планета хранится с двух сторон: `event.place` и массив `planet.events`. `create` откатывает запись события при ошибке связи, `deleteOne` чистит событие из всех планет через `updateMany`. Транзакций в проекте нет. Глобальный `ValidationPipe({ whitelist: true })` есть только в `main.ts`, интеграционные тесты поднимают приложение без него и подменяют `@nestjs/mapped-types`.

## Goals / Non-Goals

**Goals:**
- изменить событие одним JSON-запросом, не нарушая двустороннюю связь с планетой

**Non-Goals:**
- транзакции MongoDB: для single-node Mongo они требуют replica set
- multipart-тело: снимки не редактируются, поэтому PUT принимает только JSON

## Decisions

- `UpdateEventDto` описан явно, а не через `PartialType`: `@IsOptional` из `PartialType` пропускает `null`, и `{ name: null }` доходил бы до Mongoose с ответом 500. Поля проверяются через `@ValidateIf(value !== undefined)`, поэтому отсутствующее поле пропускается, а `null` получает 400. `shots` в DTO нет, whitelist его отбрасывает.
- В документ переносятся только поля со значением, отличным от `undefined`: при `target: ES2023` экземпляр DTO после `transform: true` содержит все объявленные поля как собственные ключи, и прямой `Object.assign` стирал бы неотправленные поля.
- DTO проверяется отдельным тестом через настоящий `ValidationPipe`: интеграционный стенд без глобального pipe не может проверить 400. - Планета проверяется до записи события, при неизвестной планете 404 и событие не меняется.
- После сохранения событие убирается из `events` всех планет, кроме текущей (`updateMany` с `$pull`, как в `deleteOne`), и добавляется в текущую через `$addToSet`. Так чинится и рассинхрон, который был до запроса, а повтор запроса безопасен.

## Risks / Trade-offs

- [Ошибка `$pull`/`$addToSet` после `save()` оставит рассинхрон, в отличие от `create` откат не делается] → повтор того же PUT восстанавливает связь, `npm run db:check` находит остаток.
- [Два одновременных PUT с разными `place` могут оставить событие в двух планетах] → принимается для админ-панели с одним редактором, повторный PUT или `db:check` исправляет.
