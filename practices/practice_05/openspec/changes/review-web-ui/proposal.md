# Proposal

## Why

`review_diff` сейчас доступен только из Python (вызов функции или тесты).
У сервиса нет интерфейса, через который человек мог бы вставить дифф и
увидеть результат без написания кода. Нужен тонкий веб-слой поверх
существующей функции — без изменения её контракта.

## What Changes

- Новый модуль веб-сервера на `http.server` из стандартной библиотеки:
  отдаёт одну HTML-страницу и обрабатывает `POST /api/review`.
- HTML-страница: текстовое поле для диффа, кнопка «Ревью», отображение
  результата (`review` + `stats`), состояние загрузки, отображение отказа
  (`status == "rejected"`) и ошибки модели (`status == "error"`) с их
  `code`/`message`.
- `POST /api/review` принимает JSON `{"diff": "<текст>"}`, вызывает
  `review_diff(diff)` без изменений в его сигнатуре и поведении, возвращает
  результат `review_diff` как JSON с соответствующим HTTP-статусом.
- Поведение `review_diff` и `subscribe` не меняется: веб-слой — это новый
  вызывающий код сверху существующих функций, а не изменение их контракта.

## Capabilities

### New Capabilities
- `review-web-ui`: HTTP-доступ к ревью диффа — HTML-страница и
  `POST /api/review` поверх `review_diff`, включая отображение успеха,
  отказа и ошибки модели в браузере.

### Modified Capabilities
(нет — `review-diff` не меняется: эта фича добавляет нового вызывающего,
а не новые требования к `review_diff`)

## Acceptance Criteria

1. `GET /` отдаёт HTML-страницу с полем для диффа и кнопкой запуска
   ревью.
2. `POST /api/review` с валидным диффом отдаёт результат `review_diff`
   (`status == "ok"`, с `review` и `stats`) как JSON, и страница
   отображает его.
3. Отказ (`status == "rejected"`) и ошибка модели (`status == "error"`)
   проходят через API без изменений и отображаются на странице отдельно
   от успеха, с их `code`/`message`.
4. Пока запрос выполняется, страница показывает состояние загрузки.
5. Невалидное тело запроса (не JSON, нет строкового `diff`) отклоняется
   HTTP-слоем кодом 400 до вызова `review_diff`; неизвестный маршрут —
   кодом 404.

### Ошибки

- HTTP 400 — некорректный запрос к `/api/review` (не JSON, нет/неверный
  `diff`), `review_diff` не вызывается.
- HTTP 404 — путь или метод, кроме `GET /` и `POST /api/review`.
- `status: "rejected"`/`"error"` в теле JSON с HTTP 200 — предусмотренные
  исходы `review_diff`, не ошибки HTTP-слоя (см. design.md - Decisions).

### Не входит в изменение

- Аутентификация, сессии, многопользовательский режим.
- Хранение истории ревью.
- Изменение `review_diff`, `subscribe`, `app/ollama_client.py` или
  `docs/requirements.md`.
- Реализация в рамках текущей работы: планирование останавливается на
  готовых артефактах, apply не запускается.

## Impact

- Новый код: HTTP-сервер и HTML-страница (конкретные модули и их
  размещение фиксирует `design.md`).
- Затронутые существующие файлы: не предполагается изменение
  `app/review.py`, `app/subscribe.py`, `app/ollama_client.py`,
  `docs/requirements.md`.
- Зависимости: только стандартная библиотека Python (`http.server` и
  смежные модули `http`/`json`/`urllib`).
- Эта фича не будет реализована в рамках текущей работы с OpenSpec:
  планирование останавливается после подготовки артефактов, apply не
  запускается.
