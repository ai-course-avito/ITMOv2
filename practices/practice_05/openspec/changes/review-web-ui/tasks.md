# Tasks

## 1. HTTP-сервер и маршрутизация

- [ ] 1.1 Создать новый модуль веб-сервера (например, `app/web.py`) с
      обработчиком на `http.server.BaseHTTPRequestHandler` и запуском
      через `http.server.ThreadingHTTPServer`; проверить через
      `python3 -m compileall -q app`.
- [ ] 1.2 Реализовать маршрутизацию по `self.command`/`self.path`:
      `GET /`, `POST /api/review`, всё остальное — 404; проверить тестом
      на неизвестный путь (например, `GET /unknown` возвращает 404, и
      `review_diff` не вызван).

## 2. Страница ревью

- [ ] 2.1 Реализовать обработчик `GET /`, отдающий встроенную HTML/JS
      страницу с текстовым полем для диффа и кнопкой запуска ревью;
      проверить тестом, что `GET /` возвращает HTTP 200 и тело содержит
      маркеры поля ввода и кнопки.
- [ ] 2.2 Добавить в страницу JS-логику: `fetch` на `POST /api/review`,
      отображение состояния загрузки на время запроса, отображение
      результата (`review`+`stats`), отдельное отображение отказа
      (`rejected`) и ошибки модели (`error`) с их `code`/`message`;
      проверить вручную в браузере (ручная проверка, так как JS не
      покрывается `unittest`) и зафиксировать это как ручной шаг в
      отчёте по задаче.

## 3. API ревью

- [ ] 3.1 Реализовать обработчик `POST /api/review`: прочитать тело
      запроса, распарсить JSON, проверить, что результат — `dict` с
      ключом `diff` типа `str`; при нарушении вернуть HTTP 400 без
      вызова `review_diff`; проверить тестами на невалидный JSON и на
      отсутствующий/нестроковый `diff`.
- [ ] 3.2 Вызвать `review_diff(diff)` с полученной строкой через
      инъекцию тестового клиента в тестах (сеть в тестах не
      используется) и вернуть результат как JSON с HTTP 200 без
      изменения полей; проверить тестом на `status == "ok"` (точное
      совпадение тела ответа с результатом `review_diff`).
- [ ] 3.3 Проверить тестом, что `status == "rejected"` от `review_diff`
      возвращается как JSON с HTTP 200 без изменений (например, пустой
      дифф → `code == "empty_diff"`).
- [ ] 3.4 Проверить тестом, что `status == "error"` от `review_diff`
      возвращается как JSON с HTTP 200 без изменений (клиент модели,
      имитирующий ошибку зависимости, подставляется в обработчик так же,
      как в `tests/test_review.py`).
