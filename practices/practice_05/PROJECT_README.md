# Билетик: проект для практики 5

Самостоятельная копия приложения из [практики 4](../practice_04/PROJECT_README.md). Исходники, тесты и инструменты перенесены в `practice_05`; дальнейшие изменения выполняются здесь. Задание занятия описано в [README.md](README.md), правила работы агента — в [AGENTS.md](AGENTS.md), история изменений — в [CHANGELOG.md](CHANGELOG.md).

## Что уже работает

- Поиск билетов в одну сторону и туда-обратно на конкретные даты через Ignav Flight API.
- Форма React с выбором аэропорта по городу, датами, максимальной ценой, выбором рынка и фильтром прямых рейсов.
- FastAPI проверяет ввод и обращается к Ignav с серверным ключом. Браузер вызывает только FastAPI.
- Нормализованные карточки содержат цену, валюту, перевозчика, сегменты и пересадки. Сервер сортирует их по возрастанию цены.
- Над непустым списком билетов можно выбрать «Сначала дешёвые» или «Сначала дорогие». Переключение сортирует уже полученные карточки локально, а новый успешный поиск возвращает порядок от дешёвых к дорогим.
- Одинаковые успешные запросы кешируются на три минуты. Поиск запускается только по кнопке.
- SQLite хранит параметры и минимальную цену успешных поисков, включая пустые ответы без цены. Интерфейс сравнивает цену с предыдущим сопоставимым поиском.
- Локальный MCP `flight-history` читает историю и сравнивает цены без обращения к Ignav.

Сравнение использует одинаковые маршрут, даты, тип поездки, рынок и фильтры. Состояния отсутствующей текущей или прошлой цены и несовпадающих валют показываются отдельно. Разница и процент рассчитываются общей функцией в `backend/app/price_math.py`.

Рынок (`RU`, `US`, `GB`, `TR`, `AE`) влияет на валюту; интерфейс показывает валюту из ответа без конвертации. Цены ориентировочные. Поиска за месяц, бронирования, аккаунтов и синхронизации истории нет.

## Выбор аэропорта по городу

В полях «Откуда» и «Куда» начните вводить город и выберите аэропорт из списка. Справочник содержит 45 европейских столиц, а также Санкт-Петербург, Казань и Сочи: всего 48 городов и 58 аэропортов. Столицы микрогосударств без собственного аэропорта в список не включены. Полный перечень и ограничения — в [документе фичи](docs/features/city-airport-selection.md). Свободный ввод IATA-кода в форме не подтверждает маршрут.

Ввод и выбор не запускают поиск. После изменения выбранной подписи аэропорт нужно подтвердить снова. Поиск по кнопке отправляет коды двух выбранных аэропортов в существующий API; даты и фильтры работают как прежде.

## Фича для части 1

[Выбор порядка сортировки билетов](docs/features/price-sort.md) реализован во фронтенде и оформлен в OpenSpec change `flight-price-sort`. Переключатель скрыт при пустом ответе; он не вызывает новый поиск и не меняет сохранённую историю, сравнение цен или данные кеша. Интерфейс принят человеком 2026-10-26.

## Локальный запуск

Из корня репозитория подготовьте сервер:

```sh
cd practices/practice_05/backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
cp .env.example .env
```

Укажите свой ключ в `backend/.env` как `IGNAV_API_KEY=...` или задайте серверную переменную окружения. Затем:

```sh
.venv/bin/uvicorn app.main:app --reload
```

В другом терминале из корня репозитория:

```sh
cd practices/practice_05/frontend
npm ci
npm run dev
```

Vite обычно доступен по `http://localhost:5173` и перенаправляет `/api` на FastAPI по `127.0.0.1:8000`. Проверка доступности сервера — `GET /health`. Одновременно запущенные копии практик 4 и 5 используют те же порты: запускайте нужную копию отдельно или настройте другие порты и прокси.

Живой успешный запрос к Ignav может тарифицироваться. Ключ, зависимости, SQLite и кеши не входят в перенос; история этой копии создаётся заново в `backend/price_history.sqlite3`.

## Проверки

После установки зависимостей запустите из `practices/practice_05`:

```sh
backend/.venv/bin/python .agents/skills/verify-flight-features/scripts/run.py --report verification/flight-features.md
```

Runner запускает backend-тесты, тест hook, сборку фронтенда и сценарий поиска с историей на подменённом Ignav и временной SQLite. Настоящий ключ и платный поиск для проверки не нужны. Отчёт появляется после запуска; отчёты практики 4 сюда не переносятся.

Отдельные команды:

```sh
cd backend
.venv/bin/python -m pytest -q
```

```sh
cd frontend
npm run build
```

Сборка проверяет TypeScript и создание production bundle. Для сортировки отдельно проверяйте порядок карточек и отсутствие сетевого запроса при переключении, как описано в документе фичи.

## Инструменты агента

В `.agents/skills/` перенесены `fastapi-python`, `pydantic`, `vercel-react-best-practices` и `verify-flight-features`. `opencode.json` подключает Context7 и локальный MCP; подробности — в [MCP_README.md](MCP_README.md).

Плагин `.opencode/plugins/verify-after-edit.js` при работе из OpenCode запускает runner после изменения исходников через инструменты редактирования и возвращает агенту `PASS` или `FAIL`. Отчёт — `verification/after-edit.md`. Для его загрузки запускайте OpenCode из `practices/practice_05`. Правки через shell и внешний редактор hook не перехватывает; в Codex проверки запускаются явно.

OpenSpec уже инициализирован в корне репозитория. Выполняйте его команды из корня репозитория или из `practice_05`: используется общий корневой `openspec/`. В предложении явно указывайте целевой проект `practices/practice_05`, чтобы изменения относились к этой копии.
