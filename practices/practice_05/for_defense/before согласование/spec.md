## User Scenarios & Testing *(mandatory)*

### User Story 1 - Выбрать аэропорты и найти билеты (Priority: P1)

Пользователь вводит города, выбирает конкретный аэропорт отправления и назначения и запускает поиск с прежними датами и фильтрами.

**Why this priority**: Основной сценарий устраняет необходимость знать IATA-коды.

**Independent Test**: Выбрать Шереметьево и Пулково, задать дату и нажать «Найти билеты»; проверить один поиск по выбранной паре.

**Acceptance Scenarios**:

1. **Given** пустое поле маршрута, **When** введено «Москва», **Then** показаны отдельные варианты «Москва — Шереметьево», «Москва — Домодедово», «Москва — Внуково».
2. **Given** город с одним аэропортом, **When** введено его название, **Then** показан один вариант с городом и аэропортом.
3. **Given** разные выбранные аэропорты и корректные параметры, **When** нажата кнопка поиска, **Then** выполняется ровно один поиск по выбранной паре с прежними датами и фильтрами.
4. **Given** поддерживаемый город, **When** он введён в другом регистре или с пробелами по краям, **Then** доступны те же варианты.

---

### User Story 2 - Исправить маршрут без скрытого выбора (Priority: P2)

После изменения текста пользователь явно подтверждает новый аэропорт. Видимый текст не может скрывать прежний код маршрута.

**Why this priority**: Иначе запрос может уйти по аэропорту, который пользователь больше не видит.

**Independent Test**: Выбрать аэропорт, изменить текст и нажать поиск; проверить отсутствие запроса и сообщение о выборе.

**Acceptance Scenarios**:

1. **Given** выбран аэропорт, **When** текст поля изменён, **Then** подтверждение этого поля сброшено, а второе поле не изменено.
2. **Given** текст введён без выбора варианта, **When** нажата кнопка поиска, **Then** запрос не отправлен и показана просьба выбрать аэропорт из списка.
3. **Given** неизвестный город или свободный IATA-код, **When** пользователь пытается искать, **Then** запрос не отправлен и объяснено ограничение справочника.
4. **Given** один аэропорт выбран в обоих полях, **When** нажата кнопка поиска, **Then** показана существующая ошибка совпадения и запрос не отправлен.

---

### User Story 3 - Выбрать без мыши и без преждевременного поиска (Priority: P3)

Пользователь выбирает аэропорты клавиатурой; ввод и выбор не запускают поиск и не меняют прежние результаты.

**Why this priority**: Доступность и отсутствие тарифицируемого поиска до явного действия.

**Independent Test**: Выбрать оба аэропорта только клавиатурой и проверить отсутствие запроса до нажатия кнопки.

**Acceptance Scenarios**:

1. **Given** открытый список, **When** пользователь перемещается клавиатурой и подтверждает вариант, **Then** поле показывает выбранный город и аэропорт.
2. **Given** виден результат предыдущего успешного поиска, **When** пользователь вводит город или выбирает аэропорт, **Then** результат и история не меняются.

### Edge Cases

- Пустой ввод не означает выбора; список скрыт, поиск требует подтверждения.
- При отсутствии совпадений показано «Аэропорты не найдены»; свободный код не становится выбором.
- Два разных аэропорта одного города допустимы; совпадение определяется аэропортом.
- Переключение типа поездки сохраняет выбранные аэропорты, прежние правила дат продолжают действовать.
- Ошибка поискового сервиса не сбрасывает подтверждённые аэропорты.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Экран поиска MUST показывать два изначально пустых поля «Откуда» и «Куда» для названия города и выбора аэропорта.
- **FR-002**: Каждое поле MUST показывать отдельный вариант для каждого аэропорта подходящего города; вариант и подтверждённый выбор MUST содержать город и аэропорт.
- **FR-003**: Поиск подсказок MUST игнорировать регистр и пробелы по краям ввода.
- **FR-004**: Ввод и выбор MUST работать без поискового запроса и записи истории; предыдущий успешный результат MUST сохраняться до новой отправки формы.
- **FR-005**: Любое изменение текста после выбора MUST сбрасывать подтверждение только данного поля.
- **FR-006**: Поиск MUST требовать два подтверждённых аэропорта; неподтверждённый текст и неизвестный город MUST блокировать запрос с сообщением у поля.
- **FR-007**: При корректном маршруте нажатие кнопки MUST выполнять ровно один поиск по кодам выбранных аэропортов, сохраняя прежние даты, тип поездки и фильтры.
- **FR-008**: Один и тот же аэропорт в обоих полях MUST блокировать поиск; разные аэропорты одного города MUST допускаться.
- **FR-009**: Пользователь MUST иметь возможность просмотреть и выбрать предложения клавиатурой, а также закрыть список без выбора.
- **FR-010**: Отсутствие совпадений MUST иметь отдельное сообщение и не создавать подтверждённый выбор.
- **FR-011**: Загрузка, пустой ответ и ошибка поиска MUST иметь различимые сообщения; ошибка ввода MUST отличаться от ошибки сервиса.
- **FR-012**: Документация функции MUST объяснять ограничение начального справочника.

### Спецификация UI: экран, действия, состояния и ошибки

**Экран**: существующая страница поиска практики 5. В форме поля «Откуда» и «Куда» заменяют ввод IATA на ввод города с выбором аэропорта. Даты, фильтры, кнопка поиска, область сообщений и область результатов остаются на этой странице. Отдельный экран выбора не требуется.

**Действия**: ввод или удаление текста открывает подходящие варианты; выбор мышью или клавиатурой подтверждает конкретный аэропорт; закрытие списка оставляет выбор прежним только если текст не изменился. Кнопка «Найти билеты» проверяет форму и запускает поиск. Переключение сортировки меняет только порядок уже полученных карточек.

**Состояния полей**: пустое; ввод с вариантами; ввод без вариантов; подтверждённый аэропорт; ошибка неподтверждённого поля. Каждое поле меняется независимо. После подтверждения показывается «Город — Аэропорт». При изменении текста подтверждение исчезает. Ошибка неподтверждённого поля указывает выбрать аэропорт из списка.

**Состояния результата**: прежний успешный результат остаётся во время редактирования маршрута; после отправки видны индикатор загрузки, затем карточки или сообщение об отсутствии билетов. Ошибка сервиса выводится в области сообщений, а выбранные аэропорты остаются доступны для повторного поиска.

### Спецификация логики: данные, алгоритм, правила и API

**Данные**: локальный справочник связывает город, название аэропорта и уникальный IATA-код. В каждом поле отдельно хранятся вводимый текст и подтверждённый аэропорт. Маршрут для поиска состоит только из двух подтверждённых аэропортов; результат относится к последнему отправленному маршруту.

**Алгоритм**: нормализовать ввод по регистру и пробелам по краям; найти подходящие города; вывести отдельный вариант для каждого их аэропорта; при выборе сохранить конкретную запись; при изменении текста очистить только выбор этого поля. Точный режим сопоставления фрагмента города предложен в [контракте](contract.md) для согласования.

**Правила**: пустой текст, свободный IATA-код и неизвестный город не подтверждают аэропорт. Поиск блокируется, пока оба аэропорта не выбраны и их коды не различаются. Разные аэропорты одного города допустимы. Подсказки не вызывают поиск и не меняют историю; прежние ограничения дат, цены и фильтров сохраняются.

**API**: используется существующий запрос поиска в одну сторону или туда-обратно. Отправляются только коды выбранных аэропортов вместе с прежними параметрами; новый вызов для подсказок не нужен. Поля, ответы и ошибки запросов зафиксированы в [отдельном общем контракте](contract.md).

### Key Entities *(include if feature involves data)*

- **Аэропорт справочника**: город, название аэропорта, уникальный трёхбуквенный код; один город может иметь несколько аэропортов.
- **Поле маршрута**: видимый текст, подтверждённый аэропорт либо его отсутствие, предложения и ошибка.
- **Маршрут**: подтверждённые аэропорты отправления и назначения; человеку видны названия, поиску передаются коды.
- **Результат**: билеты и сравнение цен последнего выполненного поиска, не редактируемого текста формы.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100% приёмочных сценариев с поддерживаемым городом пользователь выбирает аэропорт без знания IATA-кода.
- **SC-002**: Для Москвы видны три различимых аэропорта; для города с одним аэропортом — ровно один.
- **SC-003**: В 100% проверок ввод и выбор без нажатия кнопки не запускают поиск, не меняют историю и прежний успешный результат.
- **SC-004**: В 100% проверок изменённый после выбора текст и совпадающие аэропорты блокируют поиск с понятным сообщением.
- **SC-005**: Каждая корректная отправка запускает ровно один поиск по выбранной паре с прежними датами и фильтрами.
- **SC-006**: В приёмочном сценарии пользователь выбирает оба аэропорта только клавиатурой не более чем за 1 минуту.

## Assumptions

- Начальный справочник из OpenSpec design: Москва (SVO, DME, VKO), Санкт-Петербург (LED), Казань (KZN), Сочи (AER); названия и коды нужно сверить перед реализацией.
- Целевой интерфейс — существующий экран поиска и результатов практики 5; отдельный экран каталога не нужен.
- Поиск по всем аэропортам города сразу, внешний источник подсказок и фоновый поиск не входят в функцию.
- Сервисный поиск, кеш, история, сравнение цен и сортировка результатов сохраняют прежние правила.
- Подробные решения в [contract.md](contract.md) имеют статус предложения до согласования с заказчиком.
