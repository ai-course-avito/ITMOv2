# Общий контракт выбора аэропорта — проект для согласования

**Статус**: предложен, не согласован. **Целевой проект**: `practices/practice_05`. **Основа**: [авторская спецификация](spec.md), OpenSpec `city-airport-selection` и текущие схемы FastAPI практики 5.

## 1. Данные

| Объект | Поля и ограничения | Источник |
| --- | --- | --- |
| Аэропорт | `city` — отображаемое русское название; `airport` — различимое название; `code` — уникальный IATA-код из трёх заглавных латинских букв | Локальный справочник в клиенте |
| Поле маршрута | `text` — видимый текст; `selected` — аэропорт или `null`; `open` — открыт ли список; `active` — выделенный вариант; `error` — сообщение или `null` | Состояние формы |
| Маршрут | `origin` и `destination` — два подтверждённых аэропорта; для запроса берутся только их `code` | Два поля маршрута |

Начальный справочник: Москва — Шереметьево/SVO, Домодедово/DME, Внуково/VKO; Санкт-Петербург — Пулково/LED; Казань — Казань/KZN; Сочи — Сочи/AER. Состав взят из OpenSpec design; достоверность названий и кодов проверяется перед реализацией.

Начальные `text` пустые, `selected = null`; прежнее значение `MOW` не подставляется, поскольку обозначает город, а нужен аэропорт. После выбора в поле показывается `Город — Аэропорт`. Любое фактическое изменение текста сбрасывает `selected` только этого поля. Повторное подтверждение требуется даже если текст снова стал прежним.

## 2. Алгоритм и правила

1. При непустом вводе убрать пробелы по краям и сравнить название города без учёта регистра. **Предложение для согласования**: показывать города, название которых содержит введённый фрагмент; варианты сохраняют порядок справочника. Пустой ввод скрывает список.
2. Каждый найденный аэропорт выводить отдельным вариантом. Если совпадений нет, выводить «Аэропорты не найдены» и не создавать выбор.
3. Клик по варианту или `Enter` на выделенном варианте устанавливает `selected`, записывает полную подпись в `text` и закрывает список. `ArrowDown`/`ArrowUp` перемещают выделение, `Escape` закрывает список без выбора. Повторное открытие не отправляет запрос.
4. При нажатии «Найти билеты» проверить оба `selected`, затем различие их `code`, затем прежние правила дат и фильтров. Разные аэропорты одного города допустимы.
5. Только после успешной проверки отправить ровно один запрос поиска. Набор предложений, выбор, закрытие списка и переключение сортировки не вызывают поиск и не записывают историю. Предыдущий успешный результат остаётся до отправки формы.

## 3. Вызовы и API

Нового API подсказок нет. Форма использует существующие `POST /api/fares/one-way` и `POST /api/fares/round-trip`, JSON. Выбор endpoint определяется переключателем «Туда и обратно».

| Поле запроса | Правило |
| --- | --- |
| `origin`, `destination` | Обязательные `selected.code`, формат `^[A-Z]{3}$`, значения различны |
| `departure_date` | Обязательная полная дата `YYYY-MM-DD`, не в прошлом |
| `return_date` | Только для round-trip; полная дата не раньше вылета |
| `market` | Двухбуквенный код; текущий выбор формы сохраняется, серверный default `RU` |
| `direct` | Boolean; текущий фильтр сохраняется |
| `max_price` | Необязательное положительное целое; пустое поле опускается |

Пример one-way: `{"origin":"SVO","destination":"LED","departure_date":"2026-11-15","market":"RU","direct":false}`. Для round-trip добавляется `return_date` и меняется endpoint. Текст города и название аэропорта в JSON не передаются.

Успешный ответ сохраняет существующую форму: `itineraries`, `observed_at`, `cache_hit`, `comparison`. Пустой `itineraries` означает успешный поиск без билетов. Кеш, история, сравнение цен и сортировка результатов работают по прежним правилам. Заголовок результата относится к отправленному маршруту, а не к дальнейшему редактированию полей.

## 4. Состояния UI

| Состояние | Внешний вид и действие |
| --- | --- |
| Пустое поле | Подсказка ввода города; `selected = null`; список закрыт |
| Ввод / есть совпадения | Список вариантов `Город — Аэропорт`; каждый доступен мышью и клавиатурой |
| Ввод / нет совпадений | «Аэропорты не найдены»; выбор отсутствует |
| Выбран аэропорт | Полная подпись в поле; список закрыт; выбор действителен до изменения текста |
| Некорректный маршрут | Сообщение у незаполненного или неподтверждённого поля либо общее сообщение о совпадении; без запроса |
| Поиск выполняется | Текущий индикатор «Проверяем варианты маршрута…» и заблокированная повторная отправка |
| Успех с билетами | Карточки, сравнение и сортировка по существующим правилам |
| Успех без билетов | Существующее сообщение об отсутствии билетов |
| Ошибка поиска | Сообщение сервиса или общее «Не удалось выполнить поиск.»; подтверждённый маршрут остаётся доступен для повтора |

## 5. Ошибки и ответственность

| Ситуация | Кто обнаруживает | Поведение |
| --- | --- | --- |
| Не выбран аэропорт в одном или обоих полях | Форма до POST | «Выберите аэропорт из списка» у каждого проблемного поля; без запроса |
| Нет совпадений в справочнике | Локальные подсказки | «Аэропорты не найдены»; при попытке поиска — сообщение о выборе из списка |
| Выбран одинаковый код дважды | Форма до POST; сервер также проверяет | «Пункты отправления и назначения должны отличаться.»; без запроса |
| Некорректная дата или цена | Существующая форма и сервер | Прежняя проверка; при серверной ошибке 422 показать понятное сообщение |
| Ошибка ответа 422 | Сервер | Строковый `detail` показать пользователю; структурированный `detail` заменить общим сообщением о проверке параметров |
| Ошибка 502, 503, 504 | Сервер поиска | Показать строковый `detail`; выбранные аэропорты оставить для повтора |
| Сеть недоступна / ответ не читается | Клиент | «Не удалось выполнить поиск.»; выбранные аэропорты оставить |

Свободный IATA-код в поле UI не превращается автоматически в подтверждённый аэропорт. Серверный формат IATA и существующие endpoint остаются совместимыми с прежними клиентами.

## 6. Решения на согласование

1. **Данные**: подтверждаем шесть перечисленных аэропортов и пустые начальные поля?
2. **Вызовы и алгоритм**: подтверждаем локальные подсказки с поиском по фрагменту названия города и единственный POST только по кнопке?
3. **Ошибки и состояния**: подтверждаем сообщения у неподтверждённых полей, сохранение прежнего результата при редактировании и сохранение выбора при ошибке поиска?

До ответа заказчика этот документ остаётся проектом; план реализации на него пока не опирается как на согласованный контракт.
