# Диалог с двумя агентами: выбор аэропорта по городу

**Источник:** фрагменты двух чатов, предоставленные пользователем для подготовки защиты. Время и ответы сохранены по этому источнику; длинные автоматические списки изменённых файлов заменены ссылками на файлы репозитория. Это запись состоявшегося взаимодействия, а не реконструкция несуществующих реплик.

## Общий контекст до работы агентов

Фича описана в [Spec Kit спецификации](../../../specs/001-city-airport-selection/spec.md) и [общем контракте](../../../specs/001-city-airport-selection/contract.md). Предоставленные заказчиком версии [спецификации](<before согласование/spec.md>) и [проекта контракта](<before согласование/contract.md>) до согласования сохранены отдельно. В обсуждении заказчик выбрал два правила: искать город только с начала названия и очищать прежний результат при отправке формы, показывая ошибку при неудаче.

## Чат 1 — команда UI

### 00:03 — задача заказчика

> Реализуй UI для новой фичи `001-city-airport-selection` по спекам. Реализовывай только UI, бэк будет писать другой агент.

### 00:10 — ответ UI-агента (работа 7 мин 14 с)

> UI выбора аэропорта реализован в `practice_05`, коммит `ab22f11`. Поля «Откуда» и «Куда» показывают подсказки по городу, поддерживают выбор клавиатурой и требуют подтверждённые разные аэропорты. По кнопке поиска в существующий API передаются IATA-коды; ввод сам по себе запрос не запускает. Серверный код не менялся.

Агент указал [форму](../frontend/src/App.tsx), [компонент выбора](../frontend/src/AirportField.tsx) и [документацию](../docs/features/city-airport-selection.md). По его отчёту прошли 6 сценариев фронтенда, сборка и проектная проверка с подменённым Ignav. Он прямо отметил, что браузерную ручную проверку списка не проводил.

### 00:11 — уточнение заказчика

> А там какие города вообще есть?

**Ответ UI-агента:** Москва (Шереметьево/SVO, Домодедово/DME, Внуково/VKO), Санкт-Петербург (Пулково/LED), Казань (KZN), Сочи (AER). Остальные города на тот момент не поддерживались.

### 00:12 — расширение задачи

> Добавь европейские столицы.

### 00:15 — ответ UI-агента (работа 3 мин 8 с)

> Добавлены 45 европейских столиц; итоговый [справочник](../frontend/src/airports.ts) содержит 48 городов и 58 вариантов аэропортов. Полный перечень — в [документации](../docs/features/city-airport-selection.md). Столицы микрогосударств без собственного аэропорта не добавлены. Прошли 7 фронтенд-тестов, сборка и проектная проверка. Браузер не открывался, бэкенд не менялся. Коммит `2ee8608`.

## Чат 2 — команда логики и бэкенда

### 00:03 — задача заказчика

> Реализуй логику и бэк для новой фичи `001-city-airport-selection` по спекам. Реализовывай только бэк и логику, UI будет писать другой агент.

### 00:08 — ответ агента логики (работа 5 мин 1 с)

> Логика выбора аэропорта реализована без изменений UI-компонентов. [fareSearch.ts](../frontend/src/fareSearch.ts) проверяет подтверждённый выбор, даты и фильтры, собирает запрос с кодами аэропортов и выполняет один POST по кнопке. UI-агент подключил модуль к форме.

> Серверный API менять не потребовалось: существующие endpoints поддерживают контракт. Добавлены [backend-проверки](../backend/tests/test_flights.py) маршрутов SVO→LED и DME→VKO. Общая проверка прошла: 28 backend-тестов, 6 тестов логики и сборка фронтенда; результат записан в [отчёте](../verification/flight-features.md).

Агент также сообщил, что в Spec Kit каталоге не было `plan.md` и `tasks.md`, поэтому штатное отмечание задач `$speckit-implement` не применялось.

## Граница ответственности и проверяемые результаты

| Команда | Основной результат | Не меняла |
| --- | --- | --- |
| UI | Поля выбора, подсказки, клавиатура, подключение к форме, расширение справочника | Серверный API |
| Логика | Проверка выбранных аэропортов и параметров, сборка одного POST, обработка ошибок, backend-тесты существующего API | UI-компоненты |

Обе команды работали с общим контрактом формы и API. Архивная версия «до» содержит UI и логику в одном `spec.md`; отдельных спецификаций по командам в предоставленных материалах нет. Записи браузерного демо также нет. Этот диалог не заменяет такие артефакты.
