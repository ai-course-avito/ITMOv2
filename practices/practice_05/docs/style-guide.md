# Стиль review-mini

Пять правил под наши фичи. Перед изменением кода этот файл читают целиком.

1. **Проверяй поведение через публичный интерфейс.** Тест вызывает
   `review_diff` или `subscribe`, а не внутренние помощники. Приватную функцию
   можно переименовать, контракт — нет.
2. **Отказ и ошибка — это возвращаемое значение, а не исключение наружу.** Любой
   предвиденный исход описан в контракте кодом и `message`. Трейсбек до
   вызывающего кода не доходит.
3. **Клиент модели инъектируется параметром.** В тестах сеть не используется
   никогда: передаётся подставной объект с методом `complete`.
4. **Лимиты и таймауты — именованные константы уровня модуля**, с единицей
   измерения в имени: `MAX_DIFF_BYTES`, `REVIEW_TIMEOUT_SECONDS`. Чисел внутри
   условий не оставляем.
5. **Никаких зависимостей вне стандартной библиотеки** и никакого ослабления
   `scripts/check.sh`. Фреймворк ради маленькой правки не добавляем.

## Хороший пример

Правило 3 в деле — проверка того, что при отказе модель не вызывается. Клиент
падает, если его вызвали, поэтому тест проверяет факт, а не время ответа:

```python
class ExplodingClient:
    def complete(self, system, user):
        raise AssertionError("модель не должна вызываться при отказе")


def test_rejects_without_calling_model(self):
    result = review_diff("", client=ExplodingClient())
    self.assertEqual(result["code"], "empty_diff")
```
