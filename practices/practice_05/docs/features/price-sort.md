# Выбор порядка сортировки билетов

Статус: реализовано и принято человеком 2026-10-26. OpenSpec change: `flight-price-sort`.

## Цель

Дать пользователю возможность менять порядок уже найденных билетов по цене через переключатель «Сначала дешёвые / Сначала дорогие» над результатами поиска.

## Поведение до изменения

Сервер в `backend/app/ignav.py` сортирует нормализованные `itineraries` по возрастанию цены. `frontend/src/App.tsx` отображает их в порядке ответа. В интерфейсе выбора порядка нет. Ответ содержит цену и валюту, необходимые для локальной сортировки.

## Условия приёмки

1. При первом отображении результатов выбран порядок «Сначала дешёвые», карточки идут по возрастанию цены.
2. Выбор «Сначала дорогие» сразу показывает те же карточки по убыванию цены. Переключение обратно восстанавливает порядок по возрастанию. Карточки с одинаковой ценой сохраняют взаимный порядок из ответа сервера.
3. Переключение работает только с полученными данными: не выполняет `fetch`, не запускает поиск и не создаёт записи в истории. Исходный массив ответа не изменяется.
4. При пустом ответе остаётся прежнее сообщение об отсутствии билетов, переключатель скрыт. Единственная карточка отображается корректно в обоих порядках.
5. Каждый новый успешный поиск начинает показ с «Сначала дешёвые». Переключение не меняет параметры формы, состав карточек, блок сравнения цен и сведения о кеше.

## Границы

Изменение касается отображения результатов в `practice_05/frontend`. API, серверная сортировка, запросы к Ignav, SQLite, расчёт минимальной цены и MCP сохраняют существующий контракт. Сортировка по длительности, фильтрация, сохранение выбора после перезагрузки и изменения приложения практики 4 в эту фичу не входят.

## Проверка

| Сценарий | Ожидаемый результат |
|---|---|
| Ответ с ценами 3000, 4000, 5000 | По умолчанию карточки 3000 → 4000 → 5000 |
| Выбор «Сначала дорогие» | Карточки 5000 → 4000 → 3000, сетевых запросов не добавилось |
| Две карточки с одинаковой ценой | Их взаимный порядок сохраняется в обоих режимах |
| Повторное переключение | Все карточки сохранены, сравнение цен и форма прежние |
| Одна карточка / пустой ответ | Одна карточка показана корректно; для пустого ответа — сообщение и нет переключателя |
| Новый успешный поиск после выбора убывания | Новый список показан по возрастанию |
| Ошибка поиска | Сохраняется существующее отображение ошибки |

Для проверки используйте подменённые ответы сервера. Перед реализацией зафиксируйте свежий baseline через runner `verify-flight-features`. После реализации выполните runner и проверьте интерфейс: одна сборка фронтенда не подтверждает условия приёмки. В отчёте по каждому условию укажите ожидание, факт и доказательство.

## Дальнейшие шаги OpenSpec

Для `practice_05` создан change `flight-price-sort` со спецификацией, дизайном и задачами. После приёмки основные specs можно синхронизировать и архивировать change.

Переключатель расположен над непустым списком результатов. Он сортирует копию полученного списка локально и сбрасывается на «Сначала дешёвые» после нового успешного поиска. При пустом ответе переключатель скрыт.
