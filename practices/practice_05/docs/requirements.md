# Контракт review-mini

Целевое состояние сервиса. Фичи A и B реализуют в нём отказные и ошибочные пути;
успешный путь уже работает.

## Подписки (унаследованное поведение)

`subscribe(name) -> {"subscribed": True}` из `app/subscribe.py`.
Пустое или пробельное имя даёт `ValueError`. Повтор не создаёт дубликат.
Это поведение менять нельзя: оно служит регрессионной поверхностью.

## Ревью диффа

`review_diff(diff, client=None) -> dict` из `app/review.py`.

`client` — объект с методом `complete(system, user) -> str`. По умолчанию
`OllamaClient`, который ходит на `localhost:11434`. Инъекция клиента нужна
тестам: сеть в тестах не используется.

### Успех

```
{"status": "ok", "review": "<текст ревью>", "stats": {"files": N, "added": N, "removed": N}}
```

### Фича A — валидация входа

| Условие | Ответ |
|---|---|
| дифф пустой или только пробелы | `{"status": "rejected", "code": "empty_diff", "message": "<...>"}` |
| `len(diff.encode("utf-8")) > MAX_DIFF_BYTES` | `{"status": "rejected", "code": "diff_too_large", "message": "<...>"}` |

`MAX_DIFF_BYTES = 8192`.

Главное требование: **при отказе клиент модели не вызывается**. Проверяется
клиентом, который падает при вызове, а не подсчётом времени ответа.

### Фича B — ошибка зависимости

Ожидание модели ограничено `REVIEW_TIMEOUT_SECONDS = 30`.

| Условие | Ответ |
|---|---|
| ожидание вышло | `{"status": "error", "code": "model_timeout", "message": "<...>", "stats": {...}}` |
| соединение не установлено | `{"status": "error", "code": "model_unavailable", "message": "<...>", "stats": {...}}` |
| модель ответила HTTP-ошибкой | `{"status": "error", "code": "model_http_error", "message": "<...>", "stats": {...}}` |
| ответ без ожидаемых полей | `{"status": "error", "code": "model_bad_response", "message": "<...>", "stats": {...}}` |

`message` пишется для человека и называет причину. Наружу исключения не
пробрасываются. Отказы фичи A продолжают работать без изменений.

### Статистика диффа

Ответы `status == "ok"` и `status == "error"` дополнительно содержат поле
`"stats": {"files": N, "added": N, "removed": N}` — результат
детерминированного подсчёта по тексту диффа, без участия модели. Отказы
`status == "rejected"` поле `stats` не содержат.

Правило подсчёта: строка `--- X`, непосредственно после которой идёт
строка `+++ Y`, — заголовок файла и увеличивает только `files`. Строка
`--- x`, после которой следующая строка не начинается с `+++ ` (например,
удалённый SQL-комментарий `-- x`), — это удалённая строка контента и
увеличивает `removed`, а не `files`. Любая другая строка, начинающаяся с
`+`, увеличивает `added`; любая другая строка, начинающаяся с `-`,
увеличивает `removed`. Дифф без распознаваемых конструкций даёт
`{"files": 0, "added": 0, "removed": 0}`.
