# Few-shot

- Артефакт Практики 1: practices/practice_01/tests_e2e.md (до few-shot)
- Что хотим улучшить: из одного размытого сценария сделать набор воспроизводимых E2E-кейсов с конкретным Evidence (HTTP-статусы и проверяемые поля/логи), охватывающих успех, ошибку валидации и граничное условие по размеру diff.

## Примеры

### Хороший результат

Табличный сценарий с конкретным действием, ожидаемым статусом и проверяемыми полями ответа и логов. Пример (в духе полученного few-shot):

| Сценарий | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный: валидный diff | Сервис запущен; доступен POST `/api/reviews`; LLM замокан; длина diff ≤ 20000 | POST `/api/reviews` с телом `{"diff": "diff --git ..."}` | 200 OK; тело содержит `summary`, `risks` (≤3), `checks` | HTTP: статус=200; JSON: есть `summary`,`risks`,`checks`, `len(risks) ≤ 3`; Логи: `request_id`, `duration`, `status=200`; строки diff в логах нет |

### Плохой результат

Один общий сценарий без негативных/граничных кейсов и с расплывчатым Evidence. Пример из исходника:

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Пользователь отправляет diff и получает ответ | Сервис запущен; доступен POST `/api/reviews`; LLM замокан | Отправить `{"diff": "diff --git a/x b/x\n+line"}` | 200 OK; тело с полями `summary`, `risks` (<=3), `checks`; поля в risks заполнены | логи / тест-раннер |

## Запрос

Переписать tests_e2e.md и сохранить новую версию в practices/practice_02/few_shot/tests_e2e.md: добавить 3 сценария (позитивный 200 OK с `summary`,`risks`≤3,`checks`; негативный 422 при пустом `{}`; граничный 413 при diff > 20000), сделать Evidence воспроизводимым (конкретные статусы, проверяемые поля JSON, в логах — `request_id`,`duration`,`status`, без содержимого diff), и кратко зафиксировать формат успеха.

## Что получили

Файл practices/practice_02/few_shot/tests_e2e.md с таблицей из трёх E2E-сценариев:

- Позитивный: 200 OK; JSON включает `summary`,`risks`,`checks`, ограничение `len(risks) ≤ 3`; Evidence: статус=200, наличие ключей, в логах `request_id`,`duration`,`status=200`, отсутствие подстроки `"diff --git"`.
- Негативный: `{}` → 422 Unprocessable Entity; Evidence: статус=422, в теле ошибки указано отсутствие поля `diff`, в логах `request_id`,`duration`,`status=422`, без содержимого diff.
- Граничный: diff > 20000 → 413 Payload Too Large; Evidence: статус=413; в логах `request_id`,`duration`,`status=413`, без содержимого diff.

Добавлены «Примечания к формату»: на успех ожидается структура `summary`, `risks[]` (≤3, с деталями), `checks[]`; для ошибок — фиксируем статусы и отсутствие утечки diff в логах.

Уточнено ограничение `len(risks) ≤ 3` и явная проверка отсутствия подстроки `"diff --git"` в логах.
