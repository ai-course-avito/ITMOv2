# Few-shot

- Артефакт Практики 1: prompts.md — раздел «P1‑02 Result (OUT‑1)» (JSON‑ответ AI‑агента).
- Что хотим улучшить: убрать галлюцинации, добавить evidence и checks, разделить подтверждённые риски и открытые вопросы.

## Примеры

### Хороший результат

Критерии приёмки формулируются верифицируемо: статусы 200/422/413/5xx с конкретными предпосылками; без «или/возможно»; без утечек деталей.

### Плохой результат

Размытые статусы («422 или 400»), отсутствие сценария таймаута внешнего LLM.

## Запрос

Используем few-shot с примерами хорошего/плохого описания риска. Вход: текущие пункты из JSON «P1‑02 Result». Задача: переписать пункты так, чтобы каждый риск имел evidence (файл/строка/фрагмент), краткую формулировку и воспроизводимые checks; неподтверждённые формулировки перенести в «Открытые вопросы».

Текст промпта (роль: ревьюер артефактов AI):

```
Ты — ревьюер артефактов AI. На входе — список проблем из problems.md, часть из которых может быть неподтверждённой или двусмысленной.

Примеры:

Хороший риск:
app/api.py:36 — доступ к payload["diff"] без проверки → KeyError и 500. Evidence: фрагмент кода/строки diff. Checks: POST {} ⇒ 422.

Плохой риск:
«Нужна аутентификация и rate limiting» (без источника).

Требования:
- Для каждого риска добавь evidence (файл/строка/фрагмент) и 1–2 воспроизводимых checks.
- Неподтверждённые пункты вынеси в «Открытые вопросы» с предложенными проверками.
- Соблюдай QA‑1: опирайся только на TRAINING_PR.diff и правила в context.md.
Верни переработанный список: Confirmed risks (с evidence и checks) и Open questions.
```
