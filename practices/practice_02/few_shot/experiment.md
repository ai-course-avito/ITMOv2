# Few-shot

- Артефакт Практики 1: `practices/practice_01/TRAINING_PR.diff` и запись журнала `practices/practice_01/prompts.md` раздел P1-01
- Что хотим улучшить: снизить 500-ошибки валидируя вход, задать чёткий контракт запроса/ответа, ограничить размер diff, обработать ошибки LLM и смягчить prompt-injection, сохранить синхронное API минимальными правками.

## Примеры

### Хороший результат

Краткий вывод с проверяемыми рисками, каждый с evidence `file:line` из diff и шагом проверки.

Пример фрагмента результата:

```
summary
- POST /api/reviews добавлен без валидации входа и схем — риск 500 и слабый контракт.

risks
- candidate: Необработанный KeyError при отсутствии поля diff
  evidence: app/api.py L35-38: def create_review(payload: dict) … review_service.review(payload["diff"]) 
  rule: Валидация тела запроса → 422 на некорректный JSON
  check: POST /api/reviews с {} → ожидать 422

checks
1. POST {} → 422
2. /docs содержит схему запроса/ответа
```

### Плохой результат

- Нет ссылок на строки diff, обобщённые утверждения.
- Спекуляции вне diff (версии Python, детали реализации без evidence).
- Нет воспроизводимых шагов проверки.

## Запрос

Использованный запрос (P1-01): "Review this pull request and find problems"; анализировать только `TRAINING_PR.diff`.

Запрос для few-shot (использовать в П2): короткий контракт на результат и границы контекста.

```
Проанализируй только этот diff и верни краткий обзор проблем и проверок.
Формат: summary; risks (candidate, evidence file:line, rule, check); checks (список шагов).
Только подтверждённые diff строки, без домыслов.
```

## Что получили

- По P1-01: summary + 6 risks + checks. Все риски подтверждены ссылками на строки в diff и воспроизводимыми шагами. Спекуляции про версии/форматы были убраны.

Анализ артефактов в P1-01:
- Артефактов (hallucinations) в финальной версии не выявлено. Ранние спекуляции про версию Python и формат ответа были удалены и отражены как исправления в журнале P1-01.

## Что изменили в исходном артефакте

- Файл и раздел: `app/api.py` (по диффу из `TRAINING_PR.diff`), добавленный эндпоинт `/api/reviews`
- Изменение: предложены минимальные правки контракта и валидации без смены архитектуры
  - Ввести Pydantic-модель запроса: поле `diff: constr(max_length=N)`; задать `response_model` с полем `comment: str`.
  - При отсутствии поля `diff` сервер должен возвращать 422, а не 500 (устранить KeyError на доступе к `payload["diff"]`).
  - Ограничить размер `diff` (пример: N = 200_000 символов) и возвращать 413/422 при превышении.
  - Сохранить текущий синхронный обработчик, чтобы не менять модель исполнения.
- Как проверили:
  1. POST `/api/reviews` с `{}` → 422 Unprocessable Entity.
  2. Открыть `/docs` → у POST `/api/reviews` схема запроса/ответа с полем `diff` и `comment`.
  3. POST с большим `diff` (>N) → 413/422; с валидным — 200 и тело `{ "comment": … }`.
- Что отклонили:
  - Перевод эндпоинта в `async`/фоновые задачи — пока не требуется по минимальности изменения.
  - Глубокую переработку OpenAPI/версионирование схем — не подтверждено задачей.

- Файл и раздел: `app/review_service.py`, метод `review`
- Изменение: добавить безопасную сборку промпта и обработку исключений LLM
  - Оборачивать `diff` в явные разделители (например, тройные бэктики) и фиксированные инструкции, чтобы снизить prompt-injection.
  - Обернуть вызов `llm.generate` в `try/except` и возвращать контролируемую ошибку/сообщение.
- Как проверили:
  1. Юнит: мокнуть `llm.generate` на исключение → метод возвращает контролируемый ответ; HTTP 5xx от прикладного KeyError отсутствуют.
  2. Инъекционный diff ("Ignore previous instructions…"): промпт содержит явные разделители ``` до/после diff; ответ остаётся в рамке `comment` и не содержит действий (например, "Approved"/выполнение команд). См. practices/practice_01/adr.md, раздел «Решение», пункт про делимитеры в промпте.
- Что отклонили:
  - Изменение протокола `LLM` и переход на асинхронный интерфейс — избыточно для текущей задачи.
