# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: `practices/practice_01/product_management.md`
- Что хотим улучшить: детализацию Gherkin и coverage краевых случаев (таймауты геокодера, кэш Redis)

## Примеры

### Хороший результат

Сценарии чётко задают таймауты и поведение кэша: указан таймаут 1500 мс; описан промах кэша и прогрев; нет 5xx при деградации Redis.

### Плохой результат

Общие формулировки без чисел; не ясно, что делать при недоступности Redis; нет указания TTL кэша.

## Запрос

"Добавь в раздел Gherkin сценарии для следующих случаев: 1) таймаут внешнего геокодера с явным числом (например, 1500 мс) и сохранностью локальных результатов; 2) промах кэша и прогрев с установкой TTL; 3) поведение при недоступности Redis — degraded mode без 5xx. Используй короткие, проверяемые шаги."

## Что получили

Модель предложила три сценария: таймаут геокодера с прекращением ожидания, логированием и маркировкой «частичный»; промах кэша с записью в Redis с TTL 600 секунд; деградация Redis с обходом кэша и логом деградации.

## Что изменили в исходном артефакте

- Файл и раздел:
  `practices/practice_01/product_management.md#User stories и acceptance criteria`
 - Изменение:
  добавлены сценарии: "Таймаут внешнего геокодера", "Промах кэша и прогрев", "Redis недоступен (degraded mode)" с конкретными цифрами и поведением.
 - Как проверили:
  просмотр diff; поиск по файлу по ключам: "таймаут", "TTL 600", "degraded mode".
 - Что отклонили:
