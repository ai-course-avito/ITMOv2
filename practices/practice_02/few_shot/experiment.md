# Few-shot

- Артефакт Практики 1: tests_load.md (нагрузочные проверки)
- Что хотим улучшить: превратить документ из декларативного в практический — с тремя сценариями, профилями нагрузки, SLO/SLA, критериями «pass/fail» и корректным evidence (k6 summary/графики), без ссылок на diff и «len(diff)»

## Примеры

### Хороший результат

Короткий фрагмент финального сценария S1 (пример):

- Профиль: warmup 2 мин, ramp 2 мин до steady 8 RPS (диапазон 5–10 RPS), steady 10 мин
- Метрики: p95, p99, error rate, 5xx, timeouts
- Критерии прохождения: p95 < 500 мс, error rate < 1%, 5xx = 0%, timeouts = 0%
- Evidence (пример k6 summary): p95=430ms, p99=780ms, http_req_failed=0.6%, 5xx=0, timeouts=0

### Плохой результат

Фрагмент исходного артефакта (до правок):

- «На текущем этапе нагрузочное тестирование пока не требуется…»
- «Evidence: diff line 20 — len(diff) не проверяется»

Почему плохо: отсутствуют сценарии, SLO/SLA и проверяемые метрики; evidence не является результатом замеров.

## Запрос

Использованный метапромпт (сокращённо):

- Роль: ведущий инженер по производительности; написать tests_load.md с 3 сценариями (S1, S2, S3)
- Инпуты: product_name, base_url, endpoint_under_test, llm_latency_toggle, data_shape_small, data_shape_large, auth, tool=k6, duration_defaults, REL_1_ref, monitoring
- Жёсткие требования: цели для S1/S2/S3, таблица SLO/SLA, критерии «pass/fail», evidence (k6 summary/графики), без «len(diff)»

## Что получили

Итог: практический tests_load.md с:

- Таблицей SLO/SLA по сценариям
- Тремя сценариями: S1 (<1K символов), S2 (~20 000 символов, REL-1), S3 (задержка LLM)
- Профилями нагрузки, длительностями, целями для p95/p99, error rate, 5xx, timeouts
- Планом запуска k6, местом сохранения артефактов (summary.json, графики)

## Что изменили в исходном артефакте

- Файл и раздел: practices/practice_02/few_shot/test_load.md — заменён полностью на практический документ
- Изменение: добавлены 3 сценария, сводная таблица SLO/SLA, явные критерии «pass/fail», план запуска k6 и структура артефактов
- Как проверили: чек-лист — 3 сценария присутствуют; у каждого инструменты, профиль, длительность, метрики, критерии и evidence; есть сводная таблица SLO/SLA; нет упоминаний «len(diff)»; «Для чего» сформулировано корректно
- Что отклонили: любые оговорки «нагрузка не нужна»; нефункциональные «evidence» без замеров; навешивание непроверяемых порогов на p99 в SLO (оставили фиксацию p99 без жёсткого порога)
