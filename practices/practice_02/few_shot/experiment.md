# Few-shot

- Артефакт Практики 1: `practices/practice_01/problem.md`
- Что хотим улучшить: конкретизировать метрики (убрать плейсхолдеры, задать условия измерений и целевые значения).

## Примеры

### Хороший результат

Метрики без плейсхолдеров, с конкретными целями и условиями замера. Пример:

| Метрика | Текущее | Цель | Условия |
|---|---|---|---|
| Доля 5xx при невалидном теле | 500 на `{}` | 0% 5xx; 422 | Интеграционный тест |
| Ошибки LLM | 500 | 0 необработанных; HTTP 502 с `LLM_UPSTREAM_ERROR` | Мок LLM, unit/integration |
| Лимит diff | Нет | 20 000 символов принимаются; 20 001 — 413 | Unit-тест на Unicode-строках |
| P95 латентность | Baseline отсутствует | `P95_after <= P95_baseline` | Одинаковый стенд, diff ≤10 KB, мок 100 ms, 100 запросов |


### Плохой результат

Плейсхолдеры и неопределённости. Пример анти‑паттернов:

- «P95 <= X ms» без числа и условий.
- «Лимит (например, 100–200 KB)» без фиксации.
- «100% покрытие try/except» как цель вместо пользовательской метрики.


## Запрос

Сформируй финальную таблицу метрик для файла `practices/practice_01/problem.md` без плейсхолдеров и с воспроизводимыми условиями замеров. Используй числовое значение только при наличии источника; иначе зафиксируй baseline и правило сравнения. Укажи, как и где измеряем и какие тесты подтвердят улучшение. Не меняй проблему и границы задачи.
