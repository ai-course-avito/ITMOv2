# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Верификация 413 на границе | 1 RPS, 100 запросов: 50 с 20001 символов, 50 с 20000 | 100% кейсов > 20000 возвращают 413; ≤ 20000 — 200 | корректность кодов; латентность проверки длины | CASE.md API-1; US-02 CoV |
| Языковая формулировка не влияет | 2 RPS, 5 мин | p95 ≤ 200 мс для 413; 5xx = 0 | p50/p95 413, ошибки | chain_of_verification/experiment.md; product_management.md US-02 |
| Регресс валидации | 3 RPS, 10 мин, смесь 422/200/413 | доли кодов соответствуют входу; 5xx = 0 | распределение статусов, p95 per code | problem.md; CASE.md API-1 |

Если нагрузочное тестирование пока не требуется, условие запуска: после фиксации явного Then «413 Payload Too Large» и числа «20001 символов» в US-02 (Chain of Verification эксперимент).

## Как использовали AI

- Эксперимент: chain_of_verification/experiment.md
- Что проверили и исправили сами: сконцентрировались на проверяемых границах и корректности кодов без расширения объёма.

## Финальные Gherkin-сценарии

```gherkin
@API-1
Scenario: 413 на границе длины при 1 RPS
  Given 100 запросов: 50 с длиной diff = 20001, 50 с длиной diff = 20000
  When отправляем POST "/api/reviews"
  Then 100% случаев > 20000 возвращают 413; ≤ 20000 — 200

@API-1
Scenario: Латентность проверки длины стабильна
  Given профиль нагрузки 2 RPS в течение 5 минут
  When отправляем тела с длиной diff на границе 20000±10
  Then p95 времени проверки длины ≤ 200 мс, 5xx = 0

@API-1 @REL-1
Scenario: Смесь 422/200/413 без 5xx
  Given профиль нагрузки 3 RPS в течение 10 минут
  And 30% тел без diff, 20% с diff = 20001, 50% валидных
  When отправляем POST "/api/reviews"
  Then доли кодов соответствуют входу; 5xx = 0; p95 per code под целями
```
