# Chain of Verification — experiment

## Артефакт Практики 1

Я проверял сценарий из practices/practice_01/tests_e2e.md: POST `/api/reviews` с телом `{"diff":"..."}` и ожиданием ответа с `summary/risks/checks`.

## Вопросы проверки

1. Подтверждается ли сценарий кодом из TRAINING_PR.diff или правилом CASE? Ответ: да
2. Есть ли конкретный Evidence (статус, поле, лог)? Ответ: да
3. Нет ли двусмысленности в формулировке? Ответ: нет
4. Не выходит ли сценарий за рамки учебного кейса? Ответ: нет
5. Можно ли воспроизвести проверку по описанию? Ответ: да

## Evidence по каждому вопросу

1) Подтверждение кодом
- Evidence: TRAINING_PR.diff — app/api.py:35–38 (POST `/api/reviews`), app/review_service.py:19–22 (возвращает `{ "comment": answer }`).
- Если «нет»: выровнять формат ответа под `comment`.

2) Конкретность Evidence
- Evidence: 200 OK по умолчанию FastAPI обработчика; JSON содержит ключ `comment` (dict[str, str]) — app/review_service.py:19–22.
- Если «нет»: явно указать статус 200 и проверку наличия `$.comment`.

3) Двусмысленность формата
- Evidence: реализация возвращает только `comment` — app/review_service.py:19–22.
- Если «нет»: заменить `summary/risks/checks` на `comment`.

4) Границы учебного кейса
- Evidence: CASE.md (OUT-1) описывает целевой формат, но текущая реализация минимальна; сценарий после правки не требует полей вне `comment` и не запрашивает логирование содержимого (OBS-1).
- Если «нет»: убрать ожидания `summary/risks/checks`, не требовать логов содержимого.

5) Воспроизводимость
- Evidence: указан метод, маршрут, тело `{ "diff": "..." }`, статус 200 и поле `comment`; соответствует TRAINING_PR.diff (app/api.py:35–38; app/review_service.py:19–22).
- Если «нет»: добавить точные ассерты к статусу и полю ответа.

## Что исправили

- Выровнял ожидаемый формат ответа: вместо `summary/risks/checks` — `comment`.
- Добавил конкретику Evidence: 200 OK и наличие `$.comment` (string).
- Заменил «логи / тест-раннер» на конкретные ассерты и ссылки на строки diff.

## Что отклонили

- Ожидание `summary`, `risks`, `checks` из CASE (OUT-1) в E2E-тесте — отклонено как не соответствующее текущей реализации TRAINING_PR.diff.
- Ссылки на абстрактные «логи / тест-раннер» — отклонены; вместо этого использую статус/поле ответа. Также не требую логирования содержимого (CASE OBS-1).

CoV выявил расхождение: TO BE (summary/risks/checks) не подтверждается текущей реализацией. Для верификации выбран фактический контракт (comment) как baseline.
