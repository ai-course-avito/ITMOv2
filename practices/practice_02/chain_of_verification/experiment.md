# Chain of Verification

- Проверяемый черновик или утверждение: формулировки метрик и условий в `practices/practice_01/problem.md`.

## Запрос на проверку

Проверь следующие утверждения на верифицируемость и наличие evidence: 422 при отсутствующем, пустом или пробельном diff; HTTP 502 с `LLM_UPSTREAM_ERROR` при исключении/timeout LLM; границы 19 999/20 000/20 001 Unicode-символ; сравнение P95 с baseline при одинаковом стенде. Верни вопросы проверки, источник или способ проверки, evidence status и исправленные формулировки.

## Вопросы проверки и evidence

| Вопрос | Источник или проверка | Результат |
|---|---|---|
| Возвращается ли 422 при `{}` всегда и без 5xx в логах? | Интеграционный тест POST `/api/reviews` с `{}` | ожидается 422; фактическое evidence — после реализации теста |
| Отклоняется ли пустой или пробельный diff до вызова LLM? | Integration с `{"diff":"   "}` и счётчиком вызовов мока | ожидается 422 и 0 вызовов; `evidence_status=not_collected` |
| Преобразуется ли исключение/timeout LLM в точный контракт ошибки? | Unit/integration с мок LLM | ожидается HTTP 502 и `error.code=LLM_UPSTREAM_ERROR`; `evidence_status=not_collected` |
| Однозначна ли граница 20 000 символов? | Unit на Unicode-строках 19 999/20 000/20 001 после JSON decode и до redaction | первые два входа принимаются, третий даёт 413; `evidence_status=not_collected` |
| Есть ли регрессия P95? | Два замера по 100 запросов, мок LLM 100 ms, diff ≤10 KB, одинаковый стенд | правило `P95_after <= P95_baseline`; `evidence_status=not_collected` |

## Исправленный результат

Метрики уточнены: точная схема HTTP 502; пустой diff; единица и момент подсчёта длины; три граничных значения; сравнение P95 с baseline. До запуска все фактические результаты имеют `evidence_status=not_collected`.
