# Chain of Verification

- Проверяемый черновик или утверждение: черновые решения ADR перед внесением в `../practice_01/adr.md` — (1) «при падении LLM сервис даёт контролируемый ответ, а не 500»; (2) «секреты из diff не уходят во внешний LLM»; (3) «повторные вызовы при сбое LLM безопасны»; (4) «fallback-ответ не выдаётся за полное ревью».
## Запрос на проверку

```text
Проверь 4 утверждения из черновика ADR сервиса ревью PR:
1) отказоустойчивость при падении LLM — контролируемый ответ, не 500;
2) утечка токенов из diff исключена (SEC-1);
3) rate limits защищают внешний LLM от перегрузки при сбоях;
4) fallback-ответ помечается и не маскирует недоступность LLM.
Для каждого: сформулируй верификационный вопрос, укажи источник или проверку
и ответь, подтверждено утверждение или нет. Скрытые рассуждения не выводи.
```

## Исправленный результат

Утверждения 1, 3, 4 не подтвердились, 2 подтвердилось только как целевое. Коррекция черновика ADR:

- падение/таймаут LLM → деградированный контролируемый ответ `{degraded: true, summary: из метаданных diff, risks: [], checks: ручные проверки}`, никогда HTTP 500;
- фильтр SEC-1 выполняется до любой ветки (в т.ч. fallback), 0% утечек в логе;
- rate limit: N запросов/мин на клиента, при превышении 429, без бесконечных ретраев;
- fallback-ответ помечается `degraded` и логируется только статус (OBS-1) — не маскирует недоступность LLM.
