## Запрос на проверку

Ты — инженер по производительности и технический ревьюер. Ниже черновик
нагрузочных проверок для сервиса AI-ревью PR.

Контекст сервиса:
- эндпоинт POST /api/reviews принимает JSON {"diff": "..."};
- вызывает внешний LLM, timeout 10 секунд (REL-1);
- diff длиннее 20 000 символов отклоняется с HTTP 413 (API-1);
- ответ: summary, risks (до 3), checks (OUT-1);
- сервис только советует, код не меняет (SCOPE-1);
- в лог пишутся request_id, длительность, статус (OBS-1).

Проверь черновик по шагам:
1. Сформулируй 5–7 проверочных вопросов, ответы на которые должны быть
   в качественном файле нагрузочных проверок.
2. Для каждого вопроса укажи, что в черновике есть, чего нет и на какой
   источник или правило это опирается.
3. Отдельно проверь, является ли evidence в черновике настоящим
   evidence нагрузки или подменой (например, ссылкой на валидацию diff).
4. Предложи исправленный текст tests_load.md: не менее 3 сценариев,
   профиль нагрузки, длительность, инструмент, метрики (RPS, p95, p99,
   error rate, timeouts), критерий прохождения и evidence.
5. Не додумывай факты, которых нет в контексте. Если данных не хватает,
   пометь это как открытый вопрос.
