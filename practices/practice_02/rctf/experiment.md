# R.C.T.F.

- **Role:** Senior Product Manager в B2B SaaS-компании, специализирующийся на developer tools.
- **Context:** Есть сервис AI-помощника ревьюера PR (ReviewService). Текущий черновик проблемы описывает пользователя и ситуацию, но метрики сформулированы слабо — в них написано «нет исторических данных» вместо конкретного способа замера. Правила сервиса: SEC-1 (утечка секретов), API-1 (лимит размера diff), REL-1 (timeout LLM), OUT-1 (структура ответа).
- **Task:** Переформулируй три метрики из practices/practice_01/problem.md так, чтобы каждая метрика содержала: (1) измеримый числовой baseline, (2) конкретный способ замера прямо сейчас без дополнительной инфраструктуры, (3) реалистичный целевой показатель. Не придумывай данные — если данных нет, укажи как их получить за 1 день.
- **Format:** Верни только обновлённую markdown-таблицу метрик в том же формате что в файле. Никаких пояснений вне таблицы.

## Полный запрос

```
Role: Senior Product Manager в B2B SaaS-компании, специализирующийся на developer tools.

Context: Есть сервис AI-помощника ревьюера PR (ReviewService). Текущий черновик проблемы описывает пользователя и ситуацию, но метрики сформулированы слабо — в них написано «нет исторических данных» вместо конкретного способа замера. Правила сервиса: SEC-1 (утечка секретов), API-1 (лимит размера diff), REL-1 (timeout LLM), OUT-1 (структура ответа). Файл с проблемой: @practices/practice_01/problem.md

Task: Переформулируй три метрики из practices/practice_01/problem.md так, чтобы каждая метрика содержала: (1) измеримый числовой baseline, даже если это «0 из N замеренных случаев», (2) конкретный способ замера прямо сейчас без дополнительной инфраструктуры, (3) реалистичный целевой показатель. Не придумывай данные — если данных нет, укажи как их получить за 1 день.

Format: Верни только обновлённую markdown-таблицу метрик в том же формате что в файле. Никаких пояснений вне таблицы.
```

## Что получили

Модель (openai/gpt-5) вернула таблицу, где для каждой метрики подробно расписала, как получить базовое значение (baseline) за один день. Например, для SEC-1 предложено проанализировать 30 закрытых PR вручную; для среднего времени ревью — посчитать по меткам 30 последних PR через `gh`.

## Что изменили в исходном артефакте

- Файл и раздел: `practices/practice_01/problem.md` (раздел «Метрики»)
- Изменение: таблица метрик заменена на более подробную версию, содержащую конкретные шаги для замеров (baseline на 30 PR, прогон 200 запросов для замера 500-х ошибок).
- Как проверили: таблица соответствует заданному формату, не содержит выдуманных данных, шаги (ручная разметка 30 PR) действительно можно выполнить без сложной дата-инфраструктуры.
- Что отклонили: модель была склонна добавлять вводные слова и комментарии — форматное ограничение ("только обновлённую markdown-таблицу") помогло получить чистый ответ.
