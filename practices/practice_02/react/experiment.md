# ReAct

- Цель: расследовать аномалию — запросы к `POST /api/reviews` стали отвечать дольше 10 с, затем частично возвращать HTTP 500; определить причину, дать отчёт человеку и предложить правки артефакта.
- Доступные входы: логи (только `request_id`, длительность, статус — OBS-1), `/health`, статус-коды ответов, исходники `review_service.py`/`api.py` из `../practice_01/TRAINING_PR.diff`, правила из `../practice_01/context.md`.
- Разрешённые действия: проверять логи и `/health`, воспроизводить запрос с моком LLM (sleep 15 с), запускать curl без модификации продакшн-кода.
- Запрещённые действия: менять продакшн-код, approve/merge, читать содержимое diff и ответа модели (OBS-1), бесконечные ретраи при сбое.
- Максимальное число шагов: 5.
- Условие остановки и вопроса человеку: после установления причины на основе evidence → сформировать отчёт и завершить `Finish`; если за 5 шагов причина не подтверждается или требуются данные вне логов/диффа → остановиться и спросить человека.

## Запрос

```text
Расследуй аномалию: /api/reviews отвечает >10 с, потом часть запросов даёт 500.
Действуй по ReAct: на каждом шаге сначала размышление (Thought), затем действие (Action),
наблюдение (Observation). Разрешено: логи, /health, curl, запуск с мок-LLM
(sleep 15 с). Не менять код, не логировать содержимое diff/ответа, не делать
бесконечных ретраев. Максимум 5 шагов. Когда причина подтверждена evidence —
верни отчёт человеку и заверши (Finish). Если за 5 шагов непонятно — сообщи
и спроси человека.
```

## Наблюдаемые действия и результаты

| Шаг | Действие | Наблюдение | Решение продолжить или остановиться |
|---|---|---|---|
| 1 | Проверить `GET /health` | 200 OK — сервис жив | продолжить (гипотеза: проблема на пути LLM) |
| 2 | Прочитать логи за период аномалии | все запросы с длительностью ≈ timeout 10 с, статусы 500; содержимое diff/ответа в логах отсутствует (OBS-1 соблюдён) | продолжить (гипотеза: зависает внешний LLM, ошибка не обработана) |
| 3 | Воспроизвести с моком LLM `sleep 15 с` | `review_service.py:21` вызывает `generate` без try/except и без таймаута → исключение → HTTP 500 | подтверждено (причина REL-1 нарушения) |
| 4 | Проверить наличие fallback и rate limit в коде | в коде нет `degraded=true`, нет 429, нет ограничения повторов | подтверждено (нет защиты при повторных сбоях) |
| 5 | Собрать отчёт: причина — синхронный вызов LLM без таймаута/обработки ошибки (REL-1); правки — fallback и rate limit в ADR/NFR | — | **Finish**, отчёт передан человеку |

## Что изменили в исходном артефакте

- Файл и раздел: `../practice_01/adr.md` — «Решение» (п.6 Fallback, п.7 Rate limit), «Нефункциональные требования (NFR)»
- Изменение: аномалия «500 при таймауте LLM» переведена в явные требования — fallback `degraded=true` (не 500), rate limit 429, timeout 10 с подтверждён как порог NFR
- Как проверили: воспроизвели шаг 3 с моком LLM `sleep 15 с` после внесения правок и убедились, что правило теперь покрыто тестом `tests_integration.md`
- Что отклонили: изменение продакшн-кода в рамках практики (правим только артефакты); любые действия, нарушающие OBS-1 (чтение содержимого diff/ответа); бесконечные ретраи при падении LLM
