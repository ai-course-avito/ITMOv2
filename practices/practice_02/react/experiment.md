# ReAct

- Цель: заполнить `react/project_management.md` конкретными инкрементами и DoD, увязанными с правилами из CASE.md, метриками из problem.md и тестами tests_*; исправить Гант; исключить плейсхолдеры и неподтвержденные допущения.
- Доступные входы: `../../practice_01/CASE.md`, `../../practice_01/problem.md`, `../../practice_01/tests_unit.md`, `../../practice_01/tests_integration.md`, `../../practice_01/tests_load.md`, `../../practice_01/tests_e2e.md`, `../blank_project_management.md`, `../prompts.md` (P1-02/P1-03), `../../practice_01/prompts.md`, `../../practice_01/TRAINING_PR.diff`.
- Разрешенные действия: читать указанные файлы; извлекать правила/метрики; предлагать инкременты и DoD, ссылаясь на tests_* и метрики; составлять диаграмму Ганта с зависимостями; останавливать работу и задавать вопрос человеку при отсутствии данных.
- Запрещенные действия: придумывать владельцев, даты-обязательства и факты прогона тестов; добавлять правила вне CASE.md; менять метрики problem.md; ссылаться на несуществующие файлы; использовать внешние источники.
- Максимальное число шагов: 6.
- Условие остановки и вопроса человеку: остановиться, когда заполнены все 3 раздела без плейсхолдеров и ссылки валидны; спросить «Нужно ли указывать владельцев/сроки? Источники их не содержат.»

## Запрос

```text
Ты — инженер-практик, работаешь по ReAct: Think -> Act -> Observe.

Goal: Заполнить plan поставки (project_management.md) для учебного
сервиса «AI-помощник ревьюера PR» на основе предоставленных артефактов.

Inputs:
- CASE.md (SEC-1, API-1: лимит 20 000 и 413, REL-1: timeout 10s,
  OUT-1: summary/risks<=3/checks, SCOPE-1, QA-1)
- problem.md (метрики: OUT-1 ≥95%, timeout ≥99%, 413 = 100%)
- tests_unit.md, tests_integration.md, tests_load.md, tests_e2e.md
- blank_project_management.md (структура)
- prompts.md (P1-02: подтвержденные риски file:line; P1-03: контекст)

Constraints:
- Не выдумывать владельцев/даты/факты прогонов; числа только из inputs.
- Ссылки — относительные к practice_01. Без плейсхолдеров.

Required Output (Markdown, только тело):
1) Таблица «Инкременты и ответственность» с колонками шаблона и
   конкретными DoD-проверками (ссылки на tests_* и метрики problem.md).
2) Корректная mermaid-диаграмма Ганта с последовательностями after.
3) «Как использовали AI»: 4 буллета; тип промпта — ReAct; ссылка на
   react/experiment.md; источники — P1-02, P1-03.

ReAct protocol:
Think: какие правила/метрики применимы; какие инкременты нужны.
Act[read]: читать нужный файл(ы).
Observe: выписать ключевые числа/требования.
Think: сопоставить DoD с tests_* и метриками.
Act[write]: сформировать Markdown-вывод в требуемой структуре.
Stop: когда все разделы заполнены и ссылки валидны.
Ask (если нужно): «Добавлять владельцев/сроки? В источниках их нет.»
```
