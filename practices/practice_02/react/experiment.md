# ReAct

- Цель: Переработать черновик нагрузочного тестирования `practices/practice_01/tests_load.md`, расширить тестовое покрытие с привязкой к реальным правилам сервиса, исключить заглушки и сохранить результат в `practices/practice_02/react/test_load_new.md`.
- Доступные входы: `practices/practice_01/tests_load.md`, `practices/practice_01/context.md`, `practices/practice_01/CASE.md`.
- Разрешённые действия: Чтение исходных файлов через инструменты файловой системы, анализ требований и правил, синтез плана, итеративная запись и проверка готового файла.
- Запрещённые действия: Использовать внешние непроверенные предположения об архитектуре (Kafka, очереди, тяжелые SQL-базы), оставлять пропуски (`...`) или нечисловые критерии приемки.
- Максимальное число шагов: 5.
- Условие остановки и вопроса человеку: Документ сформирован без заглушек, проверен по структуре и сохранен по пути `practices/practice_02/react/test_load_new.md`. Если обнаружены противоречия в требованиях — запросить уточнение.

## Запрос

Используй цикл ReAct (Reasoning + Acting) для переработки плана нагрузочного тестирования:
1. Thought: Исследуй исходный файл `tests_load.md` и контекст системы `context.md`, чтобы определить дефицит покрытия и ключевые продуктовые ограничения.
2. Action: Извлеки правила системы (API-1, REL-1, SEC-1, OUT-1, OBS-1) и параметры нагрузки.
3. Thought: Спроектируй матрицу сценариев, закрывающую базовую нагрузку, стресс, спайки, soak и проверки специфических бизнес-правил под нагрузкой.
4. Action: Запиши сформированный план в `practices/practice_02/react/test_load_new.md`.
5. Thought & Observation: Проверь созданный файл на отсутствие заглушек, корректность структуры колонок и полноту блока Evidence.
