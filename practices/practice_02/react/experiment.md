# ReAct

- Цель: Найти и исправить логический пробел в описании процесса TO BE.
- Доступные входы: файл `@practices/practice_01/analysis.md`
- Разрешённые действия: `READ`, `THINK`, `FIX`
- Запрещённые действия: Запрашивать внешние API.
- Максимальное число шагов: 4
- Условие остановки и вопроса человеку: Найден упущенный шаг обработки ответа от LLM и предложено изменение.

## Запрос

```
Цель: Найти и исправить логический пробел в описании процесса TO BE.
Доступные входы: файл @practices/practice_01/analysis.md
Разрешённые действия: 
1. READ(file) — прочитать файл
2. THINK(thought) — сделать логический вывод
3. FIX(file, change) — описать, что нужно изменить
Запрещённые действия: Запрашивать внешние API.
Максимальное число шагов: 4
Условие остановки: Найден упущенный шаг обработки ответа от LLM и предложено изменение.

Запрос:
Выполни шаги ReAct, чтобы найти логический пробел в блок-схеме "TO BE" файла analysis.md. 
Подсказка: Что происходит после шага "LLM -- OK --> Resp", если сам LLM возвращает сломанный JSON, нарушающий OUT-1?
```

## Наблюдаемые действия и результаты

| Шаг | Действие | Наблюдение | Решение продолжить или остановиться |
|---|---|---|---|
| 1 | `READ`(`practices/practice_01/analysis.md`) | Получено содержимое файла со схемой TO BE | Продолжить |
| 2 | `THINK` | В схеме отсутствует валидация ответа LLM на соответствие схеме OUT-1. Если ответ невалиден, поток идёт к ревьюеру. Нужен шаг проверки OUT-1. | Продолжить |
| 3 | `FIX`(`practices/practice_01/analysis.md`, "добавить проверку OUT-1") | Предложено заменить прямую связь `LLM -> Resp` на ромб `OUT{Проверка OUT-1}` с ветками "валиден" и "невалиден (422)" | Остановиться, пробел найден |

## Что изменили в исходном артефакте

- Файл и раздел: `practices/practice_01/analysis.md` (раздел «TO BE»)
- Изменение: В Mermaid-схему процесса TO BE добавлен блок проверки валидности ответа (`OUT-1`). При невалидном JSON теперь явно возвращается HTTP 422 вместо пропуска сломанного ответа дальше.
- Как проверили: Схема перечитана глазами, все стрелки сходятся, новый ромб корректно описывает бизнес-логику валидации (Pydantic ValidationError возвращает 422).
- Что отклонили: Не отклоняли, вывод модели был точным.
