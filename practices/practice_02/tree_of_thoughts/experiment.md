### Итоговый отчёт

#### Контекст
Анализируем practices/practice_01/TRAINING_PR.diff: добавлен POST /api/reviews в app/api.py и метод review в app/review_service.py. Цель — минимальными правками повысить предсказуемость и устойчивость API.
#### Изменения

1) Контракт и валидация
- Ввести модели:
  - ReviewRequest: поле `diff: constr(min_length=1, max_length=N)`.
  - ReviewResponse: поле `comment: str`.
- В обработчике POST /api/reviews указать `response_model=ReviewResponse` и принимать `payload: ReviewRequest`.

2) Ограничения и обработка сбоев
- В ReviewService задать `MAX_DIFF_CHARS = N` и проверять длину входа.
- Оборачивать `llm.generate` в try/except; маппировать ошибки на HTTP 502.

3) Надёжность промпта к LLM
- Формировать промпт с явными границами содержимого diff:
  ```
  Review this pull request and find problems.
  Diff:
  ```
  {diff}
  ```
  ```
  Это снижает влияние инъекций внутри диффа.

#### Проверка
1. POST /api/reviews с {} → 422 Unprocessable Entity.
2. /docs показывает схему запроса/ответа для эндпоинта.
3. POST с diff длиной > N → 413/422; с валидным diff → 200 и `{ "comment": "…" }`.
4. Имитировать исключение в llm.generate → 502 с детальным сообщением «LLM service error».

#### Что не делаем
- Не переводим эндпоинт в async и не меняем модель DI — вне цели минимальных правок.
- Не внедряем аутентификацию/лимитирование — зависит от инфраструктуры.
