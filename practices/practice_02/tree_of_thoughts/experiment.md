# Tree of Thoughts

- Решение, для которого нужны альтернативы: стратегия нагрузочного тестирования LLM-вызова в первом инкременте
- Критерии выбора: скорость внедрения, сложность, риск нарушения SLA, соответствие CASE.md

## Запрос

Предложи 3 альтернативы для нагрузочного тестирования LLM-вызова (A: локальный прогон `tests_load.md` через `pytest` + `httpx`; B: выделенный load-стенд с Locust/k6; C: очереди/воркер с нагрузкой через брокер). Оцени по скорости внедрения, сложности, риску SLA, соответствию CASE.md. Заполни таблицу кратко.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A: локальный прогон `tests_load.md` (`pytest` + `httpx`) | Минимум изменений; быстрое внедрение; легко проверить API-1, REL-1, OUT-1 | Ограниченная масштабируемость; нет распределённой нагрузки | Скорость: высокая; Сложность: низкая; Риск SLA: средний; Соответствие CASE.md: высокое |
| B: выделенный load-стенд (Locust/k6) | Реалистичный профиль нагрузки; метрики latency | Больше кода и инфраструктуры; выше порог входа | Скорость: средняя; Сложность: средняя/высокая; Риск SLA: низкий; Соответствие: высокое |
| C: нагрузка через очередь/воркер | Надёжность, ретраи, нет блокировок | Инфраструктурные накладные, задержка ответа | Скорость: низкая; Сложность: высокая; Риск SLA: низкий; Соответствие: высокое |

## Выбор

- Выбранная альтернатива: A
- Почему: минимальные изменения в срок; покрывает CASE.md; позволяет быстро достичь измеримых улучшений
- Как проверим: прогоним `tests_load.md`; проверим, что соблюдены SEC-1, API-1, REL-1, OUT-1
