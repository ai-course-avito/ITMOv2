# Tree of Thoughts

- Решение, для которого нужны альтернативы: способ интеграции AI-ревьюера PR (как внешний код получает доступ к сервису ревью на базе LLM)

- Критерии выбора:
  1. Возможность централизованно фильтровать секреты и применять Context Pack (SEC-1, QA-1)
  2. Контроль timeout и контролируемой ошибки (REL-1)
  3. Разделение ревью-пайплайна и CI (SCOPE-1)
  4. Сложность и стоимость первого инкремента (низкая — лучше)
  5. Масштабируемость при росте числа ревью

## Запрос

```text
Сравни 3 варианта интеграции AI-ревьюера PR:
A) прямой вызов LLM из процесса CI;
B) асинхронный воркер через очередь задач;
C) локальный прокси-микросервис (FastAPI /api/reviews).
Сначала ВНЕШНЕ опиши каждый вариант (состав, потоки, риск), затем оцени по
5 критериям (каждый 1–5): централизация SEC-1/QA-1, контроль REL-1,
разделение CI (SCOPE-1), сложность инкремента (чем ниже, тем выше балл),
масштабируемость. Выбери вариант для первого инкремента и назови условие
перехода к следующему. Скрытые рассуждения не выводи — только таблицу
и вердикты.
```

## Варианты решения

| Альтернатива | Плюсы | Минусы | Оценка по критериям (1–5, сумма) |
|---|---|---|---|
| A: прямой вызов LLM из CI | нулевая инфраструктура, минимум кода | CI блокируется на время вызова; фильтр SEC-1 и rate limit нельзя централизовать (дублируются по джобам); секреты из diff видны в логах CI; таймаут ограничен джобой CI | SEC-1/QA-1:2, REL-1:1, SCOPE-1:3, сложность:5, масштаб:1 → **2,4** |
| B: асинхронный воркер через очередь | не блокирует CI; retries и масштабирование; отличен при потоке ревью | очередь + воркеры + состояние; результат не мгновенный; избыточно для первого сценария | SEC-1/QA-1:4, REL-1:5, SCOPE-1:4, сложность:2, масштаб:5 → **4,0** |
| C: локальный прокси-микросервис | один фасад: фильтры, timeout, rate limit, формат; переиспользуется из CI и IDE; рост в B без переписывания | ещё один сервис и контур; небольшой оверхед | SEC-1/QA-1:5, REL-1:5, SCOPE-1:5, сложность:4, масштаб:4 → **4,6** |

## Выбор

- Выбранная альтернатива: **C — локальный прокси-микросервис** (`POST /api/reviews`, FastAPI)
- Почему: централизует SEC-1/API-1/REL-1 и Context Pack (QA-1) в одном месте, сохраняет синхронный запрос с timeout 10 с для первого сценария и даёт путь роста — переход к воркеру B происходит без смены контракта API
- Как проверим: E2E-сценарии `../practice_01/tests_e2e.md`; воспроизводимость через curl (413 при >20 000, `[REDACTED]` для секретов, контролируемый ответ при мок-отказе LLM)
