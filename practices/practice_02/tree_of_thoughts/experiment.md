# Tree of Thoughts

- Решение, для которого нужны альтернативы: как покрыть E2E-тестами эндпоинт POST `/api/reviews` с учётом правил CASE (API-1, OUT-1, OBS-1, REL-1).
- Критерии выбора: полнота (все ли правила CASE учтены), воспроизводимость (можно ли повторить), реалистичность (не выходит ли за scope).

## Запрос

Примени Tree of Thoughts: предложи 3 альтернативных подхода к E2E-тестам эндпоинта. Для каждого — сценарии, оценка по критериям. Выбери лучший и обоснуй.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A. Контракт + границы + логи (стаб LLM) | Полностью покрывает API-1, OUT-1, OBS-1, REL-1; детерминированно за счёт стаба | Требует управляемого стаба LLM | Полнота: высокая; Воспроизводимость: высокая; Реалистичность: высокая |
| B. Property-based тесты | Покрывает инварианты и границы | Требует генераторов; нужен фиксированный сид; для учебной практики избыточно | Полнота: средняя/высокая; Воспроизводимость: средняя; Реалистичность: средняя |
| C. Минимальный smoke | Простые сценарии; быстро | OBS-1 и REL-1 не покрыты; ценность ограничена | Полнота: низкая; Воспроизводимость: высокая; Реалистичность: высокая |

## Выбор

- Выбранная альтернатива: A — контрактные проверки с управляемым стабом LLM.
- Почему: полностью закрывает правила CASE, детерминирована за счёт стаба, не требует внешних интеграций.
- Как проверим: сверка сценариев с API-1, OUT-1, OBS-1, REL-1; проверка Evidence на воспроизводимость.
