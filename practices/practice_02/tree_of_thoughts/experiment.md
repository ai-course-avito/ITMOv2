# Tree of Thoughts

- Решение, для которого нужны альтернативы: стратегия обработки LLM-вызова в первом инкременте
- Критерии выбора: скорость внедрения, сложность, риск нарушения SLA, соответствие CASE.md

## Запрос

Предложи 3 альтернативы для обработки LLM-вызова (A: sync+threadpool; B: полный async стек; C: очереди/воркер). Оцени по скорости внедрения, сложности, риску SLA, соответствию CASE.md. Заполни таблицу кратко.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A: sync FastAPI + threadpool + Pydantic | Минимум изменений; быстрое внедрение; легко проверить SEC-1, API-1, REL-1, OUT-1 | Масштабируемость ограничена; ручное управление таймаутами | Скорость: высокая; Сложность: низкая; Риск SLA: средний; Соответствие CASE.md: высокое |
| B: Полный async стек | Лучшая масштабируемость; естественные таймауты | Больше кода, выше порог входа | Скорость: средняя; Сложность: средняя/высокая; Риск SLA: низкий; Соответствие: высокое |
| C: Очереди/воркер (Celery/RQ) | Надёжность, ретраи, нет блокировок | Инфраструктурные накладные, задержка ответа | Скорость: низкая; Сложность: высокая; Риск SLA: низкий; Соответствие: высокое |

## Выбор

- Выбранная альтернатива: A
- Почему: минимальные изменения в срок; покрывает CASE.md; позволяет быстро достичь измеримых улучшений
- Как проверим: прогоним tests_integration/e2e; проверим, что соблюдены SEC-1, API-1, REL-1, OUT-1
