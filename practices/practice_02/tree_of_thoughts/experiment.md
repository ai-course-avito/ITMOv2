# Tree of Thoughts

- Решение, для которого нужны альтернативы: в каком слое проверять установленный API-1 лимит 20 000 символов.
- Критерии выбора: соответствие API-1, ранний отказ, защита при обходе endpoint, отсутствие лишнего дублирования, тестируемость.

## Запрос

Сравни три места проверки одного контракта API-1: только на границе API; только в Review Service; на границе API и защитно в Review Service. Все варианты обязаны принимать 20 000 символов и возвращать 413 при 20 001. Оцени каждый вариант по одинаковым критериям и выбери один.

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A. Только API | Ранний 413, ясный контракт, простая integration-проверка | Вызов service в обход endpoint останется без защиты | 4/5 |
| B. Только Review Service | Защищает все вызовы service | Поздний отказ; граница API не отражает контракт явно | 3/5 |
| C. API + защитная проверка в service | Ранний отказ и защита при обходе endpoint; один общий валидатор | Небольшое дублирование вызова проверки | 5/5 |

## Выбор

- Выбранная альтернатива: C (двухслойная защита: проверка лимита на границе API и защитная проверка в сервисе), при этом лимит — 20 000 символов, 413 при превышении.
- Почему: соответствует API-1 и повышает устойчивость при обходе граничного слоя; контракт ясен, дублирование минимально (дешёвая вторичная проверка в сервисе).
- Как проверим: юнит‑тест на функцию проверки валидации и на защитную проверку сервисного слоя; интеграционный тест 413 на API.
