Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Решение, для которого нужны альтернативы:
  Политика работы с протухшим кэшем координат.
- Критерии выбора:
  латентность для мобильных клиентов, устойчивость при ошибках внешних API, простота реализации, предсказуемость поведения.

## Запрос


"Предложи 3 альтернативы стратегии работы со stale кэшем: A) жёсткая инвалидация и блокирующая ревалидация; B) stale-while-revalidate; C) всегда свежие данные (без использования stale). Оцени по критериям и порекомендуй, что включать в Gherkin."

## Варианты решения

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A | Всегда актуальные данные | Высокая латентность при истечении TTL; повышенный риск 5xx при сбоях внешних API | Низкая по мобильной латентности |
| B | Низкая латентность; устойчивость к сбоям; предсказуемость | Нужна маркировка статуса «stale» и фоновая задача | Высокая по всем критериям |
| C | Простота реализации | Нет гарантий актуальности; возможны длительные периоды устаревших данных | Средняя, риски для качества данных |

## Выбор

- Выбранная альтернатива:
  B) stale-while-revalidate.
 - Почему:
  лучший баланс латентности и устойчивости; соответствует mobile-first и позволяет избегать 5xx.
 - Как проверим:
  наличие Gherkin-сценария про stale и фоновой ревалидации в product_management.md.
