## Mapping (фрагмент → правило → метрика)

- «Базовый (1 RPS, 5 мин; p95 ≤ 500 мс, ошибки ≤1%)» → OUT-1 (стабильный контракт), REL-1 (устойчивость без LLM) → P95 ≤ 500 мс; 422/500 < 1%.
- «Пиковый (5 RPS, 10 мин; p95 ≤ 1.5 с)» → REL-1 (таймаут и контролируемый ответ) → P95 ≤ 1.5 с; ошибки ≤ 2%.
- «Стресс (рост до 10 RPS; graceful degradation 413/контролируемые ответы)» → API-1 (413 при >20000), REL-1 (контролируемый ответ) → error/drop rate под контролем.
- SEC-1 (редакция секретов) под нагрузкой → SEC-1 → «0 инцидентов утечки».

## Gherkin

```gherkin
@OUT-1
Scenario: Базовая нагрузка без LLM укладывается в P95
  Given нагрузочное тестирование POST "/api/reviews" без вызова LLM
  And профиль нагрузки 1 RPS в течение 5 минут
  When отправляем валидные тела { diff: string }
  Then P95 времени ответа ≤ 500 мс
  And доля 422/500 ≤ 1%

@REL-1
Scenario: Пиковая нагрузка с таймаутами даёт контролируемые ответы
  Given профиль нагрузки 5 RPS в течение 10 минут
  And инжектируем таймаут LLM в 10% запросов (timeout 10с)
  When отправляем валидные тела
  Then P95 времени ответа ≤ 1.5 с
  And доля 5xx ≤ 2%

@API-1 @REL-1
Scenario: Стресс-нагрузка с деградацией на 413 и фолбэк
  Given ступенчатый рост нагрузки 5→10 RPS
  And для 20% запросов длина diff = 20001 символов
  And для 10% запросов эмулируем таймаут LLM (10с)
  When запускаем тест 10 минут
  Then 100% запросов с diff > 20000 получают 413
  And ответы при таймауте не содержат 5xx (контролируемый фолбэк)

@SEC-1
Scenario: Редактирование секретов под нагрузкой
  Given профиль нагрузки 2 RPS в течение 5 минут
  And 30% тел содержат фейковые секреты (например, "token=abc123")
  When выполняется препроцессинг перед отправкой в LLM
  Then утечки секретов = 0, все секреты в промпте заменены на "[REDACTED]"
```
