- Вопрос к источникам: как покрыть E2E-тестами POST `/api/reviews` строго по доступным источникам, с доказательствами?

## Разрешённые источники

| Файл или документ | Зачем нужен | Какой фрагмент используем |
|---|---|---|
| TRAINING_PR.diff | Текущая реализация API | app/api.py 35–37 (POST /api/reviews); app/review_service.py 19–22 (return comment) |
| context.md | Формат входа/выхода, риски | 24–26 (формат ответа); 34 (пример 200 OK); 10, 38 (риск KeyError) |

| CASE.md | Правила репозитория | SEC-1, API-1, REL-1, OUT-1, OBS-1; пример проверки 81–85 |

## Запрос

Составь E2E-сценарии для POST /api/reviews строго по источникам (TRAINING_PR.diff, context.md, problem.md, CASE.md). Для каждого сценария укажи Evidence с прямой ссылкой на файл+строки или правило CASE. Если утверждение нельзя подтвердить — не включай его.

## Ответ со ссылками на источники

7 сценариев:
1. Успешный POST (200 OK, comment) — TRAINING_PR.diff app/api.py 35–37, app/review_service.py 19–22
2. Отсутствует diff (KeyError) — context.md 10, 38; problem.md 7–8
3. diff > 20000 → 413 — CASE.md API-1
4. Маскировка секретов → [REDACTED] — CASE.md SEC-1
5. Таймаут LLM 10с → контролируемый ответ — CASE.md REL-1
6. Логи без содержимого diff — CASE.md OBS-1
7. Формат ответа summary/risks/checks — CASE.md OUT-1

## Что изменили в исходном артефакте

- Файл и раздел: `rag/tests_e2e.md`, таблица сценариев + раздел «Источники и доказательства»
