# RAG

- Вопрос к источникам: какие утверждения в [`analysis.md`](../../practice_01/analysis.md) подтверждают текущее поведение, какие задают целевые требования и какие выводы пока не имеют источника?

## Разрешённые источники

| Файл или документ | Зачем нужен | Какой фрагмент используем |
|---|---|---|
| [`TRAINING_PR.diff`](../../practice_01/TRAINING_PR.diff) | Подтвердить фактический процесс AS IS | `app/api.py:8–10` и `app/review_service.py:13–16` |
| [`context.md`](../../practice_01/context.md) | Подтвердить требования и границы TO BE | Context Pack: `SEC-1`, `API-1`, `REL-1`, `OUT-1`, `SCOPE-1`, `QA-1`, `OBS-1` |
| [`README.md`](../../practice_01/README.md) | Подтвердить задачу помощника и роль человека | Раздел «Учебный кейс: AI-помощник ревьюера PR» |

## Запрос

В analysis.md первой практики описан текущий и целевой процесс AI-ревью. Найди самое существенное неясное или неподтверждённое место. Ищи информацию только в TRAINING_PR.diff, context.md и README.md первой практики: запиши поисковые запросы, выбери релевантные фрагменты и отбрось неподходящие. Для каждого вывода укажи источник. Исправь analysis.md, потом заполни rag/experiment.md и строку RAG в prompts.md второй практики.

## Поиск и отбор фрагментов

| Поисковый запрос | Найденный фрагмент | Оценка релевантности | Решение |
|---|---|---|---|
| `payload`, `diff`, `review_service` | `app/api.py:8–10`: чтение `payload["diff"]` и вызов сервиса | Высокая: описывает вход и связь API с сервисом | Использовать для AS IS |
| `prompt`, `generate`, `comment` | `app/review_service.py:13–16`: prompt, вызов LLM и возврат `comment` | Высокая: описывает внешний вызов и текущий результат | Использовать для AS IS |
| `SEC-1`…`OBS-1` | Семь требований в Context Pack файла `context.md` | Высокая: явные требования TO BE и границы процесса | Использовать для TO BE |
| `snake_case`, `i18n` | Ограничения, прямо отмеченные в Context Pack как нерелевантные | Нулевая: не относятся к backend-diff | Отклонить |

## Ответ со ссылками на источники

Текущее поведение API и `ReviewService` подтверждается строками `app/api.py:8–10` и `app/review_service.py:13–16` в [`TRAINING_PR.diff`](../../practice_01/TRAINING_PR.diff). Ограничение размера, редактирование секретов, timeout, структура результата, границы полномочий и допустимый состав логов заданы в [`context.md`](../../practice_01/context.md). Источники не определяют ответ для отсутствующего поля `diff`, обработку ответа с нарушением `OUT-1` и обязательные события логирования. Чтобы отделить факты от требований и неизвестного, в `analysis.md` добавлена карта источников.

## Что изменили в исходном артефакте

- Файл и раздел: [`practice_01/analysis.md`](../../practice_01/analysis.md), новый раздел «Карта источников».
- Изменение: для частей процесса добавлены отдельные ссылки на подтверждения, тип утверждения и статус; неизвестные контракты отделены от AS IS и TO BE.
- Как проверили ссылки: относительные пути открываются; строки diff содержат endpoint и вызов LLM; все семь идентификаторов находятся в Context Pack.
- Что отклонили как неподтверждённое: правила про `snake_case` и i18n; конкретный HTTP-ответ для нестрокового `diff`, обработку нарушения `OUT-1` и обязательное логирование каждой ветви.
