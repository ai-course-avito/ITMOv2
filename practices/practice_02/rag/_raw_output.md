## Важное уточнение по статусу утверждений 3–5

В самом начале раздела AS IS файл analysis.md прямо указывает: «В CASE.md статистика процесса ревью PR до появления сервиса-помощника не приводится». Это означает, что весь AS IS-процесс (включая пункты 3, 4, 5) не взят из CASE.md как факт, а реконструирован в analysis.md. Формально цитаты для пунктов 3–5 внутри analysis.md есть и совпадают дословно, поэтому по критерию «есть точная цитата из одного из трёх файлов» они отмечены как «подтверждено источником». Но по сути это не независимо подтверждённые факты о реальном процессе, а логические следствия из правил CASE.md (`OUT-1`, `QA-1`, `SCOPE-1`) и предположения, оформленные в analysis.md как повествовательное описание AS IS без явной пометки «(допущение)» (в отличие от пунктов 1 и 2, где пометка «(допущение)» стоит явно).

## Вывод: какие утверждения нельзя использовать как основание для метрик

- **Утверждение 1** (3–6 часов до первого комментария) — нельзя использовать как основание для метрик: это явное допущение, число не взято из CASE.md.
- **Утверждение 2** (5 разработчиков, 10–15 PR в неделю) — нельзя использовать как основание для метрик: это явное допущение, в CASE.md состав команды и объём PR не описаны.
- **Утверждения 3, 4, 5** (отсутствие чек-листа, свободная форма комментариев, ревьюер сам делает approve/merge) — использовать с оговоркой: дословная цитата есть в analysis.md, но сам этот раздел построен как реконструкция процесса AS IS (текст об этом сообщает напрямую: статистика и процесс до сервиса в CASE.md не приведены), а не как перечисление фактов, зафиксированных в CASE.md. Как численную/фактологическую основу для метрик их брать нельзя; как формулировку рабочей гипотезы для TO BE-сравнения (в привязке к правилам `OUT-1`, `QA-1`, `SCOPE-1`) — можно, поскольку в этой роли они и используются в самом analysis.md (раздел «Разница»).
