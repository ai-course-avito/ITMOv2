# Практика 3 — локальный помощник по проекту

## Окружение и модель

Я проверял локального помощника на ноутбуке с Intel Core i5-13420H (8 ядер, 12 потоков), встроенной Intel UHD Graphics и 15 GiB оперативной памяти. Использовал Ollama 0.34.4, OpenCode 1.18.35 и Python 3.12.3. Запросы OpenCode шли в локальный Ollama по адресу `http://localhost:11434/v1`.

Итоговая модель — `itmo-agent` (ID `8a12723a963b`), собранная из `qwen3:4b-instruct`: 4.0B параметров, квантизация Q4_K_M, файл весов около 2.5 ГБ. Исходная модель допускает контекст до 262144 токенов, но для этой работы я ограничил рабочий контекст до 8192, а длину одного ответа — до 512 токенов. Небольшой контекст подходит для `demo/` и уменьшает расход памяти и задержку. В Modelfile заданы `temperature 0.7`, `top_p 0.8`, `top_k 20`; эти параметры соответствуют [рекомендациям разработчика модели](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507#best-practices).

`lab/Modelfile` и `lab/Modelfile.agent` содержат одинаковые параметры и общую инструкцию проверять утверждения по файлам. Я собрал модель командой:

```bash
ollama create itmo-agent -f practices/practice_03/lab/Modelfile.agent
```

В `lab/demo/opencode.json` выбран только `ollama/itmo-agent`. Агент `local-guide` может использовать `read`, `glob`, `grep`; остальные инструменты запрещены. `lab/demo/repo-system.txt` задаёт карту файлов проекта, но не содержит эталонных ответов. Время запроса OpenCode ограничено 120 секундами, число шагов агента — восемью. Modelfile ограничивает число генерируемых токенов, а не время выполнения.

## Эталоны и ответы локальной модели

Эталоны я составил заранее по исходным файлам `lab/demo/`. Каждый вопрос из `lab/QUESTIONS.md` задавался отдельно через `opencode run --agent local-guide --model ollama/itmo-agent` из каталога `lab/demo`. Эталоны и этот отчёт в тестовые сессии не передавались; модель получала доступ к файлам проекта через разрешённые инструменты.

Полные ответы и следы вызовов инструментов сохранены отдельно: [вопрос 1](results/question_1.json), [вопрос 2](results/question_2.json), [вопрос 3](results/question_3.json), [вопрос 4](results/question_4.json), [вопрос 5](results/question_5.json). Файлы сформированы из экспорта сессий OpenCode; абсолютные пути в них заменены на относительные.

### 1. Как запустить тесты?

**Эталон:** `make test` из `lab/demo/Makefile`; цель `test` запускает `python3 -m unittest -v`.

**Ответ модели:** «Тесты запускаются командой `make test`, которая выполняет `python3 -m unittest -v`. Источник: `Makefile`.» Модель вызвала `Read Makefile`. Время — 30.82 с. **Оценка: верно.**

### 2. Что будет при пустом имени подписчика?

**Эталон:** `subscribe` в `lab/demo/service.py` проверяет `if not name.strip():` и выбрасывает `ValueError("empty name")`. Строка из одних пробелов тоже считается пустой.

**Ответ модели:** «При пустом имени подписчика будет выброшено исключение `ValueError("empty name")`»; в подтверждение приведён фрагмент функции `subscribe` с проверкой `name.strip()`. Модель вызвала `Glob service.py` и `Read service.py`. Время — 21.54 с. **Оценка: верно.**

### 3. Где реализован `unsubscribe`?

**Эталон:** такой функции в `lab/demo/service.py` нет. Поиск `unsubscribe` по файлам `demo/` не даёт совпадений; предпосылка вопроса ложна.

**Ответ модели:** «Реализации `unsubscribe` в проекте не найдено». Модель использовала `Glob **/*.py` и `Grep unsubscribe` без совпадений. Время — 15.89 с. **Оценка: верно.** Прямой `Read` в этой сессии не вызывался; вывод основан на поиске.

### 4. Какая CI-система запускает тесты?

**Эталон:** в `demo/` нет сведений о CI-системе или конфигурации CI. `Makefile` задаёт локальную команду тестов, но не называет CI. Я также проверил список обычных и скрытых файлов `demo/`.

**Ответ модели:** «В файлах не найдено упоминаний о CI-системе. Тесты в файле `test_service.py` не содержат сведений о системе их запуска». Модель использовала `Glob` и `Grep CI`; совпадений не было. Время — 25.82 с. **Оценка: верно в пределах `demo/`.** Прямой `Read` в этой сессии не вызывался.

### 5. Сохраняются ли подписки после перезапуска?

**Эталон:** нет. `lab/demo/service.py` объявляет `subscribers = set()` в памяти процесса; сохранения на диск или в базу данных нет.

**Ответ модели:** «Нет, подписки не сохраняются после перезапуска процесса», с подтверждением `subscribers = set()` из `service.py`. Модель вызвала `Glob **/*.py` и `Read service.py`. Время — 34.37 с. **Оценка: верно.**

## Выводы и ограничения

На этих пяти вопросах смысловые ответы совпали с эталонами: **5 из 5**. В трёх сессиях модель открывала нужный файл через `Read`; в двух вопросах об отсутствии функции или CI использовала поиск. Это показывает, что OpenCode действительно вызывает инструменты для локальной модели, а не только печатает JSON вызова в ответе.

Проверка выполнена на маленьком учебном проекте `demo/`, по одному запуску на вопрос. Результат не доказывает такую же точность на более крупном репозитории или при повторных запусках. Для другого проекта нужно обновить карту файлов в `repo-system.txt` и заново проверить выбор источников. Заявления об отсутствии функции или CI ограничены файлами, доступными в проверяемом проекте.
