# Отчёт: локальный помощник по проекту `demo/`

## Железо и версии

| Параметр | Значение |
|---|---|
| Устройство | Apple M4, 16 GB unified memory |
| ОС | macOS 27.0 (26A428) |
| Ollama | 0.34.4 |
| OpenCode | 1.18.29 |
| Python для `make test` | 3.14 (Homebrew). Системный `python3` на macOS — 3.9.6, поэтому `lab/Makefile` сам ищет интерпретатор 3.10+ |

## Модель

| Параметр | Значение |
|---|---|
| Базовая модель | `qwen3.5:4b` (Ollama ID `2a654d98e6fb`), 4.7B параметров, архитектура `qwen35` |
| Квантизация | Q4_K_M, 3.4 GB на диске |
| Нативный контекст | 262 144 токенов |
| Чат-модель `itmo-local` (`Modelfile`) | `num_ctx 8192`, `num_predict 1024`, `temperature 0.2`, `top_p 0.9`, `top_k 20`, `repeat_penalty 1.05`, `seed 42`, SYSTEM с запретом выдумывать |
| Агентная модель `itmo-agent` (`Modelfile.agent`) | `num_ctx 65536`, `num_predict 4096`, те же параметры сэмплинга, без SYSTEM (его задаёт OpenCode из `demo/repo-system.txt`) |
| Память при работе агента | 5.6 GB, 100% GPU (`ollama ps`) |

### Почему такой выбор

- **4B в Q4_K_M**: на 16 GB unified memory рядом с IDE и браузером умещаются вес модели и KV-кэш на 64k. 8B+ при таком контексте уже вытесняли бы память. 0.8B/2B слишком слабы для вызова инструментов.
- **Qwen 3.5** поддерживает tools и thinking. Без поддержки инструментов агент OpenCode не работает.
- **64k для агента**: системный промпт OpenCode и JSON-схемы инструментов сами съедают заметную часть окна, остальное уходит на прочитанные файлы. **8k для чата** хватает, потому что контекст — один README.
- **temperature 0.2 + seed 42**: ответы воспроизводимы. Повторные запуски Q4/Q5 дали слово в слово тот же вывод.
- **Скорость**: ~24–26 ток/с на генерации (`baseline.json`, `results/system.json`).

## Настройка OpenCode (`demo/opencode.json`)

- Провайдер только `ollama` (`enabled_providers`) на `http://localhost:11434/v1`, облачных API нет. `share: disabled`, `autoupdate: false`.
- У модели указаны `tool_call: true`, `reasoning: true`, лимиты 65536/4096 совпадают с `Modelfile.agent`.
- Агент по умолчанию `local-guide`: `"*": "deny"`, разрешены только `read`, `glob`, `grep`, `list`. `steps: 8`.
- Глобально запрещены `edit`, `bash`, `webfetch`, `websearch`, `external_directory`. Модель не может выйти из `demo/` и прочитать эталоны или отчёт.

## Пять вопросов через OpenCode

Процесс: эталоны составлены заранее по коду в `REFERENCES.md` (вне `demo/`). Каждый вопрос задавался в новой сессии:
`opencode run --agent local-guide -- "<вопрос>"` из `demo/`. Ответы лежат в `results/q1.md` … `results/q5.md`, повторы в `results/q4.run*.md` и `results/q5.run*.md`.

| # | Вопрос | Ответ модели | Эталон | Оценка |
|---|---|---|---|---|
| 1 | Как запустить тесты? | `make test`, `demo/README.md` строка 6 | `make test`, `README.md:6`, `Makefile` | **Верно.** Сначала искала `package.json`/`*.js` (привычка к JS-проектам), но в итоге прочитала README. `Makefile` не упомянула. |
| 2 | Пустое имя | `ValueError("empty name")`, цитаты `service.py:5-6` и `test_service.py:13-15` | То же | **Верно**, строки точные |
| 3 | Где `unsubscribe`? (ложная предпосылка) | «Функция `unsubscribe` отсутствует», есть только `subscribe` | Опровергнуть предпосылку | **Верно.** Не поддалась, лишь добавила домысел «возможно, планировалось в будущем». |
| 4 | Какая CI? (ответа нет в репо) | **Пустой ответ** в 3 из 3 запусков | «Сведений нет» | **Неверно (сбой агента)** |
| 5 | Сохраняются ли подписки после перезапуска? | «В директории нет файлов… подтвердить невозможно» в 3 из 3 запусков | Нет, `subscribers = set()` в памяти (`service.py:1`, `README.md:2`) | **Неверно**, ложное утверждение о пустой папке |

**Итог: 3 из 5 верно.** Оба «ловушечных» вопроса дали разный результат: ложную предпосылку (Q3) модель распознала, а вопрос без ответа (Q4) сломал агентный цикл.

### Разбор сбоев

- **Q4, пустой ответ.** Запуск с `--format json --thinking` показал, что модель пишет вызовы `grep`/`glob` *текстом внутри reasoning* (причём по-китайски), а настоящего tool call не делает. Шаг заканчивается, и финального текста нет. Это известная слабость маленьких thinking-моделей: формат вызова инструментов «протекает» в рассуждение. Та же модель в чат-режиме с `system.txt` на этот вопрос отвечает идеально, так что ломается именно агентная обвязка, а не знание.
- **Q5, неверный вывод из пустого поиска.** Модель ищет только `**/*.js` и `**/*.ts`, получает 0 совпадений и делает вывод «в директории нет файлов», не вызвав `list` и не поискав `*.py`. Системный промпт требует сначала читать файлы, но 4B-модель этому не следует. Ответ формально осторожный («подтвердить невозможно»), но основан на ложном факте.
- **Нестабильная задержка.** Первые запуски шли 14–30 с, повторы Q4/Q5 — 178–236 с при идентичном выводе. Время уходило на скрытое reasoning/повторную обработку контекста. Точную причину я не установил.

## Ограничения и выводы

1. 4B-модель годится для **точечных вопросов по коду**, когда файл нужно просто найти и процитировать (Q1–Q3), и хорошо следует запрету на выдумки в чат-режиме.
2. В **агентном режиме** слабое место — не знания, а дисциплина вызова инструментов: вызов прямо в reasoning, узкий поиск с неверным обобщением. Для надёжной работы нужна модель побольше (8B+/14B) либо отключение thinking для агента.
3. Ограничение прав (`read/glob/grep/list`, `external_directory: deny`) работает: тестируемая модель не видела эталонов, ничего не меняла и не запускала.
4. Модель по умолчанию «думает» как в JS-проекте (`package.json`, `*.js`/`*.ts`). Подсказка в `repo-system.txt` вида «проект на Python, начни с `list`» вероятно исправила бы Q1 и Q5, но это уже подгонка промпта под вопросы.
5. Цена локальности: 15–30 с на простой вопрос в лучшем случае и до 4 минут в худшем. Зато всё работает офлайн и код не покидает машину.
