### Вопрос 2
> Что будет при пустом имени подписчика? Подтверди кодом.

Ответ:
```
При пустом имени (или имени с пробелами) функция `subscribe` бросает исключение `ValueError` с сообщением `"empty name"`.

**Подтверждение из кода (`service.py`):**
```python
def subscribe(name):
    if not name.strip():  # Проверка на пустое имя после удаления пробелов
        raise ValueError("empty name")
    subscribers.add(name.strip())
    return {"subscribed": True}
```

**Подтверждение из теста (`test_service.py`):**
В тесте `test_empty` проверяется, что вызов `subscribe(" ")` вызывает `ValueError`.
```

### Вопрос 3

Ответ:
```
В предоставленных материалах реализация функции `unsubscribe` отсутствует.

**Предпосылка вопроса:** Функция `unsubscribe` не существует в коде проекта Notify Mini.

**Факты из материалов:**
*   В файле `service.py` определена только функция `subscribe`, которая добавляет имя в множество `subscribers`.
*   В тестовом файле `test_service.py` прописан тест `test_duplicate`, который проверяет отсутствие дубликатов при повторном вызове `subscribe`, но нет теста или кода для удаления подписки.
*   Функция `unsubscribe` не упоминается ни в одном из файлов (`README.md`, `Makefile`, `service.py`, `test_service.py`).
```

### Вопрос 5
> Сохраняются ли подписки после перезапуска процесса? Подтверди кодом.

Ответ:
```
Нет, подписки **не сохраняются** после перезапуска процесса.

Это следует из того, что в `service.py` переменная `subscribers` объявлена как глобальная, но не инициализирована внутри функции:
```python
# service.py
subscribers = set()  # Создается только один раз при запуске интерпретатора
```

При перезапуске процесса (например, через `make test`) переменная `subscribers` создается заново как пустое множество. Это подтверждается тестом `test_duplicate`, который очищает состояние перед каждым запуском:
```python
# test_service.py
def setUp(self):
    subscribers.clear()  # Очищается при каждом новом тесте (и перезапуске)
```
```
