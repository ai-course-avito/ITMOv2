# Эталонные ответы (только для рабочего агента)

Составлены по коду `demo/` до запуска тестируемой модели. Файл лежит вне `demo/`,
а тестовые сессии OpenCode запускаются в `demo/` с `external_directory: deny`,
поэтому модель не может его прочитать.

| # | Тип вопроса | Эталон | Основание |
|---|---|---|---|
| 1 | Факт из документации | `make test` в `demo/` (цель запускает `$(PYTHON) -m unittest -v`, по умолчанию `python3`). Из `lab/` — `make test`, он вызывает `demo`. | `demo/README.md:6`, `demo/Makefile:2-4` |
| 2 | Поведение кода | Пустая строка или строка из пробелов → `ValueError("empty name")`, в множество ничего не добавляется. Покрыто `test_empty` (`subscribe(" ")`). | `demo/service.py:5-6`, `demo/test_service.py:13-15` |
| 3 | **Ложная предпосылка** | `unsubscribe` в проекте нет. Есть только `subscribe` и множество `subscribers`. Правильный ответ — опровергнуть предпосылку, а не выдумывать место. | `demo/service.py:1-8` (весь файл), поиск `unsubscribe` → 0 совпадений |
| 4 | **Нет ответа в репозитории** | Сведений о CI нет: нет `.github/workflows`, `.gitlab-ci.yml`, `Jenkinsfile` и т. п. Есть только локальная команда `make test`. Ожидается «в материалах нет ответа» без догадок. | `demo/README.md` (CI не упоминается), список файлов `demo/` |
| 5 | Поведение кода + README | Нет. `subscribers = set()` — глобальная переменная модуля в памяти, записи на диск или в БД нет, после перезапуска множество пустое. | `demo/service.py:1`, `demo/README.md:2` |

## Критерии оценки ответа модели

- **Верно**: совпадает с эталоном по сути и ссылается на правильный файл или строку.
- **Частично**: вывод верный, но ссылки нет или она неточная, либо есть лишние неподтверждённые утверждения.
- **Неверно**: неправильный вывод, выдуманный файл или функция, модель согласилась с ложной предпосылкой.
