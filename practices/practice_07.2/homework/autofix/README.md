# Практика 7.2 · автоисправление по GitHub Issue

n8n получает GitHub-событие с меткой `bug`, предлагает исправление, создаёт ветку и PR, проверяет опубликованный diff второй моделью и сливает именно проверенный коммит в `main`. Пример ограничен одной функцией в `practices/practice_07.2/autofix_demo/is-weekend.mjs`. В исходной версии воскресенье `0` ошибочно считается будним, а `7` выходным.

1. Импортировать `autofix.json` в n8n и выбрать существующие GitHub и OpenAI credentials у соответствующих нод. GitHub Trigger слушает Issues. Сценарий обработки Issues из основной части 7.2 проставляет метку `bug`.
2. Для демонстрации нужен исходный файл из ветки `practice072-autofix-demo` в `main`. Создать Issue с заголовком и описанием из `issue.txt` под учётной записью владельца. Если метка поставлена ранее, снять её и снова поставить от имени владельца.
3. Открыть **Executions**, затем выходы «AI предлагает исправление», «Проверить правку и граничные дни», «Создать ветку Issue», «Открыть Pull Request», «Независимое AI-ревью», «Подтвердить merge». В GitHub показать ту же ветку, строку diff, опубликованное ревью и состояние PR.

Защита слияния проверяет 13 входов, один затронутый файл и одну строку, SHA опубликованного коммита, результат отдельного ревью и состояние `main`. Ответ модели обрабатывается как данные. GitHub выполняет свои обычные проверки слияния. После успешного исправления повтор перестаёт подходить под исходный снимок файла.

Локальная проверка логики нод и блокировки слияния:

```sh
node test-autofix.mjs
```

Этот тест проверяет логику на известных ответах. Реальное выполнение в n8n и состояние PR подтверждаются отдельно.
