## Практика 6: моделирование угроз и атаки на Mini Shop

Модель угроз — [`THREAT_MODEL.md`](./THREAT_MODEL.md) (markdown + mermaid). Кастомный промпт
для LLM-судьи — [`judge-system-prompt.md`](./judge-system-prompt.md).

### Отчёт 1 — атаки на исходный сервис

26/26 автоматических атак (`evidence/attack.py`) и forced-decision тест на AI-facade прошли на
немодифицированном `lab/service.py`. Подробности — [`REPORT_01.md`](./REPORT_01.md). Самое
серьёзное: `POST /assistant/execute` исполнял любой `{tool, arguments}` без проверки, что его
реально выдала LLM для этой сессии — прямой запрос с `delete_tree` на `"."` без какой-либо
авторизации уничтожал всю файловую песочницу.

### Фикс

- Роль/id только из серверной сессии (`sessions[token]`), не из заголовков/query.
- Параметризованный SQL везде, цена заказа — только из каталога, escape отзывов при рендере.
- `/assistant/execute` проверяет `read_file` против серверных грантов, выданных только легитимным
  `/assistant/context` для **своего** заказа; `export_profiles` — только `staff`; `delete_tree`
  запрещён через facade **всегда**, независимо от decision.
- Лимит попыток логина, отсутствие утечки внутренних деталей в ошибках.
- 19 новых регрессионных тестов (`lab/test_security.py`), по одной на каждую находку.

### Выводы

См. [`CONCLUSIONS.md`](./CONCLUSIONS.md) — 2 абзаца, можно вставить прямо сюда при открытии PR:

> В исходном сервисе AI-помощник работал через facade (`/assistant/execute`), но facade слепо
> исполнял любое решение модели — включая удаление всей файловой песочницы без какой-либо
> авторизации. Это тот же риск, что разбирали на занятии на примере Ozoo Fresh: отсутствие
> прямого доступа LLM к инфраструктуре не защищает систему, если граница между "решением модели"
> и "реальным действием" не проверяется отдельно. Помимо этого в сервисе нашлось ещё 25
> классических проблем — IDOR, SQL injection, подмена роли через клиентский заголовок,
> манипуляция ценой заказа, stored XSS, утечка паролей и путей во внутренних ошибках, отсутствие
> защиты от брутфорса логина.
>
> Исправление строит доверие к AI-facade по-другому: сервер сам выдаёт временный грант на один
> конкретный путь и один заказ при легитимном обращении к `/assistant/context`, а исполнение
> проверяется против этого гранта независимо от того, что вернула модель; разрушительный
> инструмент (`delete_tree`) из facade убран полностью. Все остальные находки закрыты
> стандартными мерами (параметризованный SQL, авторизация по сессии вместо клиентских
> заголовков, server-side цена, escape вывода, лимит попыток логина). После фикса все 26
> воспроизведённых атак заблокированы, функциональность (свой профиль/чек/заказ, расширенные
> права сотрудника) сохранена, тесты проходят.
