# Отчёт 1. Атаки на исходный сервис

Объект — `lab/service.py` в исходном виде (коммит `main`, 165 строк).
Всё выполнялось только против своего локального процесса на `127.0.0.1:8066`
и его синтетических данных (`TEST_*`, `example.invalid`), внешних адресов
не использовалось. Модель угроз — [`threat-model.md`](threat-model.md) (схема —
[`threat-model.png`](threat-model.png)).

## Как искали и как подтверждали

1. **Чтение кода и модель угроз.** Сначала код разобран по потокам данных:
   каждая точка входа (маршрут, заголовок, поле тела, параметр запроса) и каждое
   место, где недоверенный ввод доходит до SQL, файла, HTML, prompt или
   исполнителя решений. Из этого получилась таблица STRIDE (T01–T22).
2. **Воспроизведение по HTTP** на запущенном исходном стенде:
   [`evidence/repro.py`](evidence/repro.py) делает по одному запросу на угрозу и
   печатает, подтвердилась ли она. Вывод:
   [`evidence/repro-before.txt`](evidence/repro-before.txt) — **подтверждено 25 из 25**
   проверок.
3. **Красные тесты.** Для каждой угрозы написан тест в
   [`lab/test_security.py`](lab/test_security.py). На исходном сервисе: 47 тестов,
   **60 падений и 4 ошибки** (64 записи с учётом подтестов)
   ([`evidence/security-red.txt`](evidence/security-red.txt)); поставляемые 16 тестов
   стенда на исходном коде зелёные.
4. **Независимый судья** (отдельный агент с пустым контекстом, промпт —
   [`judge-system-prompt.md`](judge-system-prompt.md)) проверил полноту модели
   угроз по исходному коду. Первый вердикт — `reject`: нашёл угрозы, которых в
   первой версии модели не было (T17–T21), и ряд неточных формулировок.
   Дословно — [`evidence/judge-verdict-1.json`](evidence/judge-verdict-1.json).

Моя первая полезная нагрузка для поиска по имени (`x' OR '1'='1`) **не
сработала** — хвостовой `%'` в запросе ломает условие; это ошибка примера, а не
отсутствие дыры. С другим вариантом проблема подтвердилась (T03).

## Часть с реальной моделью не выполнена

Схема «prompt injection на реальной модели» из `lab/README.md` (запуск
`shop-planner` в OpenCode до и после отзыва с вредоносной инструкцией) **не
проводилась**: шлюз VseLLM с 22.10 отвечает `HTTP 402` (лимит ключа курса,
пополнить его я не могу), локальная Ollama не запущена. Поэтому в отчёте нет
наблюдения «модель послушалась или отказалась». Есть то, что от неё не
зависит: решения подавались на `/assistant/execute` принудительно (T10–T12,
T18), то есть проверялась защита сервера, а не поведение модели. README
прямо называет это отдельным тестом доступа, который не доказывает, что модель
поддалась инъекции.

## Что осталось за рамками

- Инструменты поиска работали без OpenCode: я вёл агентскую часть напрямую
  (VseLLM недоступен), по тем же правилам стенда.
- Угроза T20 (рост памяти и зависший клиент) воспроизводилась только тестами,
  не нагрузкой по сети.
