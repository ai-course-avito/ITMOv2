# REPORT_02 — Blue Team фиксация уязвимостей

## 1. Что исправлено

Внесены изменения в practices/practice_06/lab/service.py для закрытия основных векторов атак:

- Параметризованные запросы и запрет IDOR:
  - `/profile` и `/orders` используют id из сессии (`session["id"]`), игнорируя query-параметры. Запросы параметризованы.
  - `/search` и `/assistant/context` переписаны на параметризованные SQL-запросы (`?` + `self.db.execute(..., params)`).
- Подмена роли (X-Role):
  - `/admin/export` проверяет только `session["role"] == "staff"`. Заголовок `X-Role` больше не учитывается.
- Изменение цены (Tampering):
  - `POST /orders` берёт цену только из каталога `self.products[product]`. Поле `price` из тела игнорируется.
- Path Traversal и защита ассистента:
  - `GET /files` разрешает чтение только в каталоге пользователя `files/{username}/...`, сопоставляя сессии и запрошенный user.
  - `POST /assistant/execute` добавлены проверки прав:
    - `read_file` и `delete_tree` — только в `files/{session_user}/...`.
    - `export_profiles` — только если роль `staff`.
  - `GET /assistant/context` теперь возвращает данные, обёрнутые в теги (`<review_data>`, `<order_data>`, `<user_question>`), чтобы снизить риск prompt injection.

Сохранена функциональность: покупка, отзывы, чтение своих файлов и ассистент для собственных данных работают.

## 2. Результаты повторных атак

Повторный прогон скрипта атак сохранил вывод в `practices/practice_06/evidence/after/attack_results.txt`. Ключевые фрагменты:

- IDOR (профиль bob через alice):
  - Статус `200`, но вернулся профиль alice (id=1) — чужие профили недоступны.
- Подмена роли (X-Role: staff без логина):
  - Статус `403`, ошибка `staff only` — доступ закрыт.
- Изменение цены (покупка стула за 1):
  - Статус `201`, цена в заказе `5000` — принудительно каталожная.
- Path Traversal (../../private/operator-note.txt):
  - Статус `401`, `login required` при прямом вызове без токена; с токеном доступ к приватному каталогу вне `files/{user}` блокируется.

Полный вывод см. в `practices/practice_06/evidence/after/attack_results.txt`.

## 3. Вывод

Закрыты уязвимости:

- IDOR: доступ к профилям и заказам строго по сессии пользователя.
- SQL-инъекции: все динамические запросы переписаны на параметризованные.
- Подмена роли: авторизация админских действий основана на сессии и роли, заголовок `X-Role` игнорируется.
- Изменение цены: цена заказа берётся только из каталога, попытки подмены игнорируются.
- Path Traversal: чтение и операции файлов разрешены только в `files/{session_user}/...`; ассистент ограничен теми же правилами.

Итог: сервис корректно отбивает продемонстрированные ранее атаки. Базовый функционал (покупки по каталогу, публикация и просмотр отзывов, чтение своих чеков, ассистент для собственных данных) сохранён и покрыт тестами. Все тесты прошли успешно.
