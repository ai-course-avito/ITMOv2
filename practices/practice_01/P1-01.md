## P1-01

Проанализирую PR по диффу.
Проблемы:
1. Нет валидации входных данных — payload принимается как dict без проверки наличия ключа "diff". Если его нет — KeyError.
2. Нет типизации payload — параметр payload: dict без TypedDict или Pydantic модели. Нет автодocomplete, нет валидации.
3. Нет обработки ошибок LLM — если llm.generate() бросит исключение, пользователь получит 500 без информативного сообщения.
4. prompt уязвим к инъекции — дифф подставляется в промпт напрямую без какой-либо санитизации. Пользователь может передать произвольный контент, меняющий поведение LLM.
5. Нет HTTP-статуса 201 — POST endpoint для создания ресурса должен возвращать 201 Created, а не 200.
6. Нет маппинга ошибок — нет HTTPException для случаев, когда LLM недоступен или вернул ошибку.
7. Нет документации — нет response_model, нет описания endpoint'а. Swagger будет бесполезен.
Рекомендация: использовать Pydantic модель для request/response и добавить обработку ошибок:
# models.py
from pydantic import BaseModel

class ReviewRequest(BaseModel):
    diff: str

class ReviewResponse(BaseModel):
    comment: str
