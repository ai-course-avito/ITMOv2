# P1-01 Baseline Review Findings

Source: practices/practice_01/TRAINING_PR.diff

Findings (ordered by severity)

Critical

- app/api.py: `create_review` accepts a plain `dict` body and directly indexes `payload["diff"]`. Missing field leads to `KeyError` and 500 instead of FastAPI validation (422). Use a Pydantic model and response_model.
  - Diff lines 35-38.

- app/review_service.py: No size/guardrails on `diff`; very large diffs can cause slow/expensive LLM calls, timeouts, or DoS.
  - Diff lines 19-22.

High

- app/api.py: No error handling around LLM call; exceptions bubble to 500 without clear error schema.
  - Diff lines 35-38.

- app/api.py: Synchronous endpoint calling a blocking LLM; can block worker threads. Consider `async` route and running blocking call in a threadpool or using an async client.

- app/review_service.py: Prompt injection risk; raw diff interpolated into prompt. Use clear system prompt, delimiters, and instructions that treat diff as data only.

Medium

- app/api.py: Bare dict body loses schema in OpenAPI; define `BaseModel` request and set `response_model` for better docs.

- app/review_service.py: Returns loose `dict[str, str]` with `comment`; define a typed response (TypedDict or Pydantic) to standardize clients.

- app/review_service.py: Prompt is vague; specify output format (list of findings with severity, file/line) for consistent downstream parsing.

Low

- app/review_service.py: Style-only change to Protocol method body; functionally equivalent.

Notes/Assumptions

- Assumes Python >=3.9 due to `dict[str, str]` typing. If older versions are supported, replace with `Dict[str, str]`.

Suggested Remediations (summary)

- Define `ReviewRequest(BaseModel)` with `diff: constr(min_length=1, max_length=...)`, and `ReviewResponse` model.
- Add try/except around LLM call; map errors to consistent HTTP responses.
- Introduce size limits and truncation/segmentation strategy for diffs; return 413/422 appropriately.
- Use a system prompt with strict output schema and delimiter-guarded user content.
- Make the route `async` and run blocking work in a threadpool if needed.
