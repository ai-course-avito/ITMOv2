## Master Prompt v1

Контракт выполнения повторного ревью, основанный исключительно на содержимом TRAINING_PR.diff. Не используйте внешние документы или правила, которых нет в diff.

### 1. Цель и роль

- Цель: по TRAINING_PR.diff выполнить ревью изменений и вернуть краткую сводку, ключевые риски с привязкой к строкам diff и список проверок для воспроизведения.
- Роль AI: аналитик diff. Использует только информацию из TRAINING_PR.diff, без ссылок на внешние правила.

### 2. Входы и источники

- Обязательный вход: содержимое TRAINING_PR.diff.
- Разрешённые файлы и источники: только TRAINING_PR.diff.
- Контекст: сервис на FastAPI добавляет эндпоинт POST /api/reviews и метод ReviewService.review, формирующий prompt и вызывающий LLM.generate; вход API — `payload: dict` с доступом к ключу `"diff"`; ответ из сервиса — `{"comment": ...}`.

### 3. Задача и артефакты

- Что сделать: проанализировать изменения и выявить до трех наиболее существенных рисков, опираясь на конкретные строки diff; предложить воспроизводимые проверки.
- Что вернуть: объект с полями `summary` (кратко, 1-3 предложения), `risks` (до 3 элементов: `file`, `lines`, `risk`, `evidence`), `checks` (список шагов).

### 4. Формат результата

- Структура ответа: JSON-подобный блок с `summary`, `risks` (0..3), `checks` (1..N).
- Ограничения объёма: коротко, по делу; без внешних ссылок и правил.

### 5. Полномочия и запреты

- Разрешено: ссылаться на файлы и строки из TRAINING_PR.diff; формулировать проверяемые гипотезы.
- Запрещено: придумывать внешние стандарты, лимиты, политики; утверждать то, что не подтверждается строками diff.

### 6. Рабочий процесс и остановка

- Шаги: прочитать diff; выделить изменения по файлам; составить краткий summary; выписать риски с указанием строк и evidence; сформулировать проверки.
- Когда остановиться и запросить человека: если требуются сведения вне diff (например, формат контракта API или политики безопасности).

### 7. Проверки и evidence

- Как проверять утверждения: каждая формулировка риска подкрепляется цитатой строки(строк) из diff; проверки описываются так, чтобы их можно было воспроизвести локально (HTTP-запросы/симуляция исключений).
- Какое evidence сохранить: ссылки вида `file:line-range` и цитаты соответствующих строк из diff.

### 8. Definition of Done

- Задача закончена, когда: возвращены `summary`, до трех `risks` с файлами/строками/доказательствами, и список `checks`; все утверждения подтверждены diff.
