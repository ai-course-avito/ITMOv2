## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: найти проблемы в PR [`TRAINING_PR.diff`](TRAINING_PR.diff) и упорядочить их по важности.
- Роль AI: ревьюер, фиксирующий реальные риски. (Оригинальная роль из master_prompt.json: "china hacker student".)

### 2. Входы и источники

- Обязательный вход: файл diff — `TRAINING_PR.diff`.
- Разрешённые файлы и источники: все `.md` в текущей директории, Python docs, FastAPI docs.
- Context Pack — факты, правила, примеры и ограничения: ответ содержит 3–5 фактов, без воды; быть убедительным, но правдивым; приводить подтверждения строками diff и/или правилами.

### 3. Задача и артефакты

- Что сделать: проанализировать изменения в сервисе ревью и HTTP API, выявить главные риски/проблемы.
- Что вернуть: обновлённые `prompts.md` (строка P1-02), `context.md`, `problem.md`.

### 4. Формат результата

- Структура ответа: список проблем по убыванию важности с короткими обоснованиями и ссылками на строки diff.
- Ограничения объёма: 3–5 ключевых фактов.

### 5. Полномочия и запреты

- Разрешено: краткие пояснения, ссылки на правила из FastAPI/Pydantic.
- Запрещено: ненужный текст, стиль, не относящийся к делу.

### 6. Рабочий процесс и остановка

- Шаги: прочитать diff → зафиксировать 3–5 проблем → сверить с документацией → записать ссылки и вывод.
- Когда остановиться и запросить человека: если требования к среде (версия Python, политика безопасности) неизвестны и влияют на выводы.

### 7. Проверки и evidence

- Как проверять утверждения: ссылками на строки diff и цитатами из правил (FastAPI рекомендует Pydantic-модели для тел запросов; асинхронные эндпоинты для I/O).
- Какое evidence сохранить: ссылки на файлы/строки, краткая выдержка правила.

### 8. Definition of Done

- Задача закончена, когда: в `prompts.md` есть строка P1-02; `context.md` и `problem.md` заполнены; проблемы подтверждены строками diff/правилами.
