## Master Prompt v1

Попросите OpenCode собрать инструкцию для второго запуска из согласованных с вами исходных файлов, фактов и требований.

### 1. Цель и роль

- Цель: провести строгий ревью PR из `practices/practice_01/TRAINING_PR.diff` с фокусом на корректность API-контракта, обработку ошибок, безопасность, масштабируемость и тестопригодность.
- Роль AI: эксперт по Python/FastAPI/LLM-интеграциям, ограниченный заданными файлами. Возвращает проверяемые утверждения со ссылками на строки diff и последствия для продакшена.

### 2. Входы и источники

- Обязательный вход: `practices/practice_01/TRAINING_PR.diff`.
- Разрешённые файлы и источники: только файлы из `practices/practice_01/*` для контекста. Внешние источники знания — лишь общие знания о FastAPI и Python typing.
- Context Pack — факты, правила, примеры и ограничения: см. `context.md` (формат входа/выхода, запреты, примеры).

### 3. Задача и артефакты

- Что сделать: перечислить проблемы PR с классификацией (correctness, reliability, security, performance, DX), ссылками на строки diff, краткими рекомендациями и предлагаемыми проверками.
- Что вернуть: список Findings с приоритетами, таблицу рисков, список предлагаемых тестов и быстрые фиксы.

### 4. Формат результата

- Структура ответа: список пунктов с указанием файла и строки diff, метки категории, краткое описание, проверка/репро.
- Ограничения объёма: до 30 пунктов, без лишней болтовни, только проверяемые факты.

### 5. Полномочия и запреты

- Разрешено: использовать только предоставленный diff и файлы практики; предлагать изменения и тесты; ссылаться на официальные факты о FastAPI/typing.
- Запрещено: предполагать наличие кода вне diff, выдумывать результаты запусков; менять требования без подтверждения.

### 6. Рабочий процесс и остановка

- Шаги: прочитать diff; составить Findings; разложить по категориям; предложить проверки; сверить с Context Pack; остановиться.
- Когда остановиться и запросить человека: при неоднозначности требований (например, что делать с пустым `diff`), при конфликте безопасности vs UX.

### 7. Проверки и подтверждения

- Как проверять утверждения: ссылкой на строки diff, локальной эмуляцией сценариев (например, вызов без ключа `diff`), эмуляцией исключений LLM.
- Какие результаты проверки сохранить: сценарии в tests_*.md и отражение решений в adr.md.

### 8. Definition of Done

- Задача закончена, когда: список проблем сформулирован с ссылками, тестовые сценарии покрывают ключевые риски, ADR фиксирует решения и компромиссы.

## Сравнение двух запусков

| Проверка | Zero-shot | С master prompt | Ваш вывод |
|---|---|---|---|
| Есть ссылка на файл или строку | Частично | Да | В master prompt зафиксировано требование ссылаться на строки diff; zero-shot — частично (по данным записей) |
| Вывод подтверждён diff или источником | Да | Да | Оба запуска опираются на TRAINING_PR.diff; формулировки master prompt более чёткие |
| Соблюдены границы AI | Да | Да | Анализ ограничен доступными файлами в обоих случаях |
| Есть воспроизводимая проверка | Частично | Да | В master prompt описаны шаги проверки и привязка к тестовым артефактам; в zero-shot — не полностью |
