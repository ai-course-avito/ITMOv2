## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: сделать ревью файла practices/practice_01/TRAINING_PR.diff.
- Роль AI: ревьюер кода.

### 2. Входы и источники

- Обязательный вход: practices/practice_01/TRAINING_PR.diff.
- Разрешённые файлы и источники: practices/practice_01/TRAINING_PR.diff; practices/practice_01/CASE.md.
- Context Pack — факты и правила (см. practices/practice_01/CASE.md):
  - SEC-1: до внешнего вызова удалить из diff токены, пароли и приватные ключи.
  - API-1: для diff длиннее 20 000 символов вернуть HTTP 413 и не вызывать LLM.
  - REL-1: ограничить внешний LLM-вызов 10 секундами, ошибку представить контролируемым ответом.
  - OUT-1: ответ содержит summary, массив risks (до 3: file, line, evidence, risk) и массив checks.
  - SCOPE-1: дать совет, не approve/merge, не менять код и не выполнять действия в GitHub.
  - QA-1: риск включается только если подтверждён строкой diff или правилом.
  - OBS-1: логировать только request_id, длительность и статус, без diff и ответа модели.
  - Хороший результат указывает файл и строку, называет нарушенное правило и предлагает воспроизводимую проверку. Общие советы без evidence не включать.

### 3. Задача и артефакты

- Что сделать: сделать ревью кода по предоставленному diff с учётом правил репозитория.
- Что вернуть: ответ в формате OUT-1 (см. practices/practice_01/CASE.md).

### 4. Формат результата

- Структура ответа: объект с полями `summary`, `risks`, `checks`.
- `summary`: краткое описание изменения из diff без домыслов.
- `risks`: массив максимум из трёх объектов; каждый объект содержит `file`, `line`, `evidence`, `risk`.
- `checks`: список конкретных команд или сценариев с ожидаемым результатом.
- Ограничения объёма: максимум три наиболее существенных доказанных риска; не дублировать один риск разными формулировками.

### 5. Полномочия и запреты

- Разрешено: читать указанные файлы и выполнять ревью кода.
- Запрещено: изменять код, approve/merge PR, выполнять действия в GitHub, обращаться к неуказанным источникам или выдавать предположение за факт.
- Если факт нельзя подтвердить diff или правилом, не включать его в `risks`; при необходимости явно обозначить как неизвестное вне результата OUT-1.

### 6. Рабочий процесс и остановка

- Шаги:
  1. Прочитать `TRAINING_PR.diff` и определить только добавленное или изменённое поведение.
  2. Отобрать из `CASE.md` правила, применимые к этому diff.
  3. Для каждого кандидата в риск найти конкретную строку diff и нарушенное правило.
  4. Ранжировать риски по влиянию и оставить не более трёх без дубликатов.
  5. Сформировать воспроизводимую проверку для каждого принятого риска.
  6. Проверить итоговую структуру по OUT-1, доказательность по QA-1 и границы по SCOPE-1.
- Когда остановиться и запросить человека:
  - если обязательный файл отсутствует или противоречит другому разрешённому источнику;
  - если для вывода требуется правило, которого нет в `CASE.md`;
  - после формирования валидного ответа OUT-1 — не предпринимать дальнейших действий с PR.

### 7. Проверки и evidence

- Как проверять утверждения:
  - приводить путь и номер добавленной/изменённой строки из diff;
  - связывать риск с идентификатором правила;
  - проверять, что предложенный check имеет однозначный ожидаемый результат.
- Какое evidence сохранить:
  - минимальный фрагмент diff, достаточный для доказательства;
  - правило из `CASE.md`;
  - проверку, которая воспроизводит нарушение без реальных секретов и внешних действий.

### 8. Definition of Done

- Задача закончена, когда:
  - возвращены `summary`, `risks` и `checks`;
  - в `risks` не больше трёх элементов, все обязательные поля заполнены;
  - каждый риск доказан строкой diff или правилом и имеет воспроизводимую проверку;
  - соблюдены SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1 и OBS-1;
  - AI не изменял код и не выполнял действия в GitHub.

## Сравнение двух запусков

| Проверка | Zero-shot | С master prompt | Вывод команды |
|---|---|---|---|
| Есть ссылка на файл или строку | Да | Да | Оба запуска ссылаются на конкретные файлы и диапазоны строк из diff |
| Вывод подтверждён diff или правилом | Частично | Да | Во 2-м запуске каждый риск привязан к diff/правилу (QA-1); в 1-м часть выводов — общие практики |
| Соблюдены границы AI | Да | Да | Не было действий вне роли помощника (approve/merge/изменение кода) |
| Есть воспроизводимая проверка | Частично | Да | Во 2-м запуске добавлены конкретные checks; в 1-м — общие рекомендации по тестам |

### P1-01: Резюме и метаданные

- Инструмент и модель: OpenCode, модель openai/gpt-5
- Запрос: "Ниже diff учебного PR. Посмотри PR и найди проблемы." с артефактом practices/practice_01/TRAINING_PR.diff
- Краткий результат: выявлены критичные проблемы (валидация тела запроса, отсутствие обработки ошибок LLM), высокие риски (лимиты на размер diff, слабая типизация API), средние (prompt-injection, отсутствие тестов, безопасность), низкие (формат ответа, стиль, дизайн/версии API)
- Три слабых места ответа:
  1. Часть рекомендаций основана на общих практиках без подтверждения соответствия политике проекта.
  2. Не проверены фактические версии Python/библиотек; вывод о совместимости типов предположительный.
  3. Ревью статическое, без запуска тестов/рантайма, возможны пропуски интеграционных проблем.
- Какой информации не хватило модели: целевая версия Python; принятые паттерны FastAPI (схемы/обработчики ошибок); лимиты на размер diff и таймауты/SLAs LLM; требования по аутентификации/rate limiting; ожидаемый формат ответа и его потребители.
