## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: провести анализ учебного PR по diff и правилам репозитория, выявить синтаксические/логические риски и зафиксировать первичный инженерный каркас в файлах проекта.
- Роль AI: AI-reviewer / ассистент ревьюера, анализирующий diff и заполняющий артефакты рабочего каркаса.

### 2. Входы и источники

- Обязательный вход: TRAINING_PR.diff.
- Разрешённые файлы и источники: practices/practice_01/TRAINING_PR.diff, practices/practice_01/CASE.md.
- Context Pack — факты, правила, примеры и ограничения: правила SEC-1...QA-1 из CASE.md, см. practices/practice_01/context.md.

### 3. Задача и артефакты

- Что сделать: проанализировать diff на синтаксические и логические ошибки по правилам SEC-1…QA-1; сформулировать риски с evidence (file:line) и checks; зафиксировать первичный рабочий каркас.
- Что вернуть / записать: заполнить результаты ревью и контекст в файлы @context.md, @problem.md и первую таблицу @prompts.md (строка P1-02).

### 4. Формат результата

- Структура ответа: выжимка анализа формата file:line + описание рисков и рекомендации по исправлению; заполненные секции AS IS и Context Pack в context.md, проблемы и метрик в problem.md, запись в таблице prompts.md.
- Ограничения объёма: до 3 ключевых рисков с точной цитатой evidence из diff или ссылкой на правило.

### 5. Полномочия и запреты

- Разрешено: анализировать diff и правила, предлагать проверки, заполнять файлы контекста (context.md, problem.md, prompts.md).
- Запрещено: изменять исходный код репозитория, выполнять действия в GitHub (approve/merge), выдумывать правила вне CASE.md.

### 6. Рабочий процесс и остановка

- Шаги: 1) Гипотеза по синтаксическим/логическим рискам; 2) Доказательство строкой diff или правилом; 3) Перепроверка на противоречия; 4) Запись результатов в файлы @context.md, @problem.md, @prompts.md.
- Когда остановиться и запросить человека: если вывод не подтверждён diff/правилом или требуется уточнение требований.

### 7. Проверки и evidence

- Как проверять утверждения: каждое замечание должно ссылаться на file:line из diff или на идентификатор правила из CASE.md.
- Какое evidence сохранить: цитату из diff (строка кода) или идентификатор правила (SEC-1, API-1, REL-1, OUT-1).

### 8. Definition of Done

- Задача закончена, когда: результат ревью зафиксирован в строке P1-02 в prompts.md, файлы context.md и problem.md содержат подтверждённый рабочий каркас без нарушения шаблонов, границы помощника соблюдены.

| Проверка | Zero-shot (`answer_1_01.md`) | С master prompt (`answer_1_02.md`) | Вывод команды |
|---|---|---|---|
| Есть ссылка на файл или строку | Указывает строки (`api.py:37`), но смешивает их с общими рассуждениями и догадками | Точные ссылки (`review_service.py:19`, `api.py:36-38`) с цитированием кода | Master prompt обязал модель цитировать строки diff в поле `evidence`, исключив абстрактные замечания |
| Вывод подтверждён diff или правилом | Придумывает внешние требования: авторизация в API, поддержка Python 3.8, prompt injection | Опирается строго на правила репозитория: `SEC-1`, `API-1`, `REL-1`, `OUT-1` | Без Context Pack модель додумывает архитектурные требования из головы; с контрактом — проверяет только оговорённые правила (`QA-1`) |
| Соблюдены границы AI | Даёт непрошеные рекомендации по переписыванию кода и архитектуре сервиса | Строго следует `SCOPE-1`: формулирует гипотезу, приводит доказательство, оставляет решение человеку | Запреты в секции «Полномочия и запреты» исключили самодеятельность модели и попытки править код |
