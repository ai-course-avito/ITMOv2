# Нагрузочные проверки

Файл ведёт OpenCode. Для учебного сервиса достаточно легковесных проверок без внешнего LLM.

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Подтверждение |
|---|---|---|---|---|
| POST /api/reviews с коротким diff | 10 rps, 60 сек, без вызова внешнего LLM (мок) | P95 ≤ 200 мс | Латентность, ошибка rate | wrk/locust, логи |
| Валидация 422 под нагрузкой | 20 rps, 30 сек, payload без diff | Ошибки=100%, без деградации по времени | P95 ≤ 50 мс | wrk + сценарий invalid |
| Деградация при 502 | 5 rps, 60 сек, LLM всегда timeout | Ответ 502, стабильность без ростов lat >20% | P95 ≤ 300 мс | мок+мониторинг |

Если полноценно нагружать внешний LLM нельзя, используем мок и фиксируем целевые пределы для сервиса.

## Как использовали AI

- Для чего: наметить простые и воспроизводимые проверки производительности.
- Тип промпта: структурирующий запрос.
- Строка в [`prompts.md`](prompts.md): P1-03.
- Что проверил студент и какие исправления поручил агенту: границы выбраны реалистичные для учебного стенда, без внешних зависимостей.
