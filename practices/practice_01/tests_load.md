# Нагрузочные проверки

Нагрузочное тестирование **пока не является обязательным** для учебного MVP помощника ревьюера: в `TRAINING_PR.diff` нет SLA, квот LLM и целевого RPS. Ниже — минимальный каркас пределов на случай пилота API; числа — гипотезы для согласования, не измеренный baseline.

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Подтверждение |
|---|---|---|---|---|
| Устойчивость `POST /api/reviews` с mock LLM | 5 RPS × 2 минуты, тело с diff ≤ 50 KB | p95 latency ≤ 500 мс при mock без сети LLM; error rate ≤ 1% | latency p50/p95, доля 5xx | k6/locust + mock LLM |
| Большой diff | 1 RPS × 5 минут, diff 1 MB | Либо отказ с контролируемой 4xx, либо p95 ≤ согласованного SLA. **Открытый вопрос:** лимит размера | размер тела, latency, код ответа | Нагрузочный прогон + политика лимита |
| Деградация при медленном LLM | 2 RPS, mock delay 3 с, 3 минуты | Таймаут/ошибка предсказуемы; нет неограниченного роста очереди. **Открытый вопрос:** таймаут продукта | latency, таймауты, насыщение воркеров | Integration+load с delay |

**Когда понадобится обязательно:** при пилоте на реальных PR с живым LLM, при появлении SLA или при инцидентах по latency/стоимости токенов.

## Как использовали AI

- Для чего: зафиксировать, что load не обязателен сейчас, и задать условие включения.
- Тип промпта: master prompt / test design.
- Строка в [`prompts.md`](prompts.md): P1-01 и P1-02.
- Что проверил студент и какие исправления поручил агенту: пределы помечены как гипотезы; отсутствие SLA в источниках учтено.
