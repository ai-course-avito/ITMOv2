# P1-01: Baseline zero-shot review

**Инструмент/модель:** OpenCode (claude-sonnet-4)

**Запрос (zero-shot):**
```text
Ниже diff учебного PR. Посмотри PR и найди проблемы.
```

## Результат

Ниже — 5 проблем, найденных без контекста правил репозитория.

### Critical

**`app/api.py:37`** — Доступ к `payload["diff"]` без валидации. При отсутствии ключа или неподходящем типе выбросит `KeyError` → 500 вместо 422. Нужна Pydantic-модель и проверка.

**`app/review_service.py:21`** — Нет обработки ошибок вокруг `llm.generate(prompt)`. Любая ошибка LLM приведёт к 500 Internal Server Error. Нужен try/except.

### High

**`app/api.py:35-38`** — Нет Pydantic-модели для запроса/ответа. Ухудшает OpenAPI-документацию и валидацию входных данных.

**`app/review_service.py:20`** — Промпт не обрамлён делимитерами. Сырой diff может «размыть» инструкцию или вызвать prompt injection.

### Medium

**`app/review_service.py:22`** — Неформализованный ответ `{"comment": answer}`. Трудно для машинной обработки: нет summary, risks, checks.

## Слабые места ответа

1. **Нет ссылки на конкретные правила репозитория** (SEC-1, API-1, REL-1, OUT-1, OBS-1) — zero-shot не знает, что ответ должен соответствовать OUT-1.
2. **Не перечислены все нарушения** — пропущены SEC-1 (секреты), API-1 (лимит размера), REL-1 (таймаут), OBS-1 (логирование).
3. **Нет воспроизводимых проверок** — ответ даёт рекомендации, но не описывает, как именно проверить (например, diff с token → 413/500).

## Что модели не хватило

Контекст о правилах репозитория (SEC-1, API-1, REL-1, OUT-1, OBS-1, SCOPE-1, QA-1), формате ответа и ограничениях. Без них модель находит общие проблемы кода, но не может оценить соответствие репозиторным стандартам.
