# ADR: решение для первого рабочего сценария

- Статус: proposed / accepted
- Дата: 2026-09-10
- Ответственные: команда курса; студент‑автор артефактов

## Контекст

Сервис AI‑помощника ревьюера PR должен принимать diff, возвращать краткое резюме, до трёх рисков и список проверок, не нарушая правил SEC-1, API-1, REL-1, OUT-1, QA-1, SCOPE-1, OBS-1. Текущая реализация возвращает `comment` и не соблюдает эти правила.

## Решение

Ввести контракт результата OUT-1 в `ReviewService`; на уровне API реализовать валидацию входа (`diff` обязателен, длина ≤ 20 000), маскировать секреты перед вызовом LLM, обернуть вызов LLM таймаутом 10 сек и контролируемой обработкой ошибок. Сохранить роль человека как финального решателя. Не выполнять действий в GitHub. 

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрали сейчас |
|---|---|
| Полностью автоматическое approve/merge | Нарушает SCOPE-1; требуется отдельная оценка рисков |
| Встраивание правил в LLM без валидации на API | Ненадёжно; валидация должна быть детерминирована |
| Сохранение свободного формата ответа | Не позволяет автоматизировать потребление результата |

## Последствия и главный риск

- Положительные последствия:
  - Стандартизованный результат, упрощение интеграции и проверок
  - Снижение риска утечек и зависаний
- Ограничения:
  - Ограничение размера diff
  - Дополнительные затраты на маскирование и таймауты
- Главный риск:
  - Ложноположительное маскирование, ухудшающее полезность анализа
- Как проверим риск:
  - Интеграционные тесты с тестовыми токенами и эталонными diff
