# ADR: решение для первого рабочего сценария

- Статус: accepted
- Дата: 2026-09-08
- Ответственные: PO, Systems Analyst, Solution Architect, Tech PM, QA Lead

## Контекст

Учебный сервис AI-помощника ревьюера PR получает diff и возвращает структурированные подсказки. По TRAINING_PR.diff сейчас отсутствуют валидация входа, лимит длины, маскирование секретов, таймаут 10 секунд и корректный формат OUT-1. Это вызывает 500/зависания, риски SEC-1 и непредсказуемый опыт для пользователя.

## Решение

Принять минимально достаточное решение для первого рабочего сценария:

- Контракт API: POST `/api/reviews` принимает JSON с `diff: str`, возвращает 200 JSON по OUT-1.
- API-1: если `len(diff) > 20000`, вернуть 413 без вызова LLM.
- SEC-1: перед вызовом LLM маскировать секреты в diff (`ghp_\w+`, `password=\S+`, PEM-блоки) на `[REDACTED]`.
- REL-1: вызывать LLM с таймаутом 10 секунд; при исключении провайдера вернуть 502, при превышении таймаута — 504.
- OUT-1: формировать `summary`, не более 3 `risks` с `file`, `line`, `evidence`, `risk`, и массив `checks`.
- OBS-1: логировать только `request_id`, длительность и статус; не логировать diff и ответ модели.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрали сейчас |
|---|---|
| Асинхронная очередь и отложенная обработка | Усложняет MVP; таймаут 10с и 413 покрывают основные риски производительности |
| Он-прем LLM без внешних вызовов | Не соответствует условиям учебного кейса и увеличивает затраты |
| Расширенный анализ с консервацией контекста репозитория | Выходит за рамки SCOPE-1 и MVP, повышает сложность |

## Последствия и главный риск

- Положительные последствия:
  - Предсказуемые SLA ответов, снижение 500, отсутствие утечек секретов.
- Ограничения:
  - Не решает масштабирование для >20000 символов; нет очередей и ретраев.
- Главный риск:
  - Недостаточное покрытие паттернов секретов приведёт к утечке в LLM.
- Как проверим риск:
  - Юнитами на паттерны и интеграцией с мок-LLM, проверкой маркеров `[REDACTED]`; регулярные ревизии списков паттернов.

```mermaid
    Input[POST /api/reviews] --> Validate[Валидация и лимит 20000]

    Validate -->|"ok"| Mask[SEC-1 маскирование]

    LLM -->|"ответ"| Build[OUT-1: summary, risks≤3, checks]
    LLM -->|"ошибка"| Err502[HTTP 502]
    LLM -->|"таймаут"| Err504[HTTP 504]
    Build --> Result[200 OK]
```
