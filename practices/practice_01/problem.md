# Проблема и метрики

## Проблема

- Пользователь: инженер, отправляющий diff на автоматическое ревью.
- Сейчас: необработанный diff без проверки размера и секретов уходит в LLM; вызов не имеет заданного timeout; ответ имеет произвольное поле `comment`.
- Последствие: возможны утечка секрета, слишком дорогой запрос, зависший вызов и невоспроизводимый формат результата.
- Не входит: выбор LLM-провайдера, GitHub-интеграция, approve/merge и изменение кода.

## Метрики

| Метрика | Baseline по diff | Цель | Когда измеряем | Evidence |
|---|---:|---:|---|---|
| Проверки политики входа | 0 из 2 (`SEC-1`, `API-1`) | 2 из 2 | На каждый PR | Unit/integration tests |
| Контролируемый timeout LLM | Нет | 10 секунд, без необработанного 500 | На каждый PR | Тест fake LLM с задержкой |
| Соответствие `OUT-1` | 0%: возвращается `comment` | 100% схемы `summary/risks/checks` | На каждый PR | Schema test |
| Неподтверждённые риски | Не ограничены | 0; максимум 3 риска | На каждый ответ | Проверка `QA-1` |

## Почему метрики подтверждают решение

Они напрямую проверяют четыре наблюдаемых дефекта: подготовку входа, ограничение времени, контракт ответа и доказательность рисков.

## Как использовали AI

- Для чего: связать проблему с измеримыми правилами кейса.
- Тип промпта: master prompt.
- Строка в [`prompts.md`](prompts.md): `P1-02`.
- Проверка человеком: baseline выведен только из строк 19–22 и 35–37; лишние требования удалены.
