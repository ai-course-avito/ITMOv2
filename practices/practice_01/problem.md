# Проблема и метрики

## Проблема

- Пользователь: разработчик или CI, вызывающие POST /api/reviews для автоматического ревью PR.
- Ситуация: отправляется diff PR в сервис AI-ревью, ожидается стабильный предсказуемый ответ.
- Что происходит сейчас: в новом эндпоинте отсутствует валидация входа и обработка ошибок LLM; весь diff без ограничений уходит в промпт. Это ведет к 500 при неверном теле запроса/ошибках LLM и риску переполнения токенов/высокой латентности.
- Почему это мешает пользователю или бизнесу: нестабильный API ломает CI, тратит квоту LLM, увеличивает задержки и стоимость, ухудшает доверие к инструменту ревью.
- Что не входит в задачу: полная смена схемы ответа, интеграция аутентификации/квот, выбор конкретного провайдера LLM и его SDK.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля 5xx на POST /api/reviews при невалидном теле | Воспроизводится KeyError при `{}` -> 500 (ручной тест) | 0% 5xx; 422/400 при ошибке клиента | Локально/CI после правок | Интеграционный тест, логи FastAPI |
| Обработка исключений LLM | Сейчас необработанные исключения -> 500 | 100% покрытие try/except с контролируемым ответом | Юнит/интеграционные тесты | Тесты review_service, мок LLM |
| Ограничение размера diff | Нет лимита -> риск DoS/ошибки токенов | Введен лимит (напр. 100-200 KB) и/или чанкинг | Юнит-тест на усечение | Конфиг сервиса, тесты |
| P95 латентность /api/reviews (малый diff) | Не измерялась; базовый замер | P95 <= X ms (зафиксировать в CI-бенчмарке) | После внедрения ограничений | Локальный бенч, профайлинг |

## Почему изменение метрики подтвердит решение проблемы

Снижение 5xx на клиентских ошибках подтверждает корректную валидацию и предсказуемость API. Покрытие обработкой исключений гарантирует отказоустойчивость при сбоях LLM. Введение лимита входа предотвращает деградации и ошибки токенизации. Контроль P95 демонстрирует отсутствие существенной регрессии в задержке для типичных кейсов.
