# Проблема и метрики

## Проблема

- Пользователь: Backend-разработчики, использующие review сервис
- Ситуация: PR добавляет новый эндпоинт для AI-ревью, но содержит серьёзные проблемы
- Что происходит сейчас: Diff содержит синтаксические ошибки, отсутствует валидация и обработка ошибок
- Почему это мешает пользователю или бизнесу: Код не пройдёт CI/CD, вызовет исключения в продакшене, непредсказуемое поведение
- Что не входит в задачу: Не требуется добавлять новые фичи, только исправить существующие проблемы

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---|---|---|---|
| Количество синтаксических ошибок в PR | 1 (Protocol) | 0 | После исправления | Линтер/python -m py_compile |
| Количество мест без валидации ввода | 1 (payload["diff"]) | ≥1 с валидацией | После исправления | Code review |
| Количество обработчиков ошибок | 0 | ≥1 (try/except) | После исправления | Code review |

## Почему изменение метрики подтвердит решение проблемы

Исправление синтаксической ошибки в Protocol позволит коду успешно импортироваться и функционировать. Добавление валидации ввода предотвратит KeyError в продакшене. Обработка ошибок обеспечит устойчивость сервиса.
