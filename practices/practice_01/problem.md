# Проблема и метрики

## Проблема

- Пользователь: Клиент API, отправляющий дифф PR для автоматического ревью.
- Ситуация: Появился новый эндпоинт POST /api/reviews, который принимает произвольный dict и ожидает ключ "diff".
- Что происходит сейчас: Данные из payload["diff"] без проверки и ограничения вставляются в промпт и отправляются в LLM; ошибки входа не обрабатываются.
- Почему это мешает пользователю или бизнесу: Риск 500 при отсутствии ключа/неверном типе; потенциальные издержки и задержки из-за больших входов; риск prompt injection и возможной утечки контекста; отсутствие контрактов API усложняет интеграции.
- Что не входит в задачу: Изменение реализации за рамками diff; проектирование аутентификации/биллинга на стороне платформы.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля 2xx для POST /api/reviews | Логи/апм после деплоя | >= 99% | Непрерывно | FastAPI/логирование |
| P95 latency для POST /api/reviews | Таймер вокруг review_service.review | <= 500 мс (без LLM) | CI и стейдж | Мониторинг |
| Размер входного diff | Логи с ограничением и усечением | <= 100 KB | На входе | Access logs |
