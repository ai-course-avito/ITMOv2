# Integration-проверки

| Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| FastAPI → схема запроса | Отсутствующее или нестроковое поле `diff` приводит к 500 | Отправить `{}` и `{"diff": 42}` через `TestClient` | Контролируемая 4xx-ошибка валидации; `ReviewService` не вызван | `test_api_rejects_invalid_payload` |
| FastAPI → `ReviewService` (API-1) | Нарушена граница размера или слишком большой diff дошёл до LLM | Отправить строки длиной 20 000 и 20 001 с fake service/LLM | 20 000 проходит дальше; 20 001 получает HTTP 413; LLM не вызван | `test_api_enforces_diff_size_boundary` |
| `ReviewService` → внешний LLM (SEC-1) | Исходный секрет попал в prompt | Передать diff с синтетическим токеном, перехватить prompt fake LLM | В prompt есть `[REDACTED]`, исходного значения нет | `test_service_sends_redacted_prompt` |
| `ReviewService` → внешний LLM (REL-1) | Зависание или исключение превращается в необработанный 500 | Fake LLM задерживается >10 секунд либо выбрасывает исключение | Вызов прекращён по timeout; API возвращает документированный контролируемый ответ | `test_api_handles_llm_timeout`, `test_api_handles_llm_error` |
| LLM-ответ → API (OUT-1, QA-1) | Потеря полей, больше трёх рисков или риск без доказательства | Fake LLM возвращает валидный и невалидный наборы | Клиент всегда получает валидную схему; недоказанный/лишний риск не публикуется | `test_api_returns_out1_contract` |
| API/service → журнал (OBS-1) | В лог попали diff, секрет или ответ модели | Выполнить успешный запрос и timeout, захватить логи | Есть request_id, длительность, статус; конфиденциального содержимого нет | `test_request_logs_metadata_only` |

Планируемый запуск после реализации: `pytest -q tests/integration`.
