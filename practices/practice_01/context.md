## Context Pack для первого рабочего сценария

### Факты и правила

- `SEC-1`: перед отправкой diff во внешний LLM из него удаляются токены, пароли и приватные ключи.
- `API-1`: diff длиннее 20 000 символов отклоняется с HTTP 413.
- `REL-1`: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- `OUT-1`: ответ содержит `summary`, массив `risks` (не более трёх элементов с полями `file`, `line`, `evidence`, `risk`) и массив `checks`.
- `QA-1`: риск попадает в ответ только если подтверждён строкой diff или правилом репозитория.
- `SCOPE-1`: сервис только советует; не пишет код и не выполняет действия в GitHub.
- `OBS-1`: в лог пишутся только `request_id`, длительность и статус; содержимое diff и ответа модели не логируется.

### Формат входа и результата

- Вход: diff одного PR, не длиннее 20 000 символов (`API-1`); учебный пример — `TRAINING_PR.diff`.
- Результат: JSON-подобная структура с полями `summary`, `risks` (максимум 3, каждый с `file`, `line`, `evidence`, `risk`), `checks` (`OUT-1`).

### Ограничения и запрещённые действия

- Сервис не может approve, merge или менять код в GitHub (`SCOPE-1`).
- Риск нельзя включать в ответ без подтверждения строкой diff или правилом репозитория (`QA-1`).
- Секреты из diff нельзя передавать во внешний LLM в исходном виде (`SEC-1`).
- В лог нельзя писать содержимое diff и текст ответа модели — только `request_id`, длительность, статус (`OBS-1`).
- Diff длиннее 20 000 символов нельзя обрабатывать — запрос отклоняется с HTTP 413 (`API-1`).

### Хороший пример

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```
