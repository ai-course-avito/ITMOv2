## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- OUT-1: ответ содержит summary, массив risks (макс. 3) и массив checks. В risks поля: file, line, evidence, risk.
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub.
- QA-1: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.
- OBS-1: в лог пишутся только request_id, длительность и статус. Содержимое diff и ответа модели не логируется.

### Формат входа и результата

- Вход: текстовый diff одного PR (в учебном кейсе — TRAINING_PR.diff). Жёсткий лимит длины: 20 000 символов.
- Результат: JSON с полями:
  - summary: краткое описание изменения;
  - risks: массив до 3 элементов; каждый элемент имеет поля file, line, evidence (конкретная строка diff/правило), risk (описание риска);
  - checks: перечень воспроизводимых проверок.
  - Язык результата: русский; стиль формальный профессиональный без жаргона; summary лаконичное (1–2 предложения).
  - Формат checks: чеклист с повелительными формулировками, шаги воспроизводимы и независимы.
  - При таймауте/ошибке LLM (REL‑1): возвращается контролируемый ответ с HTTP 200 и тем же JSON‑форматом, где summary указывает на деградацию (например, "LLM timeout, возвращены только обязательные проверки"), risks = [], checks содержит шаги ручной проверки и повторного запуска.
  - Требование к evidence: ссылка на конкретный файл и номер строки + фрагмент строки diff ИЛИ ссылка на правило репозитория (например, SEC‑1, OUT‑1).

### Ограничения и запрещённые действия

- Нельзя отправлять секреты во внешний LLM; всё потенциально чувствительное содержимое должно быть отредактировано [REDACTED] перед вызовом (SEC‑1).
- Нельзя принимать диффы длиннее 20 000 символов (возвращать 413) (API‑1).
- Нельзя выходить за роль советника, выполнять действия в GitHub, выполнять код (SCOPE‑1).
- Необходимо завершать LLM‑запрос через 10 секунд с контролируемым ответом (REL‑1).
- Запрещено логировать содержимое diff и ответ модели; логируются только request_id, длительность и статус (OBS‑1).
- Не надо редактировать часть "Как использовали AI" в конце файлов.

### Хороший пример

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

### Что пока неизвестно

- На текущий момент нет нерешённых вопросов по стилю и форматам; применены ваши предпочтения (RU, формальный стиль, короткий summary, checks в виде чеклиста, evidence в формате file:line — фрагмент). Архитектурные вопросы решены в рамках учебного контекста.
