## Context Pack для первого рабочего сценария

### Факты и правила

- Источник анализа: только предоставленный diff pull request.
- Текущее состояние (AS IS), подтверждённое TRAINING_PR.diff: вход не валидируется (используется `payload["diff"]`), весь diff попадает в промпт, ошибки LLM не обрабатываются, возвращается только `{ "comment": str }`.
- Целевой контракт (TO BE) — релевантные правила из CASE.md:
  - SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи (редакция до `[REDACTED]`).
  - API-1: diff длиннее 20 000 символов отклоняется с HTTP 413 (Content Too Large; прежнее название — Payload Too Large).
  - REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка конвертируется в контролируемый ответ сервиса.
  - OUT-1: ответ содержит поля `summary`, массив `risks` (≤ 3 элемента) и массив `checks`; каждый риск имеет `file`, `line`, `evidence`, `risk`.
  - SCOPE-1: сервис только даёт рекомендации и не выполняет действия в GitHub.
  - QA-1: риск включается в ответ, только если подтверждён строкой diff или правилом репозитория.
  - OBS-1: в логи не попадает содержимое diff и ответ LLM; пишутся только безопасные метаданные.
- Роль AI: AI-reviewer.
- Поток: candidate -> evidence -> check. Нет evidence -> пропустить.

### Формат входа и результата

- Вход: diff (текст). Для TO BE — валидация структуры запроса, проверка длины diff (≤ 20 000 символов), редакция секретов.
- Результат (TO BE, согласно OUT-1): `summary` + не более 3 `risks` + `checks`.
- Описание риска: `file`:`line` + `evidence` (цитата из diff) + `risk` (описание) + привязка к правилу.

### Ограничения и запрещённые действия

- Запрещено: approve, merge, edit.
- Нельзя придумывать правила или читать файлы вне diff.
- Соблюдать границы: если нет evidence в diff — пропустить кандидат.

### Хороший пример

Candidate: Нет валидации тела запроса.
Evidence: app/api.py:36 — `def create_review(payload: dict) -> dict[str, str]:` и `payload["diff"]`.
Check: POST /api/reviews с `{}` приводит к KeyError и 500; ожидаемый результат после внедрения TO BE — 422 согласно контракту валидации. Rule: QA-1.

### Плохой пример

"Нужно добавить аутентификацию" без ссылки на строки и без evidence. Нарушение: нет file:line и evidence; возможен выдуманный контекст.

### Что пока неизвестно

- Версия Python (важно для `dict[str, str]`).
- Реализация и SLA LLM (sync/async, лимиты токенов).
- Ограничения размера diff и требования к схеме ответа (зафиксированы в правилах, но ещё не реализованы в коде учебного PR).

- Для чего: сбор контекста и формирование Context Pack для AI-ревью по учебному кейсу.
- Тип промпта: master prompt.
- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: привязали правила к конкретным требованиям TO BE и отделили их от текущего состояния по TRAINING_PR.diff; исключили предположения без evidence.
