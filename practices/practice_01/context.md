## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- OUT-1: ответ содержит summary, массив risks (≤3, с полями file, line, evidence, risk) и массив checks.
- SCOPE-1: сервис только советует; не пишет код и не выполняет действия в GitHub.
- QA-1: риск включается только если подтверждён строкой diff или правилом.
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответа не логируется.

### Формат входа и результата

- Вход: `TRAINING_PR.diff` (строковый diff).
- Результат: структурированный ответ по OUT-1: `summary`, `risks[]` (макс. 3) и `checks[]`.

### Ограничения и запрещённые действия

- Не approve/merge; не менять код; не выполнять действия в GitHub (SCOPE-1).
- Не включать непроверенные утверждения без evidence (QA-1).
- Уважать лимиты API-1 и REL-1.

### Хороший пример

app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC‑1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED].

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Граница версий Python/зависимости; конкретный провайдер LLM; политика логирования в проде.

## Как использовали AI

- Для чего: baseline-оценка рисков по diff.
- Тип промпта: zero-shot.
- Строка в [`prompts.md`](prompts.md): P1-01.
- Что проверили и исправили сами: отфильтровали предположения без evidence, оставили только подтверждённые правилами CASE.md и строками diff.
