## Context Pack для первого рабочего сценария

### Факты и правила

- Задача помощника на один PR: вернуть краткое описание изменения, не больше трёх рисков (file/line/evidence/risk) и список проверок. Решение всегда принимает человек.
- OUT-1: ответ должен содержать поля summary, массив risks (≤3, с полями file, line, evidence, risk) и массив checks.
- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub.
- QA-1: риск включается в ответ, только если подтверждён строкой diff или правилом репозитория.
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответа модели не логируется.

### Формат входа и результата

- Вход: строка diff (TRAINING_PR.diff) из запроса клиента.
- Выход: JSON с полями summary, risks (до трёх элементов с file, line, evidence, risk), checks (список воспроизводимых проверок).

### Ограничения и запрещённые действия

- Не отправлять секреты во внешний LLM (см. SEC-1) — редактирование/маскирование обязательно.
- Отклонять слишком длинные диффы (см. API-1) ответом 413.
- На таймаутах/ошибках LLM возвращать контролируемый ответ в пределах 10 сек (см. REL-1).
- Соблюдать границы помощника: не approve/merge, не менять код, не выполнять действия в GitHub (см. SCOPE-1).
- В рисках ссылаться только на подтверждённые факты из diff или правил (см. QA-1).
- Не логировать содержимое diff и ответа модели (см. OBS-1).

### Хороший пример

```
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

### Плохой пример

```
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

### Что пока неизвестно

- Целевая версия Python (влияет на dict[str, str] и Protocol).
- Требуется ли аутентификация/авторизация на эндпоинте.
- Точный формат результата для клиентов (достаточно ли одного поля comment или нужен структурированный список).
- Ограничения по размеру diff на уровне SLA и производительности.
- Требования к языку ответов (RU/EN) и необходимость потоковой выдачи.
