## Context Pack для первого рабочего сценария

### Факты и правила

- Задача помощника для одного PR: на вход получает diff и возвращает 1) краткое описание изменения, 2) не больше трех рисков с файлом, строкой и доказательством, 3) список проверок. [CASE.md]
- Применимые правила репозитория: [CASE.md]
  - SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
  - API-1: diff длиннее 20000 символов отклоняется с HTTP 413.
  - REL-1: вызов внешнего LLM имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
  - OUT-1: ответ содержит summary, массив risks (максимум три элемента с полями file, line, evidence, risk) и массив checks.
  - SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub.
  - QA-1: риск включается в ответ только если подтвержден строкой diff или правилом репозитория.
  - OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответ модели не логируются.
- Факты из учебного diff: [TRAINING_PR.diff]
  - app/review_service.py: добавлен ReviewService.review, который вставляет полный diff в промпт и возвращает только {"comment": answer} (рассинхрон с OUT-1: нет summary/risks/checks).
  - app/review_service.py: нет редактирования секретов и ограничений размера diff (риски по SEC-1 и API-1).
  - app/api.py: добавлен POST /api/reviews, принимает payload: dict и обращается к payload["diff"] без валидации (KeyError→500), синхронный обработчик, нет response_model и обработки ошибок LLM (риски по REL-1/OUT-1 и качеству API).
- Не включать в контекст: snake_case для БД и i18n фронтенда — не относятся к этому PR. [CASE.md]

### Формат входа и результата

- Вход: один текстовый diff (тот же, что в TRAINING_PR.diff).
- Выход: JSON со структурой: [CASE.md]
  - summary: краткое описание изменения;
  - risks: до 3 элементов с полями file, line, evidence, risk;
  - checks: список проверок/экспериментов для воспроизведения и верификации.

### Ограничения и запрещенные действия

- Помощник не может approve, merge, коммитить или менять код; только советует. [SCOPE-1]
- Все выводы и риски подтверждать diff или правилом из раздела «Правила репозитория». [QA-1]
- Учитывать SEC-1, API-1 (20000 символов), REL-1 (10 секунд), OBS-1. [CASE.md]

### Хороший пример

app/review_service.py:16 - diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED]. [CASE.md]

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок. [CASE.md]

### Что пока неизвестно

- Целевая версия Python (dict[str, str] требует 3.9+). Нужны ли совместимые аннотации? [zero_shot_promt_answer.md]
- Контракт API запроса/ответа: только поле diff или дополнительные метаданные (repo, автор, язык, лимиты)? [zero_shot_promt_answer.md]
- Максимальный ожидаемый размер diff и SLA времени ответа; нужна ли асинхронная обработка/очередь? [zero_shot_promt_answer.md]
- Требуются ли аутентификация, квоты и лимиты для /api/reviews? [zero_shot_promt_answer.md]
