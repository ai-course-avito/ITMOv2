## Context Pack для первого рабочего сценария

### Факты и правила

- Сервис предоставляет `POST /api/reviews` и `GET /health` (FastAPI).
- `ReviewService.review(diff: str)` формирует промпт и вызывает `llm.generate`.
- Текущий ответ API: JSON с ключом `comment` и строковым значением.
- Входной JSON ожидает ключ `diff` со строкой диффа.

### Правила репозитория (для этой задачи)

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- OUT-1: ответ содержит `summary`, массив `risks` и массив `checks`. В `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`.
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub.
- QA-1: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.
- OBS-1: в лог пишутся только `request_id`, длительность и статус. Содержимое diff и ответа модели не логируется.

### Формат входа и результата

- Вход (POST `/api/reviews`): `{ "diff": string }`
- Результат: `{ "comment": string }`

### Ограничения и запрещённые действия

- В текущем коде явные ограничения не заданы (нет валидации/ограничения размера/обработки ошибок). Требования на уровне репозитория см. выше (SEC-1…OBS-1).

### Хороший пример

- Запрос: `{ "diff": "diff --git a/app/api.py b/app/api.py\n..." }`
- Ответ: `{ "comment": "...текст обзора..." }`

### Плохой пример

- Запрос без ключа `diff` или с неверным типом: `{}` → приведёт к 500 (сейчас).

### Что пока неизвестно

- Какая версия Python в рантайме/CI (совместимость аннотаций типа `dict[str, str]`).
- Требуется ли аутентификация/авторизация и rate limiting.
- Допустимый максимальный размер `diff` и SLA на генерацию.
- Требуемая структура ответа (достаточен ли один текстовый комментарий).

## Как использовали AI

- Для чего: базовый baseline‑ревью diff `TRAINING_PR.diff` для выявления рисков и дефектов.
- Тип промпта: zero‑shot.
- Строки в [`prompts.md`](prompts.md): записи `P1-01` и `P1-02`.
- Что проверили и исправили сами: сопоставили вывод с кодом (`app/api.py`, `app/review_service.py`), подтвердили ссылки на строки, сформировали перечень проблем в `problems.md` без изменения кода.
