## Context Pack для первого рабочего сценария

### Факты и правила

- Источник анализа: только предоставленный diff pull request.
- Набор правил: SEC-1...QA-1 (даются отдельно; не придумывать новые правила).
- Роль AI: AI-reviewer.
- Поток: candidate -> evidence -> check. Нет evidence -> пропустить.

### Формат входа и результата

- Вход: diff (текст), ссылки на правила SEC-1...QA-1.
- Результат: summary + не более 3 рисков + checks.
- Описание риска: file:line + evidence (цитата из diff) + ссылка на правило.

### Ограничения и запрещённые действия

- Запрещено: approve, merge, edit.
- Нельзя придумывать правила или читать файлы вне diff.
- Соблюдать границы: если нет evidence в diff — пропустить кандидат.

### Хороший пример

Candidate: Нет валидации тела запроса.
Evidence: app/api.py:36 - `def create_review(payload: dict) -> dict[str, str]:` и `payload["diff"]`.
Check: POST /api/reviews с `{}` приводит к KeyError и 500; ожидаем 422 по контракту. Rule: QA-1.

### Плохой пример

"Нужно добавить аутентификацию" без ссылки на строки и без evidence. Нарушение: нет file:line и evidence; возможен выдуманный контекст.

### Что пока неизвестно

- Версия Python (важно для `dict[str, str]`).
- Реализация и SLA LLM (sync/async, лимиты токенов).
- Ограничения размера diff и требования к схеме ответа.
