## Context Pack для первого рабочего сценария

### Факты и правила

- Помощник получает diff одного PR и возвращает: краткое описание изменения, не более трёх рисков с файлом, строкой и доказательством, список проверок, которые стоит запустить.
- `SEC-1`: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- `API-1`: diff длиннее 20 000 символов отклоняется с HTTP 413.
- `REL-1`: внешний LLM-вызов имеет timeout 10 секунд. Ошибка превращается в контролируемый ответ.
- `OUT-1`: ответ содержит `summary`, массив `risks` и массив `checks`. В `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`.
- `SCOPE-1`: сервис только советует. Он не пишет код и не выполняет действия в GitHub.
- `QA-1`: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.

Не перенесены:
- правила про `snake_case` для таблиц БД и про i18n для frontend-строк — [`CASE.md`](CASE.md) помечает их как не относящиеся к этому PR, а изменённые файлы не содержат ни схемы БД, ни строк интерфейса.

- `OBS-1` про состав логов — в [`TRAINING_PR.diff`](TRAINING_PR.diff) нет ни одной строки логирования, поэтому нарушение недоказуемо.
### Формат входа и результата

- Вход: текст unified diff одного PR. Других файлов и источников нет.
- Выход: `summary` — одно-два предложения о сути изменения. `risks` — массив не длиннее трёх элементов с полями `file`, `line`, `evidence`, `risk`. `checks` — список проверок, которые можно запустить.
- В `evidence` — либо конкретная строка diff, либо код правила репозитория.
- Язык ответа — русский, идентификаторы кода и коды правил не переводятся.
- Если подтверждённых рисков меньше трёх, массив короче. Добирать до трёх запрещено.

### Ограничения и запрещённые действия

- Не писать код и не предлагать готовые патчи, не выносить вердикт approve или merge, не выполнять действий в GitHub (`SCOPE-1`).
- Не включать риск без подтверждения строкой diff или правилом репозитория (`QA-1`).
- Не опираться на правила, не относящиеся к этому PR.
- Не достраивать неизвестное окружение: версию Python, наличие аутентификации, настройки CI и провайдера LLM. В `P1-01` именно такие пункты пришлось отклонить.
- Не комментировать неизменённые строки контекста: разбирается только то, что PR добавляет или меняет.
- Не запрашивать дополнительные файлы и не выходить за пределы приложенного diff.

### Хороший пример

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

Почему хороший: есть файл и строка, названо конкретное правило, указана воспроизводимая проверка. Номер строки в примере иллюстративный — он взят из [`CASE.md`](CASE.md) и не совпадает с нумерацией изменённого файла, где эта строка четырнадцатая.

### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

Почему плохой: нет ссылки на строку, нет правила, нет способа проверить утверждение — по такому комментарию нельзя ни согласиться, ни возразить.

### Что пока неизвестно

- Целевая версия Python и поддерживаемые версии зависимостей — вопрос возник в `P1-01`, из diff не выводится.
- Каким набором паттернов вычищаются секреты по `SEC-1`: правило требует результат, но не описывает механизм.
- Реальное распределение размеров diff — без него порог 20 000 символов нечем обосновать.
- Есть ли аутентификация и лимиты на внутренних сервисах команды.
- Где хранится актуальный список правил репозитория и кто его обновляет.

## Как использовали AI

- Для чего: черновик таблицы AS IS и отбор правил репозитория в Context Pack
- Тип промпта: R.C.T.F.
- Строка в [`prompts.md`](prompts.md): `P1-03`
- Что проверили и исправили сами: переписал таблицу AS IS и убрал из неё придуманное число ревьюеров и лишний пункт про падение внимания. Прочитал `CASE.md` целиком и сверил, что правила перенесены верно. Решение не включать `OBS-1` принял сам: в diff нет ни строки логирования, поэтому нарушение недоказуемо по `QA-1`. После сверки артефактов между собой исправил ссылку на строку: она стояла в координатах текста diff, а контракт из [`prompts.md`](prompts.md) требует координат изменённого файла
