## Context Pack для первого рабочего сценария

### Факты и правила

- Анализируем только предоставленный diff и согласованный Context Pack.
- Максимум 3 ключевых риска на ревью, каждый с file:line, цитатой (evidence) и проверкой (check).
- Валидация запроса/ответа обязательна (Pydantic). Ошибки: 422 (валидация), 502 (сбой LLM). Ответ — структурированный.

### Формат входа и результата

- Вход (AS IS): произвольный JSON с ключом diff (без валидации).
- Вход (TO BE): JSON, соответствующий схеме ReviewRequest: { diff: string }.
- Результат (TO BE): JSON ReviewResponse: { summary: string, risks: [{ file?: string, line?: int, rule: string, evidence: string, check: string }] }.

### Ограничения и запрещённые действия

- Нельзя дополнять контекст домыслами (версии, инфраструктура) вне diff/Context Pack.
- Нельзя делать approve/merge. Только анализ и проверяемые замечания.
- Нельзя возвращать свободный текст вместо согласованной схемы ответа.

### Хороший пример

- POST с корректным diff возвращает 200 и ReviewResponse с не более чем 3 рисками, каждый содержит rule, evidence с цитатой из diff и воспроизводимую проверку.

### Плохой пример

- Список из 10+ общих советов без ссылок на строки и без проверок; возвращён свободный текст без схемы.

### Что пока неизвестно

- Реальные лимиты внешнего LLM провайдера и его SLA; в практике используем мок/адаптер с таймаутом и маппингом ошибок.
