## Context Pack для первого рабочего сценария

Отобрано только то, что меняет выполнение задачи «ревью `TRAINING_PR.diff`». Этот же текст встроен в [Master Prompt v1](prompts.md#master-prompt-v1).

### Факты о PR (источник — `TRAINING_PR.diff`)

| Файл : строка нового файла | Строка diff | Что делает код |
|---|---|---|
| `app/review_service.py:13` | 19 | `ReviewService.review(self, diff: str) -> dict[str, str]` — новый метод |
| `app/review_service.py:14` | 20 | `prompt = f"Review this pull request and find problems:\n{diff}"` — diff подставляется в prompt как есть |
| `app/review_service.py:15` | 21 | `answer = self.llm.generate(prompt)` — синхронный вызов LLM, без timeout и без обработки ошибок |
| `app/review_service.py:16` | 22 | `return {"comment": answer}` — ответ в виде одного текстового поля |
| `app/api.py:8–9` | 35–36 | `@app.post("/api/reviews")`, `def create_review(payload: dict)` — тело запроса без схемы |
| `app/api.py:10` | 37 | `return review_service.review(payload["diff"])` — при отсутствии `diff` будет `KeyError` → 500 |

Остальное в diff — косметика (`def generate(...): ...` переписан в две строки). Нумерация: `hunk`-заголовки в учебном diff неточны (`+1,23`), поэтому строки нового файла считаются по содержимому hunk: контекстные и `+`-строки подряд с 1.

### Правила репозитория, которые относятся к этому PR (источник — [`CASE.md`](CASE.md))

- `SEC-1` — перед отправкой во внешний LLM из diff удаляются токены, пароли, приватные ключи.
- `API-1` — diff длиннее 20 000 символов отклоняется с HTTP 413.
- `REL-1` — timeout внешнего LLM-вызова 10 секунд; ошибка превращается в контролируемый ответ.
- `OUT-1` — ответ содержит `summary`, массив `risks` (максимум 3; поля `file`, `line`, `evidence`, `risk`) и массив `checks`.
- `SCOPE-1` — сервис только советует; не пишет код и не выполняет действия в GitHub (approve/merge/комментарии).
- `QA-1` — риск включается, только если подтверждён строкой diff или правилом репозитория.
- `OBS-1` — в лог пишутся только `request_id`, длительность и статус; diff и ответ модели не логируются. В diff нет ни одной строки логирования, поэтому нарушения `OBS-1` этот PR не показывает; правило важно для будущей реализации (см. [`tests_unit.md`](tests_unit.md)).

**Не переносим в Context Pack** (правила из `CASE.md` не относятся к этому PR): `snake_case` для таблиц БД; i18n frontend-строк.

### Формат входа и результата

- Вход сервиса: `POST /api/reviews`, `{"diff": "<unified diff>"}`.
- Выход помощника по `OUT-1`: `{"summary": str, "risks": [{"file", "line", "evidence", "risk"}] (≤ 3), "checks": [str]}`.
- Текущий выход PR: `{"comment": str}` — не соответствует `OUT-1`.

### Ограничения и запрещённые действия

- Единственный источник фактов о коде — приложенный `TRAINING_PR.diff`; другие файлы репозитория, web и shell не используются.
- Отсутствие того, чего нет в правилах (аутентификация, rate limit, async, версия Python), не считается риском: его не подтверждает ни строка diff, ни правило (`QA-1`).
- Помощник не пишет код, не предлагает «реализовать за вас» и не принимает решение о merge (`SCOPE-1`).

### Хороший пример комментария

```text
app/review_service.py:14 — diff подставляется в prompt и уходит во внешний LLM без
удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token
и убедиться, что в prompt осталось [REDACTED].
```

(В `CASE.md` пример дан со строкой `:16`; по содержимому hunk соответствующий код находится на строке 14.)

### Плохой пример комментария

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

Почему плохой: нет файла и строки, нет доказательства из diff, нет правила, нет воспроизводимой проверки.

### Что пока неизвестно

- Формат «контролируемого ответа» при timeout/ошибке LLM (`REL-1`): статус-код и тело. Принято рабочее допущение в [`adr.md`](adr.md): 504/502 и `{"error": {"code", "request_id"}}`.
- Набор паттернов секретов для `SEC-1` и вид заменителя (в `CASE.md` — только `[REDACTED]`).
- Есть ли логирование вне двух показанных файлов (`OBS-1`).
- Требования к аутентификации и квотам — в источниках не заданы.

## Как использовали AI

- Для чего: (1) baseline-ревью `TRAINING_PR.diff`, чтобы увидеть, чего не хватает во входе; (2) отбор релевантных правил и фактов в Context Pack; (3) второй запуск с master prompt для проверки Context Pack.
- Тип промпта: zero-shot (P1-01); Context Pack собран как часть master prompt (RCTF + Chain of Verification + few-shot) для P1-02.
- Строка в [`prompts.md`](prompts.md): [P1-01](prompts.md#L7), [P1-02](prompts.md#L8), сборка артефактов — [P1-05](prompts.md#L11).
- Что проверили и исправили сами: правила `SEC-1`…`OBS-1` сверены с `CASE.md`, правила про `snake_case` и i18n в Context Pack не включены; номера строк пересчитаны по содержимому hunk (заголовок `@@ +1,23` в учебном diff неточен, пример в `CASE.md` указывает `:16` вместо 14); первый прогон P1-02 в корне репозитория забракован, потому что агент прочитал `context.md` (см. [«Запуск 2»](prompts.md#запуск-2-p1-02)).
