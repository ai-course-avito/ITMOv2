## Context Pack для первого рабочего сценария

### Факты и правила

- Endpoint: `POST /api/reviews` принимает JSON с ключом `diff` и передаёт его в LLM.
- ReviewService формирует промпт: "Review this pull request and find problems:" + diff.
- Правила результата: Flow «candidate -> evidence -> check»; Risk: `file: line + evidence + rule`; не придумывать правила; без evidence — пропуск.

### Формат входа и результата

- Вход: строка `diff` (текст unified diff).
- Результат: `summary`; `risks` со схемой; `checks` — список шагов.

### Ограничения и запрещённые действия

- Нельзя approve/merge/edit; нельзя использовать внешние источники; только строки из diff как evidence.

### Хороший пример

summary: кратко описан контекст изменений; risks: 5 пунктов, у каждого `file: line`, цитата строки и проверка; checks: шаги для воспроизведения.

### Плохой пример

Длинные рассуждения без ссылок на строки, выдуманные правила, рекомендации по мерджу, отсутствие проверок.

### Что пока неизвестно

- Какие требования по аутентификации и лимитам в проде; допустимые размеры diff; SLA LLM.

## Как использовали AI

- Для чего: быстро выявить риски изменений и составить проверяемые шаги.
- Тип промпта: master prompt (AI‑reviewer, структурированный вывод).
- Строка в [`prompts.md`](prompts.md): P1-02 (использованы выводы master prompt для AS IS и Context Pack).
- Что проверили и исправили сами: проверили file:line и цитаты против diff, удалили неподтверждённые утверждения, добавили шаги проверки.
