## Context Pack для первого рабочего сценария

### Факты и правила

- Обработчик `POST /api/reviews` извлекает `diff` как `payload["diff"]` из произвольного `dict` без проверки наличия ключа.
- Метод `ReviewService.review` формирует строку prompt и передаёт её в `LLM.generate`.
- В доступных файлах отсутствует валидация входа и обработка исключений в этих точках.

### Формат входа и результата

- Вход: предполагается JSON-объект с ключом `diff` (вывод из использования `payload["diff"]`). Точный формат и тип валидацией не закреплены.
- Результат: возвращается словарь с ключом `comment` из `ReviewService.review`. Формальная схема не задана.

### Ограничения и запрещённые действия

- Работать только с доступными файлами; не использовать внешние источники; не додумывать отсутствующий код/требования; не выдавать предположения за факты; не изменять TRAINING_PR.diff; не придумывать название модели.

### Хороший пример


Запрос с телом, содержащим ключ `diff` (строка диффа). Ответ содержит ключ `comment` (строка). Детали формата за пределами предоставленных файлов не подтверждены.

### Плохой пример


Запрос без ключа `diff` — обращение `payload["diff"]` вызовет ошибку времени выполнения (KeyError) и приведёт к 500 согласно текущей реализации обработчика.

### Что пока неизвестно

- Кто пользователи сервиса; требования к SLA; ограничения длины `diff`; формат строгих схем запроса/ответа; поведение `LLM` и обработка его исключений; детали `app.dependencies`.
