## Context Pack для первого рабочего сценария

### Факты и правила

- Задача помощника: по одному PR на вход принимает diff и возвращает: 1) краткое описание изменения; 2) до трёх рисков с файлом, строкой и доказательством; 3) список проверок (CASE.md).
- OUT-1: результат содержит summary, массив risks (≤3, поля file, line, evidence, risk) и массив checks.
- QA-1: риск включается только если подтверждён строкой diff или правилом репозитория.
- SCOPE-1: помощник только советует; не approve/merge и не меняет код.
- REL-1: внешний LLM‑вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- SEC-1: из diff перед отправкой во внешний LLM удаляются секреты.
- API-1: diff длиннее 20 000 символов отклоняется (HTTP 413).
- OBS-1: логируются request_id, длительность и статус; содержимое diff/ответа не логируется.

### Формат входа и результата

- Вход: текстовый diff PR (TRAINING_PR.diff) как единый артефакт.
- Результат: структурированный ответ с summary, ≤3 risks и checks; каждая проблема с file:line и evidence из diff.

### Ограничения и запрещённые действия

- Запрещено: approve/merge; модифицировать код; выводить больше трёх рисков; включать непроверенные утверждения без evidence; логировать содержимое diff.

### Хороший пример

app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED].

### Плохой пример

«Код можно улучшить. Добавьте тесты и обработку ошибок.» — без файла/строки и evidence.

### Что пока неизвестно

- Целевая версия Python для прод; требуется ли аутентификация, лимиты на клиента; формат ответа клиента (схема) — зафиксировано в открытых вопросах P1‑01.

## Как использовали AI

- Для чего:
- Тип промпта: zero‑shot (P1‑01) и master prompt (P1‑02)
- Строка в [`prompts.md`](prompts.md): разделы «P1‑01 Result», «Master Prompt v1», «P1‑02 Result»
