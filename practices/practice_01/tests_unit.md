# Unit-проверки

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| `ReviewService.review` возвращает словарь с комментарием | Метод `review` при замоканном LLM | `diff = "+++ b/x.py\n+print(1)"`, mock `generate` → `"ok"` | `{"comment": "ok"}`; mock вызван один раз; в prompt есть переданный diff | Unit-тест с mock LLM |
| Промпт включает исходный diff | Содержимое строки prompt | Уникальная метка в `diff` | Метка присутствует в аргументе `generate` | Assert на аргумент mock |
| Пустой diff не маскируется как «успешный ревью без входа» | Поведение `review("")` | `diff = ""` | Зафиксировать фактическое поведение (вызов LLM или отказ). **Открытый вопрос:** желаемый контракт продукта | Unit + запись фактического результата в отчёт |
| Риск в ответе помощника обязан иметь доказательство | Парсер/чеклист формата ответа агента (не прод-код) | Ответ с риском без цитаты | Риск отклоняется чеклистом | Скрипт проверки формата или ручной чеклист на P1-02 |

## Как использовали AI

- Для чего: перечень unit-проверок по `TRAINING_PR.diff` и формату помощника.
- Тип промпта: master prompt / test design.
- Строка в [`prompts.md`](prompts.md): P1-01 и P1-02.
- Что проверил студент и какие исправления поручил агенту: контракт пустого diff не выдуман — помечен открытым вопросом.
