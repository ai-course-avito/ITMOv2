# Unit-проверки

Тестируются чистые функции сервиса с заглушкой LLM; сеть и FastAPI не нужны. Все «секреты» — заведомо фиктивные строки. Фикстура ревью — [`TRAINING_PR.diff`](TRAINING_PR.diff).

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| `SEC-1` | `redact` заменяет токен | `+token = "ghp_TESTTOKEN0123456789"` | В результате `[REDACTED]`, исходного значения нет | `app/review_service.py:14` — сейчас diff уходит как есть |
| `SEC-1` | `redact` заменяет пароль | `password: hunter2-test`, `DB_PASSWORD=test123` | Значения заменены на `[REDACTED]`, имена ключей сохранены | Правило `SEC-1` в [`CASE.md`](CASE.md) |
| `SEC-1` | `redact` заменяет приватный ключ | Блок `-----BEGIN PRIVATE KEY-----` … `-----END PRIVATE KEY-----` с фиктивным телом | Весь блок заменён, маркеры `BEGIN`/`END` не остаются вместе с телом | Правило `SEC-1` |
| `SEC-1` | `redact` не портит обычный diff | `TRAINING_PR.diff` | Результат равен входу (секретов нет) | `TRAINING_PR.diff`, строки 1–42 |
| `API-1` | Проверка длины на границе | `"a" * 20000` и `"a" * 20001` | 20 000 — принимается; 20 001 — ошибка «слишком длинный» | Правило `API-1`; сейчас лимита нет (`app/api.py:10`) |
| `REL-1` | Обёртка вызова LLM при задержке | Заглушка `generate` спит дольше timeout (в тесте timeout уменьшен до 0,1 с) | Выбрасывается доменная ошибка timeout, а не зависание | `app/review_service.py:15` |
| `REL-1` | Ошибка провайдера | Заглушка `generate` бросает исключение | Доменная ошибка «llm_error», исходный текст исключения не попадает в ответ | `app/review_service.py:15` |
| `OUT-1` | Разбор ответа модели | JSON с `summary`, 2 рисками, `checks` | Объект с теми же полями | Правило `OUT-1`; сейчас `return {"comment": answer}` (`app/review_service.py:16`) |
| `OUT-1` | Более трёх рисков | JSON с 5 рисками | В результате не больше 3 (по порядку тяжести) или ошибка формата — решение зафиксировано в ADR | Правило `OUT-1` |
| `OUT-1` | Невалидный ответ модели | Не JSON; JSON без `checks`; риск без `line` | Доменная ошибка «llm_bad_output» | Правило `OUT-1` |
| `QA-1` | Фильтр рисков | Риск с `evidence`, которого нет в diff, и без ID правила | Риск отброшен | Правило `QA-1` |
| `QA-1` | Фильтр оставляет подтверждённое | Риск с `evidence = 'answer = self.llm.generate(prompt)'` | Риск сохранён | `TRAINING_PR.diff`, строка 21 |
| `OBS-1` | Формат записи лога | Обработка запроса с diff, содержащим маркер `SECRET_MARKER` | Запись содержит `request_id`, длительность, статус и не содержит маркера, diff и ответа модели | Правило `OBS-1` |
| `SCOPE-1` | Нет действий вне советов | Публичный интерфейс `ReviewService` | Нет методов approve/merge и клиента GitHub | Правило `SCOPE-1` |
| Валидация схемы | Модель запроса | `{}`, `{"diff": 123}`, `{"diff": "x"}` | Первые два — ошибка валидации, третий — принят | `app/api.py:9–10` (`payload: dict`) |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): [P1-05](prompts.md#L11) (черновик таблицы); идеи проверок в стиле «вход → ожидаемый результат» — из [P1-02](prompts.md#L8).
- Что проверили и исправили сами: убраны проверки на аутентификацию и rate limit (не подтверждены правилами); сверены ID правил с `CASE.md` и строки с `nl -ba TRAINING_PR.diff`; поведение при более чем трёх рисках (обрезать или отвергнуть) в правилах не определено — вынесено в решение автора.
