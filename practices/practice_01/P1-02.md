# P1-02 Review with Master Prompt

Source: practices/practice_01/TRAINING_PR.diff

Findings

Critical

- app/api.py (lines 35-38): `create_review(payload: dict)` accesses `payload["diff"]` directly. Missing field raises `KeyError` -> 500 instead of 422. Use Pydantic model for input and response.

- app/review_service.py (lines 19-22): No size guard or validation on `diff`; large inputs can cause excessive latency/cost and potential DoS of LLM backend.

High

- app/api.py (lines 35-38): No error handling for LLM failures; exceptions bubble to 500 without a stable error schema.

- app/api.py: Synchronous endpoint calling a potentially blocking LLM. Consider `async` with threadpool or async client to avoid tying up workers.

- app/review_service.py (lines 19-22): Prompt injection risk: raw diff interpolated into prompt. Use a fixed system prompt and delimit user content.

Medium

- app/api.py: Using bare `dict` loses schema in OpenAPI; define `BaseModel` request, set `response_model`.

- app/review_service.py: Returns loose `dict[str, str]` with `comment`; prefer a typed response for contract stability.

- app/review_service.py: Prompt is vague; specify output format to improve consistency and downstream parsing.

Low

- app/review_service.py (lines 9-13): Style-only change to Protocol method body; harmless.

Suggested Fixes

- Define `ReviewRequest(BaseModel)` with required `diff: str` and size constraints; set `response_model` for consistent output.
- Add try/except around LLM invocation; map to controlled HTTP errors with clear messages.
- Introduce diff size limit and truncation/segmentation policy; return 413/422 as appropriate.
- Use a system prompt and explicit delimiters to reduce prompt injection; specify output schema.
- Make the route `async`; run blocking calls via threadpool or use an async LLM client.

Assumptions / Questions

- Target Python version (due to `dict[str, str]` typing)?
- Desired response structure (single comment vs structured findings)?
- Acceptable diff size/time budgets for LLM processing?
