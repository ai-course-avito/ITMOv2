# E2E-проверки

Сквозные сценарии повторяют путь ревьюера целиком: от запроса до решения. Внешний LLM заменён заглушкой с заранее заданным ответом, чтобы результат был воспроизводимым.

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный | Сервис запущен, правила репозитория загружены, подготовлен diff на 4000 символов с нарушением `SEC-1` | Ревьюер запрашивает подготовку ревью для этого PR | Ответ содержит `summary`, не более трёх `risks` и `checks`. Хотя бы один риск ссылается на `SEC-1` и содержит `file`, `line` и `evidence` | Сценарий «Позитивный» в [`product_management.md`](product_management.md) |
| Негативный | Сервис запущен, подготовлен diff на 25000 символов | Ревьюер запрашивает подготовку ревью | HTTP 413, обращения к внешнему LLM не произошло | `API-1`, сценарий «diff превышает лимит» в [`product_management.md`](product_management.md) |
| Негативный, отказ внешней зависимости | Сервис запущен, заглушка LLM отвечает через 11 секунд | Ревьюер запрашивает подготовку ревью | Контролируемый ответ об ошибке вместо HTTP 500. В журнале `request_id`, длительность и статус без содержимого diff | `REL-1` и `OBS-1` в [`CASE.md`](CASE.md) |
| Граничный | Сервис запущен, подготовлен diff без нарушений правил | Ревьюер запрашивает подготовку ревью | Массив `risks` пуст, ни одного риска без evidence, `summary` и `checks` заполнены | `QA-1` и `OUT-1`, сценарий «Граничный» в [`product_management.md`](product_management.md) |

Во всех четырёх сценариях решение о комментариях и мерже принимает ревьюер. Сервис не выполняет действий в GitHub, это проверяется отсутствием исходящих запросов к его API.
