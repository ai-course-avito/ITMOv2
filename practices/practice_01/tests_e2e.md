# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный — валидный diff | Сервис запущен, LLM доступен | POST /api/reviews с `{"diff": "diff --git a/app/review_service.py ..."}` (валидный diff < 20k символов) | HTTP 200, JSON с полями `summary` (строка), `risks` (массив до 3 элементов с `file`, `line`, `evidence`, `risk`), `checks` (массив строк) | `app/review_service.py:19-22` — текущий возврат `{"comment": answer}` не соответствует формату OUT-1 |
| Негативный — отсутствует ключ diff | Сервис запущен | POST /api/reviews с `{"code": "print('hello')"}` | HTTP 422 с описанием: поле `diff` обязательно | `app/api.py:37` — `payload["diff"]` без проверки наличия ключа |
| Негативный — diff превышает лимит | Сервис запущен | POST /api/reviews с diff длиннее 20 000 символов | HTTP 413: diff превышает допустимый размер | CASE.md: API-1 |
| Граничный — diff с секретами | Сервис запущен, LLM доступен | POST /api/reviews с diff, содержащим `token=ghp_abc123xyz` | Ответ получен, в промпте для LLM токен заменён на `[REDACTED]` (SEC-1). Ответ JSON с форматом OUT-1 | `app/review_service.py:20` — diff отправляется без очистки секретов |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): P1-02
- Что проверили и исправили сами: проверили, что сценарии покрывают позитивный, негативный (2 варианта) и граничный случаи, что каждый сценарий ссылается на конкретный код или правило, что предусловия и результаты измеримы
