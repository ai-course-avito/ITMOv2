# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный: получить рекомендации | Развёрнут сервис; stub LLM возвращает доказанные риски; diff допустим и содержит синтетический токен | Отправить `POST /api/reviews`, затем проверить перехваченный запрос к stub LLM | HTTP 2xx; ответ содержит `summary`, `checks`, 0–3 полных `risks`; токен заменён на `[REDACTED]`; в логах только разрешённые метаданные | `test_e2e_review_success`; сохранённые HTTP response, prompt stub и sanitized log |
| Негативный: LLM недоступен | Stub LLM отвечает ошибкой или не отвечает >10 секунд | Отправить допустимый diff | Клиент получает контролируемый ответ примерно после границы timeout, а не необработанный 500; содержимое не попадает в лог | `test_e2e_llm_failure`; response и замер длительности |
| Граничный: ровно 20 000 символов | Stub LLM доступен | Отправить diff длиной 20 000 | Запрос принят и обработан по OUT-1 | `test_e2e_accepts_20000_chars`; HTTP response и счётчик вызовов stub |
| Граничный: 20 001 символ | Stub LLM ведёт счёт вызовов | Отправить diff длиной 20 001 | HTTP 413; счётчик вызовов LLM не изменился | `test_e2e_rejects_20001_chars`; HTTP response и счётчик stub |
| Негативный: payload без diff | Сервис доступен | Отправить `{}` | Контролируемая 4xx-ошибка валидации, без вызова LLM | `test_e2e_rejects_missing_diff`; HTTP response и счётчик stub |

Планируемый запуск после реализации: `pytest -q tests/e2e` в тестовом окружении со stub LLM.
