# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный: черновик ревью по учебному diff | Доступен `TRAINING_PR.diff`; задан Master Prompt v1 с Context Pack | Ревьюер передаёт diff помощнику (чат/агент) и получает ответ | Есть описание изменения; ≤3 риска с файлом, строкой и цитатой; список проверок с ожидаемым результатом; нет approve/merge/правок кода | Ответ P1-02 + чеклист DoD |
| Негативный: пустое тело API продукта | Поднят сервис из учебного diff; LLM можно замокать | `POST /api/reviews` с `{}` | Зафиксирован сбой/ошибка (по коду: `payload["diff"]` → `KeyError`). Человеку виден факт проблемы; желаемый UX 4xx — **Открытый вопрос** | HTTP-лог / TestClient + сверка с риском в отчёте помощника |
| Граничный: в diff нет SLA и тестов | Тот же master prompt; вход только diff | Запрос «найди проблемы и предложи проверки» | Помощник не выдумывает прод-требования; пробелы — «Открытый вопрос»; проверки воспроизводимы от diff | Разметка ответа; сравнение с P1-01 |

## Как использовали AI

- Для чего: сквозные сценарии ревьюера и API.
- Тип промпта: master prompt / test design.
- Строка в [`prompts.md`](prompts.md): P1-01 и P1-02.
- Что проверил студент и какие исправления поручил агенту: E2E опираются на наблюдаемое в diff и прогоны P1-01/P1-02.
