# Анализ процесса: AS IS и TO BE

## AS IS

Участники: автор/ревьюер PR (пользователь), API (FastAPI), ReviewService, внешний LLM, логирование.

Процесс:

1. Пользователь отправляет текстовый diff на POST /api/reviews.
2. Сервис формирует prompt и отправляет diff во внешний LLM без редактирования секретов.
3. Ожидает ответ LLM без таймаута и возвращает свободный текст в поле comment/аналог.
4. Логи не стандартизированы; возможна запись чувствительного содержимого.

Проблемы и задержки:

- SEC-1: риск утечки секретов (нет санитайзера).
- API-1: отсутствует лимит 20 000 символов и код 413.
- REL-1: нет таймаута 10 секунд; зависания и непредсказуемые задержки.
- OUT-1: несоответствие формату JSON; невозможность автоматической обработки.
- OBS-1: нет request_id, длительности и статуса; возможны логи с содержимым.

## TO BE

Изменённый процесс для одного рабочего сценария:

```mermaid
flowchart LR
    A[POST /api/reviews] --> B{length <= 20000?}
    B -->|no| C[HTTP 413]
    B -->|yes| D[Sanitize diff (SEC-1)]
    D --> E[LLM call (timeout 10s)]
    E -->|timeout/error| F[Controlled response]
    E -->|ok| G[Normalize & validate (OUT-1, QA-1)]
    F --> G
    G --> H[(Log: request_id, duration, status)]
    H -.-> D
    G --> I[HTTP 200 JSON]
```

## Разница

| Что меняется                | AS IS                                                 | TO BE                                                       | Как проверим изменение                                                           |
| --------------------------- | ----------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Санитайзер секретов (SEC-1) | Отсутствует                                           | Есть, заменяет чувствительные данные на [REDACTED]          | Unit/Integration: проверка паттернов, отсутствие утечек, инспекция промпта стаба |
| Лимит длины (API-1)         | Нет                                                   | >20000 символов → 413; 20000 — OK                           | Integration/E2E: 20001 → 413; 20000 → 200                                        |
| Таймаут LLM (REL-1)         | Нет                                                   | 10с таймаут, контролируемая деградация                      | Integration/Load: 11с стаб → ответ ≤10с с деградацией                            |
| Формат ответа (OUT-1)       | Свободный текст                                       | Структурный JSON (summary, risks<=3, checks)                | Unit/Integration/E2E: валидатор схемы                                            |
| Наблюдаемость (OBS-1)       | Нет request_id/duration/status; логируется содержимое | Логи только с request_id, duration, status; без содержимого | Integration/E2E: анализ логов                                                    |
