# Анализ процесса: AS IS и TO BE

## AS IS

Поведение согласно TRAINING_PR.diff:

- Клиент отправляет произвольный словарь в POST `/api/reviews`.
- Эндпоинт объявлен как `def create_review(payload: dict) -> dict[str, str]:` и напрямую обращается к `payload["diff"]` без валидации.
- Весь `diff` без ограничений вставляется в prompt: `f"Review this pull request and find problems:\n{diff}"`.
- Вызов LLM выполняется напрямую `self.llm.generate(prompt)` без видимой обработки исключений и без таймаута.
- Результат API — только поле `comment` из ответа LLM.

Точки отказа и риски:

- KeyError и 500 при отсутствии ключа `diff` или неправильном типе.
- Безлимитный diff → риск переполнения токенов/большой латентности.
- Необработанные исключения LLM → 500.
- Нет структуры результата для дальнейшей автоматической проверки.


## TO BE

Целевое поведение согласно правилам CASE.md:

- Валидация запроса: `diff` обязателен и является строкой.
- Проверка лимита: длина `diff` ≤ 20 000 символов; иначе 413 Content Too Large.
- Редакция секретов: токены/пароли/ключи заменяются на `[REDACTED]` перед вызовом LLM (SEC-1).
- Формирование ограниченного prompt с учётом лимитов модели.
- Таймаут вызова внешнего LLM — 10 секунд (REL-1).
- Контролируемая обработка ошибок LLM и timeout: HTTP 502 с `error.code=LLM_UPSTREAM_ERROR`, без утечки деталей провайдера.
- Структурированный результат: `summary`, `risks` (≤3), `checks`; каждый риск содержит `file`, `line`, `evidence`, `risk` (OUT-1).
- Безопасное логирование: только метаданные (`request_id`, длительность, статус) без diff и ответа LLM (OBS-1).
- Решение всегда принимает человек (SCOPE-1).

```mermaid
flowchart LR
    U[Клиент/CI] -->|POST /api/reviews| API[FastAPI endpoint]
    API --> VAL[Валидатор запроса]
    VAL -->|422 при невалидном теле| U
    VAL --> SIZE[Проверка длины diff]
    SIZE -->|413 при > 20000 симв.| U
    SIZE --> RED[Redaction секретов]
    RED --> PR[Prompt ограниченный]
    PR --> LLM[Внешний LLM (timeout 10s)]
    LLM -->|успех| TR[Преобразование ответа]
    LLM -->|исключение/timeout| ERR[Контролируемая ошибка]
    TR --> LOG[Безопасное логирование]
    ERR --> LOG
    TR --> HUM[Человек принимает решение]
    ERR --> HUM
    HUM --> RES[summary + ≤3 risks + checks]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Валидация входа | Нет, прямой доступ к `payload["diff"]` | Схема запроса, 422 при невалидном теле | Интеграционный тест: `{}` → 422 |
| Лимит diff | Нет | 413 при длине > 20 000 символов | Юнит/интеграционный тест на 19 999/20 000/20 001 |
| Redaction секретов | Нет | Секреты заменяются на `[REDACTED]` | Юнит‑тест на паттерны token/password/private key |
| Таймаут LLM | Нет | Таймаут 10 секунд | Интеграция с мок LLM, искусственная задержка |
| Обработка ошибок LLM | Нет | Контролируемый ответ | Интеграционный тест с исключением в мок LLM |
| Структура результата | Только `comment` | `summary/risks/checks` (≤3) | Юнит‑тест преобразования ответа |
| Логи | Возможна запись diff/ответа | Только метаданные | Инспекция логов/настройки |
