# Анализ процесса

## AS IS

- Вход: POST `/api/reviews` с JSON-телом, содержащим ключ `diff` (TRAINING_PR.diff: app/api.py:35-38).
- Обработка: контроллер вызывает `review_service.review(payload["diff"])` без валидации входа (TRAINING_PR.diff: app/api.py:36-37).
- Логика сервиса: `ReviewService.review` формирует строку prompt с включённым diff и вызывает `llm.generate(prompt)`; результат оборачивается в `{"comment": answer}` (TRAINING_PR.diff: app/review_service.py:19-22).
- Протокол LLM: `generate(self, prompt: str) -> str` (TRAINING_PR.diff: app/review_service.py:9-13).
- Выход: JSON `{"comment": str}`.
- Не зафиксированы: схема входа/выхода в API, валидация, ограничения размера diff, маскирование секретов, таймаут и контролируемая обработка ошибок.

## TO BE

- Валидация входа на уровне API: тело соответствует схеме с обязательным `diff: str`; при ошибке — 422 Unprocessable Entity.
- Ограничение размера diff согласно критериям репозитория; длинные запросы отклоняются кодом 413.
- Маскирование секретов/редакция перед отправкой в LLM; разделение системных инструкций и пользовательского ввода в prompt.
- Таймаут внешнего LLM-вызова и преобразование ошибок в контролируемый ответ.
- Контроллер формирует ответ API; сервис возвращает доменный результат (строку), не JSON.
- Структура ответа API соответствует принятому контракту (например, `summary`, `risks`, `checks`) — приоритизируется по правилам репозитория.

## Разница (AS IS vs TO BE)

| Область | AS IS | TO BE |
|---|---|---|
| Контракт входа | Свободный `dict` | Явная схема модели запроса |
| Валидация | Отсутствует | 422 при невалидном входе |
| Ограничение размера | Отсутствует | 413 при превышении порога |
| Безопасность prompt | Вставка diff как есть | Редакция секретов и ограничение размера |
| Таймаут/ошибки LLM | Не задано | Таймаут и контролируемый ответ |
| Структура ответа | `{"comment": str}` | Контракт ответа на уровне API |
| Разделение слоёв | Сервис возвращает dict | Сервис возвращает строку; API формирует JSON |
