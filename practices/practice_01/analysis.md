# Анализ процесса: AS IS и TO BE

## AS IS

Синхронный HTTP-вызов без валидации входа и без строгого контракта.

- Событие: внутренний клиент отправляет POST `/api/reviews` с JSON-телом.
- Обработка: FastAPI-эндпоинт принимает `payload: dict` и извлекает `payload["diff"]` без проверки наличия и размера.
- Дальше: `ReviewService.review` формирует строковый промпт и синхронно вызывает `llm.generate(prompt)`.
- Результат: возвращается JSON `{ "comment": "<ответ LLM>" }`.
- Риски и потери:
  - При отсутствии ключа `diff` возникает `KeyError` и, как следствие, неконтролируемый 5xx.
  - Нет правил по SEC-1 (редакция секретов), API-1 (ограничение размера diff), REL-1 (таймаут LLM) и OUT-1 (строгий формат ответа). Логи не нормированы (OBS-1).

## TO BE

Синхронный вызов API с валидацией входа и строгим контрактом ответа.

- Событие: клиент отправляет POST `/api/reviews` с JSON-объектом, соответствующим контракту `{ diff: str }` и лимиту длины.
- Обработка: вход валидируется Pydantic-моделью; применяется лимит размера (API-1) и редакция секретов (SEC-1). Запрос оборачивается в вызов LLM с таймаутом 10 секунд (REL-1). Логи содержат `request_id`, длительность и статус без содержимого (OBS-1). Соблюдён SCOPE-1 и QA-1.
- Результат: контролируемый ответ по OUT-1: `{ summary, risks: [<=3], checks: [] }` ИЛИ контролируемая ошибка 4xx/5xx без утечки деталей.

```mermaid
flowchart LR
    A[POST /api/reviews] --> V[Валидация (Pydantic)]
    V -->|ОК| S[SEC-1 редакция секретов]
    V -->|Ошибка| E4[4xx: контракт/лимит]
    S --> L[REL-1 LLM c таймаутом]
    L -->|Ответ| F[OUT-1 Формирование ответа]
    L -->|Таймаут/ошибка| E5[Контролируемая 5xx]
    F --> O[Ответ клиенту]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Валидация входа | Нет | Pydantic-модель, 4xx при нарушении | Интеграционный тест: пустое тело -> 422/400 |
| Лимит размера diff (API-1) | Нет | 413 при длине > 20000 символов | Интеграционный тест на 413 |
| Редакция секретов (SEC-1) | Нет | Токены/ключи замещаются [REDACTED] | Юнит-тест сервиса на редактирование строки |
| Таймаут LLM (REL-1) | Нет | 10s таймаут с контролируемым ответом | Интеграционный тест с заглушкой LLM, проверка статуса |
| Формат ответа (OUT-1) | Свободный `{"comment": ...}` | Строгий `{summary, risks[], checks[]}` | Юнит-тест формирования ответа |
| Логирование (OBS-1) | Не регламентировано | Только `request_id`, длительность, статус | Ревью логгера и smoke-тест |
