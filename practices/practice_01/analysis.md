# Анализ процесса: AS IS и TO BE

## AS IS

Событие: автор или CI отправляет diff на API. Процесс: FastAPI принимает POST `/api/reviews`, извлекает `payload["diff"]` и передаёт в `ReviewService`. Сервис формирует prompt и вызывает LLM. Ответ возвращается как `{ "comment": <строка> }`. Участники: пользователь/CI, API, ReviewService, внешний LLM, человек‑ревьюер. Задержки/риски: отсутствие проверки длины diff (может привести к 413 поздно или перегрузке), отсутствие таймаута/обработки ошибок LLM (потенциальные зависания), отсутствие маскирования секретов, неструктурированный ответ, возможный KeyError при отсутствующем `diff`.


## TO BE

В рамках первого инкремента: добавлена валидация входа и контракт результата. API проверяет наличие `diff`, длину ≤ 20 000 символов (возвращает 413 при превышении), перед вызовом LLM маскирует секреты; вызов LLM обёрнут таймаутом 10 секунд с контролируемой ошибкой. `ReviewService` возвращает структуру OUT-1: `summary`, `risks` (≤3), `checks`. Человек‑ревьюер остаётся финальным решателем.

```mermaid
flowchart LR
    A[Отправка diff (пользователь/CI)] --> B[API: валидация diff]
    B -->|diff ≤ 20k| C[ReviewService: подготовка prompt]
    B -->|>20k| E[[HTTP 413]]
    C --> D[Mask secrets]
    D --> F[LLM call (timeout 10s)]
    F -->|ok| G[OUT-1: summary/risks/checks]
    F -->|timeout/error| H[[Контролируемый ответ]]
    G --> I[Человек‑ревьюер]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Формат ответа | `{"comment": ...}` | OUT-1: `summary/risks/checks` | Контрактные тесты |
| Ограничение длины | Нет | 413 при >20k | API-тесты с большим diff |
| Таймаут LLM | Нет | 10 сек + graceful error | Интеграционные тесты отказа |
| Маскирование секретов | Нет | Да (SEC-1) | Интеграционные тесты с токеном |
| Валидация поля `diff` | Возможен KeyError | Проверка и сообщение об ошибке | Unit-тесты API |
