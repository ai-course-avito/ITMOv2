# Анализ процесса: AS IS и TO BE

## AS IS

- Событие: клиент отправляет diff в POST /api/reviews.
- Система: FastAPI получает тело запроса как произвольный dict, извлекает payload["diff"], передает строку в ReviewService.review.
- ReviewService: формирует промпт простым конкатенированием и вызывает llm.generate без таймаута, фильтрации секретов и пост-обработки.
- Результат: ответ от LLM возвращается как {"comment": str}. Ошибки входа приводят к 500 (KeyError). Контракт ответа не зафиксирован; нефункциональные требования не определены.


## TO BE

- Валидация входа: Pydantic-модель с полем diff:str; 422 на невалидном теле. Проверка длины diff и 413 при >20,000 символов (API-1).
- Безопасность: перед вызовом LLM удаляем/маскируем секреты из diff (SEC-1).
- Надежность: вызов LLM с таймаутом 10 с; при таймауте возвращаем контролируемый ответ (REL-1).
- Ответ: структурированный объект с полями summary, risks[<=3], checks (OUT-1). Логи: только request_id, duration, status (OBS-1).

```mermaid
flowchart LR
    Client[Клиент] -->|POST /api/reviews| API[FastAPI]
    API -->|Validate & len<=20000| Gate[Валидация]
    Gate -->|Mask secrets| Sanitize[Секрет-редакция]
    Sanitize -->|<=10s| LLM[LLM Provider]
    LLM --> Post[Пост-обработка]
    Post --> Resp[summary+risks+checks]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Валидация тела | dict без схемы | Pydantic-модель | Интеграционный тест: {} -> 422 |
| Лимит размера | отсутствует | 413 при >20k | Интеграция: 20001 -> 413 |
| Редакция секретов | отсутствует | Маскирование | Юнит с фиктивным секретом в diff |
| Таймаут LLM | отсутствует | 10 с + контролируемый ответ | Юнит/интеграция с «медленным» LLM |
| Формат ответа | {comment} | summary+risks+checks | E2E проверка контракта |
| Логирование | не задано | request_id,duration,status | Ручная проверка логов |
