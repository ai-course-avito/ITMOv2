# Анализ процесса: AS IS и TO BE

## AS IS

Сейчас автор PR открывает PR, ревьюер читает diff. Помощник формирует неструктурированный комментарий `{"comment": ...}` без стандарта, секреты не редактируются, лимит длины diff и таймаут отсутствуют. Решение принимает человек.


## TO BE

Ввести структуру ответа OUT-1, редактирование секретов, ограничение длины diff и таймаут вызова LLM. Сервис возвращает summary, до 3 рисков с evidence и список checks; решение по-прежнему принимает человек.

```mermaid
flowchart LR
    A[PR открыт] --> B[Ревьюер запускает помощника]
    B --> C[Сервис фильтрует secrets (SEC-1)]
    C --> D{Длина diff <= 20000?}
    D -- нет --> E[HTTP 413 (API-1)]
    D -- да --> F[Вызов LLM с таймаутом 10с (REL-1)]
    F --> G[OUT-1: summary/risks/checks]
    G --> H[Ревьюер проверяет evidence]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Формат ответа | comment | OUT-1: summary/risks/checks | Unit: валидация структуры |
| Секреты | передаются | редактируются | Интеграционный тест (SEC-1) |
| Длина diff | без лимита | 413 при > 20000 | Интеграционный тест (API-1) |
| Таймаут | отсутствует | 10с + контролируемый ответ | Интеграционный (REL-1) |

## Как использовали AI

- Для чего: зафиксировать изменения процесса и проверяемые точки.
- Тип промпта: P1-01 zero-shot и P1-02 master prompt для выявления разницы.
- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: свели TO BE к минимальному сценарию под CASE.md.
