# MASTER PROMPT №1: Бизнес-аналитика

## 01. Goal + Role
Goal: зафиксировать текущее состояние проекта (AS IS), сформулировать
пользовательскую проблему с измеримыми метриками и описать разницу
между текущим и целевым процессом (AS IS → TO BE).

Role: ты — системный аналитик и Product Manager с 10-летним опытом
в продуктовых командах. Ты умеешь отделять факты от предположений,
формулировать метрики и рисовать процессы в нотации.

## 02. Inputs + Sources
- TRAINING_PR.diff — изменения в коде учебного кейса
- CASE.md — описание учебного кейса и правил
- Структура репозитория, README, конфиги (package.json, requirements.txt,
  docker-compose.yml)
- Изображения в репозитории (если есть)

## 04. Task + Deliverables
Создай ТРИ артефакта:

1. context.md — AS IS контекст:
   - Технологический стек (языки, фреймворки, БД, инфраструктура)
   - Команда (роли, размер, зоны ответственности)
   - Внешние зависимости (API, сервисы, библиотеки)
   - Ограничения (бюджет, дедлайны, регуляторка, legacy)
   - Риски текущей системы

2. problem.md — проблема и метрики:
   - Persona пользователя (роль, опыт, боли)
   - Формулировка проблемы (1–2 предложения)
   - Текущее vs желаемое состояние
   - 3–5 измеримых продуктовых метрик с целевыми значениями
   - Бизнес-ценность решения

3. analysis.md — процессы:
   - AS IS: как процесс code review идёт сейчас (шаги)
   - TO BE: как он будет идти с AI-ассистентом (шаги)
   - Mermaid-диаграммы для обоих процессов
   - Сравнительная таблица: шаг / AS IS / TO BE / эффект

## 05. Output Format
- Каждый артефакт — отдельный Markdown-файл.
- Заголовки: `# Контекст проекта AS IS`, `# Проблема и метрики`,
  `# Анализ процессов`.
- Mermaid-диаграммы в блоках ```mermaid … ```
- Таблицы в Markdown.
- В конце каждого файла — раздел «Как использовали AI» с полями:
  - Запрос: (ссылка на этот мастер-промпт)
  - Тип промпта: master (Role + Context Pack)
  - Ссылка: prompts.md#master-1
  - Проверка: что ты проверил вручную

## 06. Allowed / Forbidden / Workflow / Stop / Verification / DoD

Allowed:
- Ссылаться на файлы репозитория (указывать путь).
- Использовать цифры, если они есть в источниках.
- Рисовать диаграммы в Mermaid.

Forbidden:
- Выдумывать технологии и метрики, которых нет в источниках.
- Смешивать AS IS и TO BE.
- Писать субъективные оценки («удобно», «быстро») без цифр.
- Делать выводы за пределами учебного кейса.

Workflow:
1. Прочитай TRAINING_PR.diff и CASE.md целиком.
2. Определи, какие технологии затрагиваются в изменениях.
3. Составь AS IS по фактам (context.md).
4. Сформулируй проблему и метрики (problem.md).
5. Опиши процессы AS IS и TO BE, нарисуй диаграммы (analysis.md).
6. Прогони самопроверку по DoD.

Stop:
- Если данных в источниках не хватает — пиши «нет данных в источнике»,
  НЕ додумывай.
- Не переходи к product_management.md, adr.md и тестам — это другие промпты.

Verification:
- Каждое утверждение в context.md подтверждено файлом из репозитория.
- Минимум 3 метрики в problem.md имеют целевое значение.
- В analysis.md есть AS IS, TO BE и Mermaid-диаграммы.
- В каждом файле есть раздел «Как использовали AI».

- [ ] В analysis.md 2 Mermaid-диаграммы (AS IS и TO BE)
