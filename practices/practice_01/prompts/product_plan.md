# MASTER PROMPT №2: Продукт и планирование

## 01. Goal + Role
Goal: превратить проблему и процессы в функциональные требования
(user stories, use cases) и в реалистичный план поставки по инкрементам.

Role: ты — Product Owner и Project Manager. Ты умеешь писать user
stories с критериями приёмки, приоритизировать бэклог и раскладывать
работу по спринтам, распределяя задачи между людьми и AI.

## 02. Inputs + Sources
- context.md — AS IS контекст проекта
- problem.md — персона, проблема, метрики
- analysis.md — AS IS и TO BE процессы
- CASE.md — правила учебного кейса

## 04. Task + Deliverables
Создай ДВА артефакта:

1. product_management.md:
   - 5–7 user stories в формате
     «Как [роль], я хочу [действие], чтобы [ценность]»
   - Критерии приёмки для каждой story (Given/When/Then или чек-лист)
   - Приоритеты: Must Have / Should Have / Could Have
   - 2–3 use case: основной, альтернативный, исключительный
   - Матрица «story ↔ метрика из problem.md»

2. project_management.md:
   - 3 инкремента (спринта по 1–2 недели)
   - Для каждого: какие stories входят, кто делает (человек/AI),
     результат инкремента, как проверяем
   - Roadmap с датами
   - 3 риска и способы митигации
   - Роли людей и AI в команде

## 05. Output Format
- Два отдельных Markdown-файла.
- User stories — заголовками `### US-01: …` с полями
  Роль / Действие / Ценность / Приоритет / Критерии приёмки.
- Use cases — заголовками `### UC-01: …` с полями
  Актор / Предусловие / Основной сценарий / Альтернатива / Исключение.
- Roadmap — Markdown-таблица.
- В конце каждого файла — раздел «Как использовали AI».

## 06. Allowed / Forbidden / Workflow / Stop / Verification / DoD

Allowed:
- Ссылаться на метрики и персону из problem.md.
- Указывать AI как исполнителя конкретных задач.
- Ограничивать объём (не более 7 stories, не более 3 спринтов).

Forbidden:
- Технические требования («использовать pandas», «настроить Redis»).
- Stories без критериев приёмки.
- Смешивать product_management и project_management в одном файле.
- Планировать больше 3 спринтов.

Workflow:
1. Прочитай context.md, problem.md, analysis.md.
2. Выдели роли из problem.md — они станут акторами user stories.
3. Напиши 5–7 stories, привяжи каждую к метрике.
4. Опиши use cases по процессу TO BE из analysis.md.
5. Оцени объём и разложи по 3 инкрементам.
6. Прогони самопроверку по DoD.

Stop:
- Если story не привязана к метрике — удали её.
- Не переходи к adr.md и тестам — это другие промпты.

Verification:
- Каждая story имеет роль, действие, ценность, приоритет, критерии.
- Минимум 2 use case с альтернативой и исключением.
- Roadmap содержит даты и результаты по инкрементам.
- В каждом файле есть «Как использовали AI».

DoD:
- [ ] product_management.md: ≥5 stories, ≥2 use cases
- [ ] project_management.md: 3 инкремента, roadmap, ≥3 риска
- [ ] Каждая story привязана к метрике
- [ ] Роли людей/AI распределены явно
- [ ] В каждом файле есть «Как использовали AI»
