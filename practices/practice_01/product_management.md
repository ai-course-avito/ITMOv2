## Первый рабочий сценарий

**Когда** пользователь ищет локацию по тайтлу аниме и сохраняет её координаты, **система** выполняет поиск по базе и, при необходимости, обращается к внешнему геокодингу с кэшированием, **а пользователь получает** точные координаты и может добавить локацию в избранное.

Не входит в этот сценарий:

- Бронирование билетов/отелей; офлайн-карты; AR/VR; монетизация UGC; мультимодальные маршруты с реальным трафиком

## Use case

| Поле | Значение |
|---|---|
| Актор | Пользователь (турист/фанат), Клиентское приложение |
| Триггер | Пользователь вводит тайтл и/или название сцены/локации для поиска |
| Предусловия | Локации частично присутствуют в БД; подключены внешние геокодеры; доступен Redis кэш |
| Основной результат | Список совпадений с точными координатами; выбранная локация открывается и сохраняется в избранное |
| Ошибка или отказ | Локация не найдена; внешнее API недоступно; возвращается сообщение об ошибке и предложение повторить позже |

```mermaid

    System-->>User: Список локаций; выбор и сохранение в избранное
```

## User stories и acceptance criteria

```gherkin
Feature: Поиск и сохранение локаций AnimeMap API

  Scenario: Поиск локации по тайтлу (happy path)
    Given пользователь на экране поиска и API доступно
    And в базе есть локации, связанные с тайтлом "Your Name"
    When пользователь вводит "Your Name" и нажимает поиск
    Then система возвращает список локаций с координатами и статусом верификации
    And пользователь открывает локацию и видит точные координаты

  Scenario: Кэшированный ответ по координатам
    Given в Redis есть кэш по запросу "Your Name stairway"
    When пользователь повторно запрашивает координаты
    Then система отвечает из кэша за < 100 мс

  Scenario: Ошибка внешнего геокодера
    Given внешний геокодер недоступен
    When система пытается дополнить координаты
    Then система возвращает 503 и сообщение «Попробуйте позже», без разрушения уже найденных локальных результатов
```

Use cases (минимум 3):

- Поиск локации по тайтлу: пользователь вводит название аниме; система находит связанные локации, нормализует названия JP/EN, при необходимости обогащает координаты через геокодер и возвращает список результатов.
- Получение координат: клиент запрашивает координаты конкретной локации по ID/slug; система отдаёт точные координаты, статус верификации и кэширует ответ.
- Добавление точки в избранное: аутентифицированный пользователь сохраняет локацию в избранное; система фиксирует связь user-location, предотвращает дубли и возвращает подтверждение.

User stories:

- Как турист-отаку, я хочу искать локации по названию тайтла, чтобы быстро находить места из любимого аниме.
- Как фанат, я хочу получить точные координаты локации, чтобы безошибочно добраться на место.
- Как авторизованный пользователь, я хочу добавлять локации в избранное, чтобы собирать персональный маршрут.
- Как модератор, я хочу отмечать локации как верифицированные, чтобы повысить доверие к данным.
- Как разработчик клиента, я хочу получать стабильные и кэшируемые ответы API, чтобы обеспечить быструю работу приложения на мобильных устройствах.
