# Продуктовая часть

## Первый пользователь

- Клиент FastAPI, отправляющий diff учебного PR для анализа моделью LLM.

## User story

- Как клиент сервиса, я хочу отправить diff PR и получить комментарий модели, чтобы быстрее заметить проблемы в изменениях.

## Позитивный сценарий

1. Клиент отправляет POST `/api/reviews` с JSON телом `{ "diff": "..." }`.
2. Контроллер валидирует вход и вызывает сервис.
3. Сервис формирует промпт и получает ответ от LLM.
4. Клиент получает ответ API с комментарием.

## Негативный сценарий

1. Клиент отправляет POST `/api/reviews` без ключа `diff` или с типом, отличным от строки.
2. Контроллер возвращает 422 с описанием ошибки.

## Метрики продукта

| Метрика | Базовое значение | Цель |
|---|---:|---:|
| Доля 5xx на POST /api/reviews | Недостаточно данных | < 1% |
| Доля 422 при некорректном теле | 0% | > 95% корректно 422 |

## Как использовали AI

- Для структурирования артефакта по фактам TRAINING_PR.diff и текущим context.md / problem.md; запись P1-03 в prompts.md.
