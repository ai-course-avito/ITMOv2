# P1-02: Повторное ревью с master prompt v1

**Инструмент/модель:** OpenCode (claude-sonnet-4)

**Запрос (master prompt):** P1-02 в `prompts.md` с Context Pack.

## Результат

15 проблем, сгруппированных по правилам репозитория из CASE.md.

### Critical (5)

1. **`app/api.py:37`** — `payload["diff"]` без валидации → KeyError → 500. Требуется Pydantic-модель ReviewRequest.
2. **`app/review_service.py:20`** — SEC-1: сырой diff передаётся в LLM без удаления токенов/паролей/ключей.
3. **`app/review_service.py:20`** — API-1: нет проверки `len(diff) > 20 000` → отсутствует HTTP 413.
4. **`app/review_service.py:21`** — REL-1: no timeout на `llm.generate()` — вызов может зависнуть дольше 10 секунд.
5. **`app/review_service.py:22`** — OUT-1: ответ `{"comment": answer}` не содержит `summary`, `risks` (max 3), `checks`.

### High (4)

6. **`app/api.py:36`** — нет Pydantic-модели для валидации входа (payload: dict).
7. **`app/api.py:35`** — нет `response_model` и явного статус-кода (200 вместо 201 для создания ресурса).
8. **`app/review_service.py:20`** — prompt injection: сырой diff в f-string без делимитеров (`===DIFF START=== / ===DIFF END===`).
9. **`app/review_service.py:21`** — нет try/except вокруг `llm.generate()` — любая ошибка LLM → 500.

### Medium (4)

10. **`app/api.py` + `app/review_service.py`** — OBS-1: нет логирования request_id, duration, status.
11. **`app/api.py:35`** — отсутствует аутентификация/авторизация на публичном эндпоинте.
12. **`app/review_service.py:19`** — тип возврата `dict[str, str]` не соответствует структуру OUT-1.
13. **`app/review_service.py:20`** — промпт не задаёт строгий формат вывода LLM (жёсткий JSON-формат).

### Low (2)

14. **`app/review_service.py:11-12`** — изменение `...` на отдельную строку (стиль, не ошибка; оба варианта валидны в Python).
15. **`tests/**`** — нет покрывающих тестов unit и E2E.

## Сильные стороны ответа

1. **Каждый риск привязан к строке diff или правилу** (QA-1): все 15 проблем ссылаются на конкретные строки diff (app/api.py:37, app/review_service.py:20-22) или правила (SEC-1, API-1, REL-1, OUT-1, OBS-1).
2. **Соблюдены границы помощника** (SCOPE-1): сервис только советует, не пишет код и не выполняет действия в GitHub.
3. **Воспроизводимые проверки**: для каждого риска есть конкретный способ проверки (тест с diff содержащим token, проверка размера > 20 000, timeout LLM).

## Слабые места ответа

1. Некоторые проблемы пересекаются (API-1 и prompt injection обе на app/review_service.py:20).
2. Pydantic-модель и response_model на app/api.py:35-36 — рекомендации по реализации, а не только выявление проблемы.

## Отклонённые предложения

- **Аутентификация** (app/api.py:35): вынесена в backlog — требует инфраструктурных решений (OAuth, JWT), не описанных в kейсе.
- **Модернизация Protocol** (app/review_service.py:11-12): не исправлено — оба варианта синтаксиса валидны, приоритет ниже.
