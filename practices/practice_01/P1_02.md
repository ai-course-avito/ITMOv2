# P1-02: Повторное ревью с master prompt

## Цель
Проанализировать PR TRAINING_PR.diff и указать на проблемы

## Проблемы (по убыванию критичности)

### Critical
**`app/api.py:37`** - Доступ к `payload["diff"]` без валидации. При отсутствии ключа выбросит `KeyError`, что приведёт к 500 вместо 422.

**`app/review_service.py:19-22`** - Отсутствует обработка ошибок LLM. Любая ошибка в `llm.generate()` приведёт к 500 Internal Server Error.

### High
**`app/api.py:35-38`** - Нет схемы запроса/ответа (Pydantic модели). Ухудшит автодокументацию и валидацию входных данных.

**`app/review_service.py:20`** - Промпт не ограничен делимитами. Риск prompt injection и некорректного анализа.

**`app/review_service.py:19, app/api.py:36`** - Нет ограничений на размер входного diff. Большие диффы могут привести к превышению токенов и таймаутам.

### Medium
**`app/api.py:35`** - Отсутствует аутентификация/авторизация. Возможны злоупотребления.

**`app/review_service.py:20-22`** - Неформализованный ответ `{comment: текст}`. Трудно для машинной обработки.

**`app/api.py:36`** - Синхронный endpoint для долгой операции (LLM). Нужно учесть таймауты.

**`app/review_service.py:9-13`** - Совместимость `typing.Protocol`. Требует Python 3.8+ или `typing_extensions`.

### Low
**`app/review_service.py:11-12`** - Тело метода Protocol с `...` на отдельной строке - стиль, но не ошибка.

**`app/**`** - Отсутствует логирование запросов и ошибок.

**`tests/**`** - Нет тестовой покрывающей базы.

## Рекомендации

1. **Валидация ввода**: добавить Pydantic модели `ReviewRequest` и `ReviewResponse`
2. **Error handling**: обернуть `llm.generate()` в try/except
3. **Промпт-инъекция**: обрамить diff в маркеры `=== DIFF START ===` и `=== DIFF END ===`
4. **Лимит размера**: добавить проверку длины diff и таймаут запроса
5. **Логирование**: добавить корреляционный ID и метрики
6. **Тесты**: покрыть Unit-тестами сервис и интеграционными тестами API
