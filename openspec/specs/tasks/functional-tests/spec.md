# tasks/functional-tests Specification

## Purpose
Определить функциональные тесты, проверяющие поведение недельного календаря и валидацию времени: ISO 8601 хранение, отображение в локали/часовом поясе клиента, допуск отсутствия времени и взаимоисключаемость режимов при наличии времени.

## Requirements

### Requirement: Взаимоисключаемость при наличии времени; допуск отсутствия времени
Тесты SHALL проверять, что при наличии времени принимается ровно один режим и недопустимые комбинации отклоняются; отсутствие времени допускается и приводит к отображению в секции «без времени».

#### Scenario: Отклонение обоих режимов сразу
- **WHEN** API-запрос включает дату all-day и start/end одновременно
- **THEN** API отвечает 400 с кодом ошибки "time_mode_conflict"

#### Scenario: Принятие задачи без времени
- **WHEN** API-запрос не содержит ни all-day, ни start/end
- **THEN** API отвечает 201, запись сохраняется без временных полей, UI отображает задачу в секции «без времени»

#### Scenario: Принятие и сохранение all-day
- **WHEN** API-запрос включает all-day "2026-10-28"
- **THEN** API отвечает 201, а запись в хранилище содержит значение даты "2026-10-28"

### Requirement: Принятие ISO 8601 форматов и точности до минут
Тесты SHALL проверять, что all-day использует YYYY-MM-DD, а значения времени используют ISO 8601 дату-время с точностью до минут и смещением; секунды отклоняются.

#### Scenario: Принятие значений с точностью до минут
- **WHEN** API-запрос включает start "2026-10-28T09:30+03:00" и end "2026-10-28T10:45+03:00"
- **THEN** API отвечает 201, и запись в хранилище содержит значения с точностью до минут

#### Scenario: Отклонение секунд
- **WHEN** API-запрос включает "2026-10-28T09:30:05+03:00"
- **THEN** API отвечает 400 с кодом ошибки "invalid_time_precision"

### Requirement: Рендер локального времени и ISO-недели
Тесты SHALL проверять локальный рендеринг времени и ISO-нумерацию недель (понедельник — первый день).

#### Scenario: Локальный рендер отражает часовой пояс
- **WHEN** сохранённое время "2026-10-27T23:30Z" отображается для пользователя в UTC+02:00
- **THEN** UI показывает 2026-10-28 01:30 и относит задачу к корректному дню/ISO-неделе
