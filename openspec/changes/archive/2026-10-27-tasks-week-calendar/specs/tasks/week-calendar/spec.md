# Spec Delta

## Purpose
Еженедельный календарь задач с режимами «на весь день» и «по времени»; хранение времени в ISO 8601, отображение в локали и часовом поясе пользователя, ISO-нумерация недель.

## ADDED Requirements

### Requirement: Формат хранения времени ISO 8601
Система SHALL хранить временные поля задач в формате ISO 8601. Задачи «на весь день» SHALL хранить дату в виде YYYY-MM-DD. Задачи с длительностью SHALL хранить start и end как строки ISO 8601 с точностью до минут и с часовым смещением; секунды НЕ ДОЛЖНЫ присутствовать.

#### Scenario: Сохранение даты для задачи на весь день
- **WHEN** пользователь создаёт задачу «на весь день» на 2026-10-28
- **THEN** сохраняется значение времени "2026-10-28" и поля start/end отсутствуют

#### Scenario: Сохранение start/end для задачи по времени
- **WHEN** пользователь создаёт задачу со start "2026-10-28T09:30+03:00" и end "2026-10-28T10:45+03:00"
- **THEN** оба значения сохраняются в точности как ISO 8601 строки с точностью до минут и указанным смещением

#### Scenario: Отклонение секунд в значениях времени
- **WHEN** пользователь передаёт start "2026-10-28T09:30:05+03:00"
- **THEN** запрос отклоняется с ошибкой валидации "seconds not allowed"

### Requirement: Взаимоисключаемость режимов при наличии времени; допускается отсутствие времени
Если время указано, SHALL быть указан ровно один режим: либо all-day, либо интервал start/end. Отсутствие времени допустимо; такие задачи отображаются отдельно в секции «без времени».

#### Scenario: Одновременная передача all-day и start/end
- **WHEN** пользователь передаёт одновременно all-day и start/end
- **THEN** запрос отклоняется с ошибкой валидации "choose either all-day or start/end"

#### Scenario: Не указано ни all-day, ни start/end (задача без времени)
- **WHEN** пользователь не указывает ни all-day, ни start/end
- **THEN** запрос принимается, задача сохраняется без временных полей и отображается в секции «без времени»

#### Scenario: Только all-day
- **WHEN** пользователь указывает только дату all-day "2026-10-28"
- **THEN** запрос принимается и сохраняется как дата без времени

### Requirement: Отображение локального времени на клиенте
Интерфейс SHALL отображать дату и время в локали и часовом поясе пользователя; хранилище SHALL оставаться независимым от локали. Метки недель SHALL использовать ISO-нумерацию (понедельник — первый день).

#### Scenario: Отображение с учётом часового пояса
- **WHEN** задача со значением хранения "2026-10-27T23:30Z" просматривается пользователем в UTC+02:00
- **THEN** UI показывает 2026-10-28 01:30 в локали пользователя и относит задачу к корректному дню

#### Scenario: ISO-нумерация недель с понедельника
- **WHEN** пользователь открывает неделю, содержащую 2026-10-28 (среда)
- **THEN** UI показывает ISO-неделю с понедельником в качестве первого дня и корректной меткой недели
