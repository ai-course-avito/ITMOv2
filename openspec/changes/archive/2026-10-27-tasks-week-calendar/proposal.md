# Proposal

## Why

Сейчас задачи не имеют временной модели и отображаются только списком. Нужно планирование на неделю с локальным временем пользователя и сохранением текущего поведения списка, чтобы видеть задачи во времени и управлять ими без потери текущего UX.

## What Changes

- Добавить временную модель задач: выбор точки времени (`when`) или интервала (`start`/`end`).
- Добавить недельный календарь с навигацией: «Предыдущая неделя», «Эта неделя», «Следующая неделя»; подписи дней и номер недели (ISO-8601, неделя начинается в понедельник).
- Отображать события без времени отдельно от слотов по времени.
- Расширить форму добавления: задать дату/время (точка или длительность) в текущей форме; поддержать редактирование.
- Сохранить существующие API и поведение списка задач (добавление, удаление, переключение done) без регрессий.
- Ввести отдельную спецификацию на функциональные тесты (coverage ключевых сценариев списка и календаря).

## Capabilities

### New Capabilities
- tasks/week-calendar: Недельное отображение задач с локальным временем, навигацией, поддержкой точек и интервалов, и секцией «без времени».
- tasks/functional-tests: Требования к автотестам для списка задач и недельного календаря (API и UI-сценарии как внешне наблюдаемое поведение).

### Modified Capabilities
- (нет) — существующих спецификаций проекта пока нет; изменения требований к текущему поведению не заявлены.

## Impact

- Бэкенд (Flask): расширение модели данных задач (новые поля времени), валидация и обратная совместимость; потенциальные новые параметры в POST/PATCH без ломающих изменений существующих схем.
- Фронтенд (HTML/JS): новый вид «Календарь недели», переключатель представлений, навигация по неделям, локальные вычисления дат/времени/номера недели.
- Хранение: формат JSON с опциональными полями времени; миграция не требуется, старые записи остаются валидными.
- Тестирование: новые автотесты API и сценариев UI.
