# Design

## Context

`practices/practice_05/frontend/src/App.tsx` хранит успешный ответ поиска в `result` и сейчас выводит `result.itineraries` напрямую. Сервер уже возвращает их по возрастанию цены. Форма выполняет `fetch` только в `handleSubmit`; сравнение цен и признак кеша находятся в том же ответе. См. `proposal.md` и `specs/flight-price-order/spec.md`.

## Goals / Non-Goals

**Goals:** сохранять ответ нетронутым, получать устойчивый порядок по числовой цене и сбрасывать выбранный режим после успешного поиска.

**Non-Goals:** менять серверную сортировку или пересчитывать валюты, цену сравнения и сведения о кеше.

## Decisions

- Хранить только выбранный порядок в состоянии React; отсортированный список выводить из ответа и режима. Отдельное состояние карточек могло бы разойтись с ответом после нового поиска.
- Сортировать копию массива с явным исходным индексом как вторичным ключом. Это делает порядок равных цен независимым от стабильности реализации `Array.sort` и не мутирует ответ.
- Показывать обычный подписанный `select` только для непустого списка. Он доступен с клавиатуры и не вмешивается в обработчик отправки формы.
- Сбрасывать режим после успешного `fetch`, вместе с установкой нового результата. Ошибочный поиск сохраняет текущий механизм отображения ошибки.

## Risks / Trade-offs

- Повторная сортировка при рендере → использовать `useMemo` по `result` и выбранному режиму.
- Цены разных валют нельзя сравнивать напрямую → поисковый ответ относится к одному выбранному рынку; текущий контракт не смешивает валюты. Пересчёт и смешанные ответы остаются вне этой фичи.

## Migration Plan

Миграция данных не нужна. При откате достаточно вернуть прежнее отображение списка и убрать состояние переключателя.
