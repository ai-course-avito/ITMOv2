# Feature Specification: Export Report UI (/export-report)

**Feature Branch**: `[001-export-report]`

**Created**: 2026-10-22

**Status**: Draft

**Input**: User description: "Создай спецификацию для команды /export-report в OpenCode. Это интерфейс (UI) для генерации сводного отчёта по результатам практик. Пользователь вводит команду, система спрашивает: 1. Формат отчёта: Markdown или HTML. 2. Что включать: только метрики, или также артефакты (prompts.md, REPORT.md). В результате система должна показать: - Путь к сохраненному файлу (например, reports/report-2026-10-22.md). - Краткое резюме: сколько файлов собрано, сколько метрик, статус (Success). Ограничения: - Читать только из practices/, docs/, lab/results/. - Не трогать node_modules, .venv, .git. - Если данных нет — вывести \"Нет данных для отчёта\"."

## User Scenarios & Testing (mandatory)

### User Story 1 - Генерация отчёта с выбором формата и состава (Priority: P1)

Пользователь запускает `/export-report` и отвечает на два вопроса: формат отчёта (Markdown или HTML) и состав (только метрики или метрики + артефакты: `prompts.md`, `REPORT.md`). Система собирает данные из разрешённых каталогов, генерирует отчёт, сохраняет файл в `reports/` и показывает путь к нему и краткое резюме (сколько файлов собрано, сколько метрик, статус Success).

**Why this priority**: Это основной сценарий и ключевая ценность функции.

**Independent Test**: Запустить `/export-report`, выбрать Markdown и «метрики + артефакты»; проверить, что создан `reports/report-<DATE>.md` и выведено резюме с корректными числами и статусом Success.

**Acceptance Scenarios**:
1. **Given** доступны данные в `practices/`, `docs/`, `lab/results/`, **When** пользователь выбирает формат Markdown и состав «метрики + артефакты», **Then** создаётся файл `reports/report-<DATE>.md`, выводится путь и резюме.
2. **Given** пользователь выбирает формат HTML и состав «только метрики», **When** команда выполняется, **Then** создаётся `reports/report-<DATE>.html` с корректным резюме.

---

### User Story 2 - Отсутствие данных (Priority: P1)

Если в разрешённых каталогах нет данных, система ничего не сохраняет и выводит чёткое сообщение: "Нет данных для отчёта".

**Why this priority**: Предотвращает пустые или вводящие в заблуждение отчёты, соответствует требованиям.

**Independent Test**: В среде без данных в `practices/`, `docs/`, `lab/results/` выполнить `/export-report` и проверить, что выводится ровно "Нет данных для отчёта".

**Acceptance Scenarios**:
1. **Given** ни один файл или метрика в разрешённых каталогах не найден, **When** запускается команда, **Then** выводится "Нет данных для отчёта" и файл не создаётся.

---

### User Story 3 - Ограничение области чтения и исключения (Priority: P2)

Поиск и сбор данных выполняется только из `practices/`, `docs/`, `lab/results/`. Пути `node_modules/`, `.venv/`, `.git/` полностью игнорируются.

**Why this priority**: Снижает шум, ускоряет обработку и исключает нежелательные данные.

**Independent Test**: Разместить тестовые файлы как в разрешённых, так и в исключённых каталогах; убедиться, что в отчёт попадают только разрешённые.

**Acceptance Scenarios**:
1. **Given** артефакт находится в `node_modules/`, **When** команда выполняется, **Then** этот артефакт не учитывается.
2. **Given** метрики находятся в `lab/results/`, **When** команда выполняется, **Then** они учитываются в подсчёте метрик.

### Edge Cases

- Большое количество файлов: подсчёты выполняются, а вывод остаётся кратким.
- Отчёт за один день уже существует: создаётся новый файл с тем же шаблоном имени, перезапись допускается как разумное поведение для v1.
- Частичная недоступность файлов: пропустить проблемные файлы, продолжить сбор и корректно отразить в подсчётах.

## Requirements (mandatory)

### Functional Requirements

- **FR-001**: Система MUST предоставить команду `/export-report` с интерактивными вопросами: формат (Markdown или HTML) и состав (только метрики либо метрики + артефакты: `prompts.md`, `REPORT.md`).
- **FR-002**: Система MUST читать данные только из каталогов `practices/`, `docs/`, `lab/results/` и MUST игнорировать `node_modules/`, `.venv/`, `.git/`.
- **FR-003**: Система MUST генерировать файл отчёта в каталоге `reports/` в корне проекта с именем `report-YYYY-MM-DD.ext`, где `ext` — `md` или `html` в зависимости от выбранного формата.
- **FR-004**: Система MUST выводить после генерации: путь к сохранённому файлу и краткое резюме (сколько файлов собрано, сколько метрик, статус Success).
- **FR-005**: Система MUST выводить ровно "Нет данных для отчёта" и не создавать файл, если источники данных пусты.
- **FR-006**: Система MUST работать в режиме чтения для источников; запись ограничена созданием отчётного файла в `reports/`.

### Key Entities

- **Report**: итоговый документ, содержащий сводные метрики и, при выборе, артефакты.
- **Metric**: количественное значение, извлечённое из данных практик и результатов.
- **Artifact**: файл контента (например, `prompts.md`, `REPORT.md`), включаемый в отчёт при соответствующем выборе.

## Success Criteria (mandatory)

### Measurable Outcomes

- **SC-001**: После выбора опций пользователю показывается путь к отчёту и резюме; операция завершается менее чем за 15 секунд при стандартном объёме данных.
- **SC-002**: Исключения путей (`node_modules/`, `.venv/`, `.git/`) соблюдены на 100% случаев по проверке тестовыми файлами.
- **SC-003**: В отчёте корректно отражаются подсчёты: число учтённых файлов и число метрик соответствуют фактическим данным в разрешённых каталогах.
- **SC-004**: При отсутствии данных выводится ровно "Нет данных для отчёта" без создания файла.

## Assumptions

- Дата в имени файла отчёта соответствует дате запуска команды (локальное время).
- "Метрики" — это количественные показатели, присутствующие в данных практик и результатов; точный формат источников будет поддержан существующими материалами проекта.
- В v1 отчёт содержит сводные числа и краткое содержание артефактов; детальная визуализация вне области.
